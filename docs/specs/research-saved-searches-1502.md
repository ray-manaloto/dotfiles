## 1. Objective

Ray has asked twice for every GitHub search a research sweep runs (issues, PRs, discussions, releases, code search)
to be **saved so it can be re-run later**. Today those searches live only in gitignored `.agent/` manifests and in
prose report tables, so "find newer examples" means re-deriving queries by hand. The failures this prevents:

- a sweep's searches are lost when `.agent/` is cleaned or the clone changes;
- a re-run that reports "0 results" when its control could not discriminate (the code-search tokenizer and query shape
  defects of #1471);
- a hand-maintained search list that drifts from what actually ran (the queries come from manifests on disk, never
  from an agent's retyping).

Deliverables: (a) a tracked saved-search file format; (b) the sweep WRITES its executed queries to it automatically,
on every exit; (c) a `mise run` task that re-runs a saved file, with controls; (d) a diff report against the previous
run and a staleness report. Skill → mise task → python; zero bash logic.

## 3. Interfaces

### 3.1 File format (TOML, `schema_version = 1`)

A superset of the N1 draft `[[watch]]` schema (`docs/specs/research-watch-2026-09-30.md` §3.1 on branch
`feat/native-cli-installers-workflow`), so the existing `docs/research/saved-searches/orchestration-2026-10-02.toml`
MUST load unchanged.

```toml
# generated by research-saved-search record — edits are overwritten on the next record; copy to a new file to curate
schema_version = 1
question = "<sweep question>"          # optional top-level
origin   = "report:<abs or repo-relative report path>"   # optional top-level

[[watch]]
id       = "issues-jdx-mise-llvm-project-3f2a9c1d"  # ^[a-z0-9][a-z0-9-]{0,79}$, unique in the file
kind     = "issues"            # "code" | "issues" | "discussions" | "releases"
origin   = "report:..."        # optional
question = "..."               # optional
cadence  = "weekly"            # optional: "daily" | "weekly" (default weekly)
tags     = []                  # optional list[str]
limit    = 10                  # optional, 1..100, default 10
repo     = "jdx/mise"          # issues/discussions: optional (absent ⇒ draft form, query used verbatim);
                               # releases: required
queries  = ["llvm-project"]    # non-empty for EVERY kind; for releases it is the term filter (an empty or
                               # all-stopword term set matches nothing: research_fanout.py:664-684)
role     = "query"             # code only, optional: "query" | "must-hit" | "health" | "readme"; default "query"
# code-only draft fields, all optional: grep, path_grep, control_hit, control_hit_grep, control_hit_path_grep,
# control_absent (must contain "{nonce}" when present)

[[result]]                     # baseline(s); extra keys tolerated (draft files carry examples/verified/…)
watch_id = "issues-jdx-mise-llvm-project-3f2a9c1d"
date_run = "2026-10-02T21:03:11+00:00"
status   = "ok"                # recorder writes research-fanout's status or "ok"/"error" for code rows
count    = 10                  # number of items (fan-out) or total_count (code)
urls     = ["https://github.com/jdx/mise/issues/13566", ...]   # fan-out items' urls, code items' html_url; may be []
```

Validation (rc 2, message names file, id and field; before any network call): unknown `[[watch]]` key; duplicate or
malformed id; unknown kind or role; `queries` empty for code/issues/discussions; releases without `repo`; `repo` not
matching `^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$` with a dot-only segment refused (same rule as
`research-sweep-run.js:105-108`; reuse `research_fanout._repo_ok`, `:1617-1621`); `limit` out of range; `control_absent` without `{nonce}`; a non-compiling
`grep`/`path_grep`/`control_hit_grep`/`control_hit_path_grep`; `schema_version != 1`; a `[[result]]` whose `watch_id`
names no watch (warning to stderr, not fatal — draft files carry `_controls-code`). `[[result]]` extra keys are allowed.

Id rule (recorder): `f"{kind}-{repo with / → -, or 'any'}-{slug(query)[:40]}-{sha256(kind|repo|query|role)[:8]}"`,
lower-cased, non-`[a-z0-9-]` → `-`, collapsed. Same search ⇒ same id across runs.

### 3.2 CLI: `mise run research-saved-search -- <subcommand>`

`main(argv: list[str], repo_root: Path, *, runner: Runner = default_runner, timing: ProbeTiming = _REAL_TIMING) -> int`
— same injection boundary as `research_fanout.main` (`research_fanout.py:2194-2201`). Relative paths resolve against
`repo_root` (`MISE_PROJECT_ROOT`, as `research_fanout._repo_root`, `:2223-2224`).

**`record`** — `record --out PATH [--question Q] [--origin O] [--fanout-manifest P]... [--probe-manifest P]... [--code-search ROLE=QUERY]...`
- Reads each fan-out manifest; for each source row whose `source` is `github-issues|github-discussions|github-releases`
  emits one watch (kind `issues|discussions|releases`, `repo` = manifest `repo`, `queries = [manifest query]`) and one
  `[[result]]` (`date_run` = manifest `generated_at`, `status` = row status, `count` = len(items), `urls` = item urls).
  Non-GitHub sources are not saved; their count is reported as `skipped_sources`.
- Reads each probe manifest (`{"kind":"probe","probes":[...]}`); each `kind == "code-search"` row with role in
  `query|must-hit|health|readme` becomes a `code` watch with that `role`, plus a `[[result]]` (`count` = row count,
  `status` = `ok` when rc 0 and count ≥ 0 and not rate-limited/incomplete, else `error`). `known-absent` rows are
  **never saved**: the token is spent once written down (`probes-need-a-control-arm.md` rule 3); rerun renders fresh
  ones (§4.3).
- `--code-search ROLE=QUERY` (roles as above, known-absent refused rc 2) adds a code watch with no `[[result]]` — for
  importing older sweeps whose code rows exist only in a report table.
- A missing/unreadable/malformed manifest is NOT fatal: listed in `missing`. Zero watches total ⇒ rc 1, nothing written.
- Merge: if `--out` exists and its first line is the generated header, existing watches are kept, new ids appended,
  and an id seen again gets its `[[result]]` replaced by the new one. If `--out` exists WITHOUT the header ⇒ rc 1,
  file untouched (never clobber a curated/hand-written file).
- Write via `tomli_w`, header comment prepended, atomically (temp file in the same dir + `os.replace`).
- stdout: one human line per watch, then a final line
  `SAVED-SEARCH-JSON {"kind":"saved-search-record","out":<exactly the --out string passed>,"path":<resolved>,"written":bool,"watches":N,"added":N,"updated":N,"skipped_sources":N,"missing":[...],"reason":str|null}`
  (compact JSON, sorted keys). The line is printed on EVERY outcome after argument parsing (rc 0 ⇒ `written: true`;
  rc 1 ⇒ `written: false` with `reason` = `no watches` or `refused: not a generated file`), so a workflow never reads a
  no-op as a save.

**`rerun`** — `rerun FILE [--id ID]... [--snapshot-dir DIR] [--report PATH] [--timeout S]`
- Runs every (or each `--id`) watch; writes a snapshot JSON to
  `DIR/<file stem>/<UTC %Y%m%dT%H%M%SZ>.json` (default DIR `.agent/kb/raw/saved-searches`, gitignored —
  `.gitignore:125`); prints a markdown diff report to stdout and to `--report` when given.
- rc 0 when every run watch is `ok` or `empty-verified`; rc 1 when any is `error`, `rate-limited`, `incomplete` or
  `empty-unarmed`, or a control failed; rc 2 on load/usage error.

**`status`** — `status [PATH]...` (default `docs/research/saved-searches/`)
- One row per file: watches, newest baseline `date_run`, newest snapshot time under the default snapshot dir, age in
  days, and `STALE` when age > the smallest cadence among its watches (daily = 1 d, weekly = 7 d). A file never re-run
  is aged from its baseline. rc 0 always (it is a report); rc 2 only on a load error.

### 3.3 Snapshot JSON

`{"file":..., "generated_at":..., "watches":[{"id","kind","query","repo","status","count","urls":[...],"confirmed":int|null,"reason":str|null}], "controls":[{"role","query","count","rc","status"}]}`.

### 4.2 Reuse, do not duplicate fetchers
- issues/discussions/releases with `repo`: `research_fanout.fan_out(FanoutRequest(query, repo, (source,), limit, timeout), runner=runner)`
  (`:143-151`, `:1209-1219`). Map its `Status` (`:93-101`): `ok`→`ok`, `empty_verified`→`empty-verified`,
  `empty_unverified`→`empty-unarmed`, `error`/`skipped`→`error`.
- issues/discussions in draft form (no `repo`): one `gh api` call through the same `runner` and `research_fanout._gh_env()`
  (`:544`): issues `search/issues?q=<quote_plus(q)>&per_page=<limit>`; discussions via the same GraphQL document as
  `_GITHUB_QUERY` (`:70-74`) with `searchQuery=q`. A draft watch's `control_hit` must return ≥1 and its
  `control_absent` (fresh `{nonce}`) 0, else every 0 in that watch is `empty-unarmed`.
- code: `research_fanout._gh_include` (`:1659-1686`, one retry after a ≤60 s rate-limit wait) with
  `["-X","GET","search/code","-f",f"q={q}","-f",f"per_page={limit}"]`; read `total_count`, `incomplete_results`,
  `items[].html_url`, `items[].url`, `items[].path`, `items[].repository.full_name`. Rate-limit and incomplete handling
  exactly as `_code_search_probe` (`:1689-1714`): a failed or limited search has count -1, never 0.
- Use `from dotfiles_setup.research_fanout import ...` (never `research_fanout._x` attribute access: ruff SLF001 is
  stable under `select = ["ALL"]`, `pyproject.toml:75-77`, and inline suppressions are banned). If ruff rejects a
  private-name import, add public aliases in `research_fanout.py` with no behaviour change.
- `fan_out` checks `shutil.which("gh")` itself (`_prerequisite_reason`, `research_fanout.py:969-973`), regardless of
  the injected runner; tests MUST put a fake `gh` on PATH the way `tests/test_research_fanout.py:330-337`
  (`_install_path_tools`) does, or every GitHub source comes back SKIPPED.
- COUNT SEMANTICS (rev 2.1 — ONE rule, supersedes any other wording incl. §4.4): a run's `count` is the API
  `total_count` for every DIRECT search call (code, and draft-form issues without `repo`), and the number of items
  returned (≤ `limit`) for every fan-out call (issues/discussions/releases WITH `repo`). A baseline's previous count is
  `count` when present, else `total_count` (draft files store only `total_count` for both code and issues, e.g.
  `orchestration-2026-10-02.toml:389-394`). Because a watch's form never changes between runs, both sides of a diff
  always use the same measure. `count = -1` means "no count" (a failed or limited search, `research_fanout.py:1689-1714`);
  never treat it as 0 and never give the schema's `count` a `minimum` above -1.
- Dates: `date_run` may be RFC 3339 or date-only (`2026-10-02`, draft files); a date-only value means 00:00 UTC.
  An empty string `grep`/`path_grep`/`control_hit_grep`/`control_hit_path_grep` (`''`) means "not given".

### 4.3 Controls on rerun (`probes-need-a-control-arm.md`)
- Code searches are serialised with a pace of 6.5 s between `search/code` calls via the injected `timing.sleep`
  (GitHub's 10/min code-search bucket; this also avoids the shared-bucket collision of #1582).
- Once per rerun containing a code watch: the health control `repo:cli/cli filename:README.md`
  (`research-sweep-run.js:169`) must return > 0, else every code result is `error` with reason `code search unhealthy`.
- Per distinct SHAPE among `role = "query"` code watches: one known-absent `"<nonce>" <qualifier tokens>` where the
  qualifier tokens are the shape's `key:value` tokens only (boolean operators and parentheses are dropped — a nonce
  cannot be OR-ed meaningfully), with `nonce = "zz" + secrets.token_hex(6)`, generated fresh per run, never written to
  the TOML (only to the snapshot). It must return 0; if it returns > 0 that shape cannot discriminate and every 0 of
  that shape is `empty-unarmed`.
- A draft code watch's own `control_hit` (> 0, and `control_hit_grep`/`control_hit_path_grep` confirmed on ≥ 1 item
  when given) plus its own rendered `control_absent` (== 0) arm THAT watch regardless of shape, as the N1 draft
  intends; recorded watches are armed only by the shape rule below.
- SHAPE = the same rule as the workflow's `shapeOf` (`research-sweep-run.js`, the `const shapeOf` line): qualifier
  tokens `^-?[A-Za-z_]+:\S` lower-cased, plus `OR|AND|NOT`, plus `()` for any token containing a paren; sorted,
  space-joined. Port it and test it against the same examples.
- A `query` code watch with count 0 is `empty-verified` only when, in THIS rerun, a same-shape `must-hit` code watch
  (or that watch's draft `control_hit`) returned > 0 AND that shape's known-absent returned 0. Otherwise `empty-unarmed`.
- Draft code watches with `grep`/`path_grep`: re-fetch up to `limit` items (`gh api <item.url> -H "Accept: application/vnd.github.raw"`,
  core bucket, not paced) and set `confirmed` = count matching all given patterns; a re-fetch failure is unconfirmed.
  Recorded watches have no grep ⇒ `confirmed = null`.

### 4.4 Diff report
Previous = the newest snapshot for the same file stem older than this run; else the TOML's newest `[[result]]` per
watch (`count` from `count` or `total_count`; `urls` if present). Per watch, print: id, kind, query, prev count → new
count, status (and change), `NEW` urls (in new, not prev), `GONE` urls. A watch with no previous is `first run`.
Header: file, run time, previous source (`snapshot <path>` or `baseline`), totals per status. Never print environment
values or tokens.

Rev 2.2 (live rerun + `docs/research/kb/reports/agents/saved-searches-diff-identity-review-2026-10-03.md`, option
chosen by Ray 2026-10-03):
- URL identity is the canonical blob URL: `/blob/<ref>/` → `/blob/HEAD/` (`_canonical`), applied to new URLs, to
  previous URLs before diffing, and in `record`. search/code's ref is the repo's head commit and moves on every push,
  so raw URLs made every unchanged hit NEW + GONE.
- A row whose `count` exceeds its stored URLs is marked `(top N of M)`: NEW/GONE there can be best-match ranking churn.
- The report ends with a `## Controls` table, so an rc 1 caused by a control is explained.
- A code watch with `control_hit` and no `control_absent` borrows its shape's fresh known-absent (§4.3); for other
  kinds a lone `control_hit` cannot arm (rc 1).
- Deferred to a follow-up issue: a CHANGED state from the item blob `sha`, and `sort=created` for draft issues.

Rev 2.3 (`docs/research/kb/reports/agents/saved-searches-newer-examples-research-2026-10-03.md`): code search ranks by
best match with no date sort or qualifier, so a top-`limit` window diffs a RANKING and a new example ranked below it
never shows. A code `query` watch DEFAULTS to `collect = "all"`. Ray ruled 2026-10-03: "make it configurable, but
collect all should be the default". `collect = "top"` opts a watch out; must-hit, health and readme controls default to
`top`, because they need only a count above 0. See `collect_mode`. Rerun then:
- pages `per_page=100` until a short page, up to the 1000-result cap, paced like every search/code call;
- diffs the full canonical repo+path set;
- reports `count` as the number collected (`total_count` moved 125 → 141 seconds apart);
- marks the run `complete`.
Failure and limit handling:
- One failed, limited or incomplete page fails the whole run, so no partial set is ever diffed.
- `total_count > 1000` returns the new status `uncollectable` after one call; split the query, for example by `size:`
  ranges.
- grep confirmation re-fetches only the top `limit` items.
- The first full collection after a top-window run shows `n/a (first full collection)` instead of diffing.
- `collect = "all"` on any other kind or role is a load error (rc 2).
