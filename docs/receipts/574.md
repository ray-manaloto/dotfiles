# Receipt — #574: Grill node granularity and the first-slice role set

**Verdict:** The tick's selectable unit is **one STAGE of a ticket**, not a whole ticket: a
`/to-tickets` ticket is exploded into a chain of stage issues linked by native `blockedBy`, and
one node = one stage = one short `claude --bg` session. The tracker carries exactly **one**
selector axis — a `dag:stage:<name>` label — and everything else (kind, role, runner, model,
effort, per-stage slot cap, permission mode, budget cap) lives in a **reviewed table in the
repo**, which is therefore the configuration surface; a stage label with no table row must fail
**closed**. The **scheduler** expands a ready ticket into its stage chain deterministically — no
LLM ever writes graph topology — and #573's *"the body is NEVER machine-written"* is narrowed, in
this receipt and deliberately, to *"the scheduler never **EDITS** a body"*: a stage issue's body is
**authored once at creation** as the rendered brief (parent link, stage, role, evidence contract)
and never rewritten, because the rule guarded an *edit* hazard (a read-then-replace that no-opped
an empty fetch to `""` and pushed a wiped body at rc=0) that creation cannot reach. Slice 1's chain
is **`research → implement → review`** — #550's three roles unchanged — with `gate` a *kind* that
materialises only on escalation, never a per-ticket stage (map #556 fixed exactly one static gate,
at the spec, above the ticket). Nodes launch as
`claude --bg --agent <role> --model <m> --effort <e> "<rendered brief>"`: the role stays a project
`.claude/agents/` file, the per-ticket brief is passed as the **positional prompt**, and
`initialPrompt` is **never** used because plugin scope drops it *silently*. Stage models are
**research → Opus 5 @ `high` for the first 3-5 tickets, then Sonnet 5 by a one-row table PR;
implement → Codex `sol` @ extra-high; review → Opus 5 @ `high`**; **Haiku appears nowhere** (200K
context against a 1M-needing corpus sweep, no `effort` dial at all, and therefore unlaunchable by a
launcher that must pass `--effort`), and **Fable appears nowhere in the table** — its advisory
consult is endorsed in shape but sits behind a four-step probe, while the probe-free form (a
human-invoked Fable advisory session over a decision's evidence, reachable from the `gate`) is
what this grill itself ran. The table carries only knobs something **consumes** in slice 1 —
`permission_mode`, the per-stage slot cap, and a hard budget cap — with `turn_timeout_ms` and
`stall_timeout_ms` deferred to #590, because #578 shipped WEDGED as **log-only** and a declared
timeout nothing enforces reads to the next session as working stall detection. Role bodies adopt
itervox's split as **two labelled sections in the one agent file** (`## Soul` / `## Instructions`,
both asserted by #550's validator seam), because `--agent` resolves to exactly one file and git
already reviews a section-scoped diff independently.

## The stage table (slice 1)

| Stage | Runner | Model | Effort | Grounds |
|---|---|---|---|---|
| `research` | `claude --bg --agent researcher` | **Opus 5** (bring-up, 3-5 tickets) → **Sonnet 5** | `high` | 1M window for the 6,446-file corpus; bring-up per the vendor's *"harder to distinguish between model failures and setup failures"* |
| `implement` | `codex exec` | `sol` | extra-high | Standing mode; the only lane adding Anthropic-side headroom; it is also what makes the reviewer cross-family |
| `review` | `claude --bg --agent adversarial-reviewer` | **Opus 5** | `high` | Highest judgment density, smallest input; the only sourced numbers put cheaper review at 92-96% of frontier, worst on a tail-catching pass |
| `gate` | human | — | — | Escalation-only kind (no per-ticket gate) |

Five constraints the table's schema must carry: **effort is a mandatory column** (a
non-interactive `/effort` cannot release the model-default hold, so `--effort` must be passed at
launch); the schema should **forbid `haiku`** (it has no effort dial, so a launcher that always
passes `--effort` cannot treat it uniformly); the `review` role needs two *measured* prompt rules
now — coverage-first with **no** severity filter, and **delete** any self-verification instruction,
both of which have silent recall failure modes; the cost model is **date-stamped** (Sonnet 5 intro
pricing ends 2026-08-31, so research input rises 50% on 09-01); and the advisor's
**capability-ordering constraint** (advisor ≥ executor, vendor-enforced with a 400) is encoded now
even though the advisor is deferred, so the schema cannot express cheap-advises-expensive and
discover it at runtime in a background node nobody is watching.

⚠️ **Verify the model that actually ran, from the result message's `modelUsage`.** A subagent whose
model is excluded by `availableModels` is **silently run on the inherited model**, and org effort
caps clamp **silently** in background agents. A stage table is only as true as the check that the
node honoured it.

## Adversarial review

**Lens:** a dedicated **Fable 5 advisory pass** over the four workers' output plus the full
decision log, briefed to overturn rather than ratify (*"an advisory pass that ratifies everything
is worth nothing"*). Persisted verbatim: `574-fable-advisory.md`.
**Verdict:** R1-R6 ratified; **one dissent accepted as a correction, one as a design change.**

- **D1 — accepted, and it corrects this session's own synthesis.** The R7 rationale as first
  logged imported *"separate rate-limit pools ⇒ heterogeneous stage models are a throughput win"* —
  an **API-metering** fact — onto the **subscription** meter the DAG actually runs on, where
  per-model API pools buy nothing. This receipt therefore grounds R7 on: 2× price
  (API-corroborated), the Fable **entitlement gate** (the native `model_fable_consent`
  substitution), the 25-40% ITPM/OTPM throttle **as evidence of vendor-side rationing** rather than
  as our operative ceiling, and **Codex as the only real headroom**. The decisions survive; the
  stated ground did not.
- **D2 — accepted as the bring-up phase** now in the table above.
- **R1 was the invited target and survived on four independent mechanisms**, the strongest of
  which no worker stated: **prompt caches do not cross models**, so with Sonnet / `sol` / Opus per
  stage the "merge the stages" alternative saves nothing *even in principle* — the ~78-85k floor
  is the price of heterogeneous models, not of stage-per-issue. The remaining three: implement is
  another vendor's CLI and #550 US-14 requires a reviewer with no design context, so two boundaries
  are structural regardless; #573's rework semantics need an upstream issue to exist; and a
  whole-ticket single-context node trips the ~30% context gate, converting one floor into a
  restart-with-handoff anyway.

Each of the four worker reports also ran control arms and **self-corrected**: `model-select`
retracted "the supply claim is unsupported" after fetching the page that owned the fact;

caught a false negative in its own first fetch.

## Notes

- **Adopt orch-budget's objection as a standing table-review question, not a redesign:** any PR
  adding a stage row must answer *"does this split save more than one ~78-85k floor, or differ from
  a neighbour in model or effort?"* The "prefer fewer, larger nodes" caution binds **below** stage
  granularity and on **fan-out width**, not on stage-per-issue.
- ⚠️ **Load-bearing and still single-route:** *"model choice lowers the burn RATE"* of the shared
  window is inherited from `wf-dag-model-routing.md` §5 and never re-derived. If the window meters
  raw tokens **unweighted by model**, Sonnet-vs-Opus buys nothing against the binding constraint
  and steady-state reduces to "Fable is gated + Codex adds headroom". Second route: the vendor's
  subscription usage/limits docs (step-00 KB grep first), or an observed `/usage` delta across two
  same-shape workloads on different models. Settle it before any budget plan rests on it. Note also
  that Opus burns a **second** meter (`seven_day_opus`), which the bring-up phase doubles down on.
- **The research-stage contradiction, resolved here so it is not reopened:** `fable-skeptic`'s
  sources name research/synthesis as Fable's *flagship* strength while the vendor-corpus workers
  assign research to Sonnet. Both are right — research is **many-turn**, and many-turn is exactly
  where Fable's superlinear turn cost and rationed supply bite hardest. Fable's best *fit* is its
  worst *cost case*.
- **Availability ≠ elicitation.** *"Defining the tool is not sufficient on its own; without an
  instruction in the system prompt, Claude Fable 5 rarely calls it."* This is the best available
  mechanism for this repo's 3-of-3 SendMessage-before-idle failures, and it generalises to every
  node's evidence-comment contract: the role definition must **elicit** the delivery act, not
  merely permit it. It goes in all three role `## Instructions` sections. Measured this session:
  the one brief that asked explicitly delivered both file-first and by message.
- **The Fable advisory probe, stop at the first failure:** (1) the surface exists in this pinned
  Claude Code under subscription auth — KB step-00 grep first, then a live probe, not a web search;
  (2) a call succeeds from `--bg` on subscription auth, **both arms** (a valid pairing succeeds AND
  cheap-advises-expensive returns the documented 400); (3) the economics survive the CLI path — the
  consult must read the **existing** transcript, since one that re-uploads context is a worse Fable
  node, not a cheaper one; (4) frequency is controllable.
- **Deferred deliberately:** the exact `dag:*` label spellings and table file path, the per-stage
  cap and budget *values*, the evidence contracts each stage's brief renders, and when bring-up
  ends. This grill fixed semantics, not spellings or numbers.
- ⚠️ **Operational, found while triaging an unrelated bot PR:** `WebFetch` refuses verbatim
  vendor-doc reproduction on copyright grounds — research briefs that need quotes must route
  through the exa raw fetcher.
