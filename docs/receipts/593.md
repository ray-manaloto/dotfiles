# Receipt — #593: Probe roster `procStart` encoding; add PID-reuse defense to dag-tick liveness

**Verdict:** The encoding is **pinned with both arms and the defense SHIPPED** — Ray's
"ship nothing" ruling did not trigger. `procStart` is the literal `ps -o lstart=` string
under `LC_ALL=C TZ=UTC`, trimmed; comparison is **exact string equality**;
`background_pid_alive` now requires liveness AND identity, and adds a negative only on a
**positively-read, differing** value. The `PermissionError`-reads-ALIVE half is in scope and
**deliberately left as-is**: it is the harness's own conservative predicate, and the identity
read closes the real hazard exactly where `kill(pid, 0)` is blind.

**Resolved:** 2026-08-07

## The probe

### Live sample — the roster entry (`claude --bg`, read while running, then stopped + `claude rm`'d)

```json
"2be66919": { "pid": 30714, "procStart": "Fri Aug  7 19:12:08 2026", "cliVersion": "2.1.224", … }
```

| Arm | Command | Result |
|---|---|---|
| **match** | `LC_ALL=C TZ=UTC ps -o lstart= -p 30714` | `Fri Aug  7 19:12:08 2026` — **byte-exact** |
| **mismatch (control)** | `ps -o lstart= -p 30714` (host locale/zone) | `Fri Aug  7 14:12:08 2026` — differs by the UTC offset |
| **discrimination** | same, `-p 1` | `Mon Aug  3 05:18:29 2026` — a different process reads differently |
| **unanswered** | same, `-p 97893` (dead) | rc=1, empty |

So the probe can return match, mismatch, and no-answer. It is not a coin with one face.

### From the binary (2.1.224, byte-search)

```js
function RKe(e){ let t=T7e(`LC_ALL=C TZ=UTC ps -o lstart= -p ${e}`,{timeout:1000}); return t?t.trim():void 0 }
function iau(e,t){ return t===void 0 || t===e || Ad_(e,t) }          // recorded, actual
function Ad_(e,t){ if(!cho())return!1; … r>300000000000000000!==n>300000000000000000 }
function cho(){ return!1 }
async function s3(e,t){ if(t===void 0)return!0; return iau(t, await Qk(e)) }
```

and the roster GC path, reading this same `roster.json`:

```js
zC(f.pid) && await s3(f.pid, "procStart" in f && typeof f.procStart==="string" ? f.procStart : void 0)
```

**Tolerance: none, on this platform.** `Ad_` is a numeric-units escape for the alternate
`procStartFt` encoding and is gated behind `cho()`.

| Bundle | Ft-mode guard | Body |
|---|---|---|
| 2.1.222 | `Vlo` | `return!1` |
| 2.1.223 | `Iuo` | `return!1` |
| 2.1.224 | `cho` | `return!1` |

Found **structurally** (via the unique `{procStart:void 0,procStartFt:` writer, 1 hit per
bundle) rather than by name — minified identifiers differ per build, and searching
`function cho(){return!1}` across all three returns 1, which alone would have looked like
"2.1.224 added it". The `return!0` arm was probed too: **0 in all three**. An `lstart`
string is not numeric anyway, so `Number.isFinite` would reject it even if the mode flipped.

### The `PermissionError` half — Ray's ruling 2, and why nothing changed

The bundle ships **two** predicates over the same syscall:

| Export | Behaviour on EPERM | Used where |
|---|---|---|
| `isProcessRunning` (`zC`) | **dead** — any throw is false | roster GC, lock checks |
| `isProcessProvablyGone` (`htn`) | **alive** — `return zt(t)==="ESRCH"` | conservative callers |

`pid_is_alive` is the second, and that is right for a caller whose DEAD branch **respawns**:
a false-DEAD double-starts a node (the #601 class), a false-ALIVE costs one 60s cycle.

The real EPERM hazard is an **identity** failure, not a liveness one — a recycled pid landing
on another user's process answers `kill(pid, 0)` with EPERM forever. Measured live:

```
pid=1     kill(0)->PermissionError    ps rc=0 lstart='Mon Aug  3 05:18:29 2026'
pid=65890 kill(0)->ALIVE(no-raise)    ps rc=0 lstart='Fri Aug  7 19:13:13 2026'
```

`ps` reads another user's start time fine. So the identity check closes it exactly where
`kill` is blind, and pid 1 is a real (not synthetic) end-to-end arm in the test suite.

⚠️ One divergence worth naming: the harness's own in-life supervisor treats
`ESRCH || EPERM` as vanished (`checkPid`). That is a supervisor watching its OWN child, where
EPERM really does mean "no longer mine". Ours watches from the outside, so it stays
conservative and lets identity decide. Both reach DEAD on a recycled pid.

## What shipped

`background_pid_alive` = liveness **AND** identity, with the negative added on one branch only:

| Roster entry | Outcome | Mirrors |
|---|---|---|
| no `procStart` | pid liveness decides | `isSameProcessAsync(pid, undefined) -> true`; `pidRecycled`'s `if(!this.procStart)return!1` |
| `ps` unanswered **or blank** | **ALIVE** | `iau`'s `actual === undefined \|\| actual === recorded` |
| read, and differs | **DEAD** | the GC path's reap; `pidRecycled`'s `e!==this.procStart` |

The blank case is guarded **twice** — normalized in `read_proc_start`, re-tested at the call
site — because `"" == recorded` is False for every real value, i.e. a blank compared as if it
were a reading fails toward the respawn. That cell was found by mutation testing, not by
design.

Also corrected in the same change: the module docstring asserted a `kind:"background"` census
row *"carries `state` but never `pid`"*. On 2.1.224 it **does**, and it is the wrong process —
census `pid: 30723` (`claude bg-spare`) vs roster `pid: 30714` (`claude bg-pty-host`), its
parent, both from the same live sample. Left standing, that is an invitation to drop the
roster read in favour of a pid the harness never pairs with `procStart`.

### Mutation testing — differing blast radii

| Mutation (the realistic regression) | Tests that fail |
|---|---|
| identity wiring deleted (pre-#593 behaviour) | **4** — unit, live-default, classifier end-to-end, `execute_respawn` end-to-end |
| unanswered-`ps` guard dropped | **1** |
| `TZ=UTC` dropped from the reader | **2** |

The 1-failure result is the signature `tests/AGENTS.md` warns about, and following it up found
a real unenumerated neighbouring cell (the blank reading), now pinned.

⚠️ **`TZ=UTC` is the axis nothing else could have caught.** Every other test compares the
reader against **itself**, so an off-by-the-UTC-offset reader passes them all while
mismatching every real node — the roster's value is written by the CLI, not by us. It is
pinned as a property against an independent adjudicator, `ps -o etime=`, a **duration**, so no
timezone is involved in producing it. On a host whose local zone is UTC (a CI runner) the two
coincide and the test is satisfied vacuously — honest, because there the defect has no
observable effect. This is `session-2026-08-07c.md` §5.13 applied: gate against an artifact
you did not author.

## Notes

- **Phase-5-adjacent, deliberately not done:** nothing here reads `dag-binding.json` or
  touches projection. #593 is a liveness fix only.
- **What to re-check if the CLI moves:** the Ft-mode guard. If a future bundle's equivalent of
  `cho()` returns true, the roster writes `procStartFt` instead and `read_roster`'s
  `entry.get("procStart")` silently goes `None` — which reads ALIVE, so the defense degrades
  to pre-#593 behaviour **quietly**. Find the guard structurally (the unique
  `{procStart:void 0,procStartFt:` writer), never by its minified name.
- **`monkeypatch.setattr(dag_tick.subprocess, "Popen", …)` patches the stdlib module**, and
  `subprocess.run` is built on `Popen` — so the new reader dies inside any Popen-patched test.
  Inject the `proc_start` seam instead; one new test hit this and says so inline.
- **The probe vehicle, for next time:** `claude --bg "<prompt>"` (positional — `-p` is refused,
  it conflicts with `--bg`) populates `workers{}` within **1 second** and revives a dead
  supervisor as a side effect. Sample the roster in the same breath as the spawn: the daemon
  dies on its own within the hour, which is what left #578 with an empty roster.
