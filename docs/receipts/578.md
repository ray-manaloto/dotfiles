# Receipt — #578: Build the launchd watchdog tick (`mise run dag-tick`)

**Verdict:** Shipped — slice 1 of the #573 pull-loop scheduler design, exactly the OUTER loop
the ticket scoped. A declarative `[bootstrap.macos.launchd.agents.dotfiles-dag-tick]` block in
`mise.toml` (`start_interval = 60`, `program` = the literal `~/.local/bin/mise` binary — the
bare name is a zsh function launchd cannot exec) fires `mise run dag-tick`, a thin task over
`python/src/dotfiles_setup/dag_tick.py` (zero-bash-logic). Each tick, in fixed order: one
non-truncating `flock` (overlap guard + single-writer) → fleet-gate preflight (`claude logs
<fresh-uuid>`; both faces exit rc=1, so the state is read from stderr TEXT only) → census
(`claude agents --json --cwd <repo> --all`, a TTY-free top-level array; only
`kind:"background"` rows are in scope) → classify ALIVE/DEAD/WEDGED/DONE (the #565
terminal predicate: `state ∈ {done,failed,stopped} ∧ tempo ≠ "active" ∧ no queuedPrompt`;
background pid liveness comes from `~/.claude/daemon/roster.json`, since background census
rows carry no pid) → act (DEAD → `claude respawn` via the binary's own `/restart` recipe
verbatim — strip the 12-name `RQr` set + `CLAUDE_JOB_DIR` + every `CLAUDE_BG_*`, spawn
detached, stdio ignored, cwd `$HOME`; DONE-with-live-pid → `claude stop`, after a fresh
pid re-check; WEDGED → **log only**, stall recovery is #590 by Ray's round-2 trade) → exit 0
always — every failure mode (lock held, gate off, census unreadable, missing binary)
degrades to "do nothing this tick; the next tick reconciles". A `--max-age` bound (default
24h) keeps recovery honest: a DEAD node older than it (or with no readable age) gets a LOG
line, never a respawn — crash recovery, not archaeology. The block is **inert until a
human runs `mise bootstrap macos launchd-agents apply`** (or plain `mise bootstrap`, its
step 11 per the live `--help`) — merging this changes nothing on the host. Commits:
