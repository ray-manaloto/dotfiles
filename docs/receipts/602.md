# Receipt — #602: Project NEEDS_HUMAN to the tracker

**Verdict:** The projection is **built and live**, as the SCHEDULER'S first slice
rather than a watchdog feature — `dotfiles_setup.dag_project`, its own
`mise run dag-project` verb, and its own LaunchAgent at 300s, all importing
`dag_tick`'s predicates rather than re-deriving them. An escalated node
(`state=blocked` ∧ `needs` ∧ ¬`queuedPrompt`) now reaches the tracker as the
`dag:needs-human` label plus one append-only comment per **(node, question)**,
deduped on an invisible `node=<id> digest=<sha256(needs)[:12]>` marker. The
ticket named three deferrals and the scoping pass found a **fourth it had not**:
nothing binds a node to an issue — no such field in the union of every
`state.json` key set on this host — so a bound-nodes-only reading would have
shipped #602 surfacing **0 of its own 2 motivating cases**. Ray ruled: the
scheduler writes `dag-binding.json` at dispatch, and an UNBOUND node projects to
a standing escalation issue (**#623**). R5 became a **label, not a gate**, decided
**structurally** ("is there a machine-readable evidence field?") rather than
semantically, because reading it as a gate would DROP both live escalations and
recreate the silence #602 exists to end — and because the #601 review already
killed substring-based meaning-judging across two rounds. Consequence, stated
rather than hidden: **every harness-native escalation is UNVALIDATED today**,
measured 3-for-3 across CLI 2.1.207 / 2.1.217 / 2.1.224. The ANSWER path stays
out of scope on **evidence** rather than on R1's boundary argument: a dead
blocked node is enumerable (as a server-side `bridge` row, kept *because* it is
not locally live) but **not addressable** — `SendMessage` returns
`success: false`, enforced in code — and 2.1.224 added restriction on two axes,
not reach. **Phases 1-4 shipped; phase 5 (the dispatch binding) is blocked on a
dispatcher existing**, which costs nothing today because every real node is
unbound and routes to #623.

## Adversarial review

**Lens:** the by-hand pilot (phase 1) and the gates themselves, rather than a
review agent — every finding below came from PRODUCING an artifact or running a
gate, not from reading a diff.

- **Phase 1 caught three format defects that reading the format had not.** A
  blockquote does not quote verbatim (the real payload CONTAINS backticks, which
  GitHub renders as inline code); a timestamp carried LOCAL `ls` time stamped
  `Z`; an example asserted a job dir was gone when it existed. ⚠️ **And the gate
  itself was wrong in the more interesting direction** — "both comments render
  correctly" would have PASSED the broken draft, because a mangled payload
  renders beautifully. It only became a real check when restated as a **byte
  comparison against `state.json`**.
- **Phase 2's gate caught two more.** Comparing `--dry-run` output against the
  comments already live on #623 — hand-written before the module existed, so not
  fixtures this code authored — showed the mtime was the fixture's COPY date
  while `updatedAt` held the real one; `updatedAt` is now authoritative. And
  `git checkout --` cannot restore an UNTRACKED file, so four mutation arms
  accumulated and the "restored" run was still broken.
- **The token audit caught me twice.** `'"--repo",'` matched **5 sites** in
  `main.py` and bound none of them; then adding a second LaunchAgent gave
  `mise.toml` a second `program = "~/.local/bin/mise"`, breaking
  `workflow.dag-tick-wiring`'s previously-unique token — in a contract this
  change never edited. The first was rebound; the second is recorded in
  `AMBIGUITY_ALLOWED` with a reason, because there the multiplicity IS the
  assertion.
- **Two wrong mechanisms were published for one right conclusion.** The
  answer-path probe's round 1 said a dead node "is not in the namespace" —
  correct for the `uds` transport, stated about all four. Round 2 retracted it.
  The verdict never moved; the mechanism under it was wrong twice.

## Notes

- ⚠️ **`_needs_human_reason()`'s clause *"tracker projection to dag:needs-human is
  NOT done here — #602"* stays TRUE and must not be edited.** It is scoped to
  THAT process, `dag_project` is a separate one, and the string is pinned by
  golden equality — which now also guards operator-facing tracker content,
  because the comment reproduces it verbatim.
- ⚠️ **The LaunchAgent is INERT** until a human runs `mise bootstrap macos
  launchd-agents apply`. Verified at ship time: no plist, not loaded.
- **The live two-run gate passed against scratch issue #629** (created, used,
  closed): run 1 posted exactly one comment and applied the label, run 2 skipped
  as a duplicate and posted nothing; the payload round-tripped through the real
  `gh --body`. The escalation was **manufactured** with `claude --bg --bare`,
  which lands a node in `blocked` + `needs: "login required — run /login"` in
  seconds — a better fixture than a hand-authored one, because the harness's own
  writer produces it at the current CLI version.
- **`None` and `set()` mean opposite things** when reading a target's existing
  markers, and the code must not collapse them: empty is *safe to post*, `None`
  is *could not look* and SKIPS, reported as a distinct `skipped-unreadable`.
- **A closed STANDING issue is reopened; a closed BOUND issue is not** — the
  latter is rework, whose semantics `575.md` R7 owns.
- ⚠️ **Not proven, and worth naming:** whether the harness's own supervisor
  respawns a `blocked` node. That is the unverified single-route claim #575
  handed to #590, and 2.1.224 did not touch it — so `_needs_human_reason()`'s
  "separate route this module cannot close" count is still **2**, not 3.
- **An escalated node whose daemon has died is removable by NO automated path**
  (`claude rm` needs the daemon socket; `dag_tick` deliberately never acts on a
  NEEDS_HUMAN node). Surfaced by #602's own phase 1; it belongs with **#590**.
