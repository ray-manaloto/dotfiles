### 4. Anthropic's own design signal: files + just-in-time retrieval

The platform **memory tool** (`memory_20250818`, GA on the Messages API) is a **directory of files** with view/create/str_replace/insert/delete/rename — explicitly framed as "just-in-time context retrieval: rather than loading all relevant information up front, an agent records what it learns in memory files and reads them back on demand," linking Anthropic's "Effective context engineering for AI agents." No graph, no embeddings, no query language — a filesystem contract. Source: <https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool.md> (fetched 2026-07-09). Claude Code's native auto memory implements the same shape (bounded MEMORY.md index + on-demand topic files).

**Implication for the domain recommendation:** Anthropic's first-party memory surfaces — API memory tool, Claude Code auto memory, CLAUDE.md/rules/skills — are ALL "structured files + bounded index + lazy read," none are graph or vector stores. The repo's existing architecture (mintlify-cache + `mintlify-catalog.md` index + cache-first grep + repos-touched enumeration sections) is already the native-aligned pattern; what it lacks versus native auto memory is only the *bounded always-loaded index* discipline (a ≤200-line INDEX.md over `docs/research/**` + `docs/research/runs/**` would replicate `MEMORY.md` semantics inside the tracked corpus).

### 5. Bottom-line assessment for this angle

- **No plugin candidate from claude-plugins-community qualifies as THE research KB.** The only mature one (claude-mem, 86.6k stars, daily commits) is session-observation memory with an MCP retrieval layer — wrong corpus (tool-call history, not curated research artifacts) and wrong integration shape for the `no_mcp_registration` rationale. The KB-shaped ones (agent-knowledge, agent-recall) are 7-13-star single-maintainer MCP servers; agent-knowledge is ~3 months stale.
- **auto-memory (severity1) is the only constraint-clean plugin** and is complementary, not competitive: it maintains CLAUDE.md, it does not retrieve. Ray already evaluated and disabled it (`.claude/settings.json:54`); the repo's hk-enforced CLAUDE.md size cap and hand-curated rules pipeline make its auto-writes a governance risk (AUTO-MANAGED sections vs. `claude_md_size_limit`).
- **The native surface that scales is a pattern, not a product:** bounded index loaded always + topic/artifact files read on demand + git for sync. Native auto memory should stay on for what it is (machine-local session learnings) but cannot host the corpus (machine-local, Claude-curated, not reviewable). The corpus belongs in tracked markdown with an index file — which is also what Anthropic's memory tool and auto memory would independently converge to.
