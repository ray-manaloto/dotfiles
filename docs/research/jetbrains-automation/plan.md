> The plan as of the spike (2026-11-05). The tracked implementation is `swift/` (jbax) and `python/jbctl/` (issue #502).

# jbctl plan: drive JetBrains IDEs from code, with zero or minimal agent tokens

Goal: any routine IDE change (settings, toggles, dropdowns, navigation) runs as a deterministic
script. It needs no LLM in the loop and verifies its own result. An agent is needed only to
author a new recipe, or to repair one after an IDE update breaks it.

## Architecture: map once, execute many

```
 rea (mapping, offline)   ──►  widget maps (JSON, versioned per IDE build)
                                          │
 recipes (declarative JSON/YAML) ─────────┤
                                          ▼
 jbctl executor (Python, no LLM) ──► backends:
   1. rea scenario       press / scroll / key-entry (AXValue)            background
   2. jbax (Swift)       select (AXSelected), popup windows, labels      background
   3. agent-desktop      press keys, focus-window, menus, headed input   foreground only
                                          │
                                          ▼
 verifiers: breadcrumb/page check, AX value, screenshot, external truth (MCP tools/list,
 options/*.xml)
```

### Who does what (from what was proven on CLion 2026.3, 2026-11-05)

| need | backend | background? | status |
|---|---|---|---|
| map a window: roles, Swing labels, actions, paths | rea observe-native-ui (patched) | yes | ✅ |
| navigate Settings pages | rea key-entry into the Settings search, then clear; breadcrumb check | yes | ✅ |
| press buttons (Apply/OK/Cancel, links, checkboxes) | rea click (AXPress) | yes | ✅ |
| commit a dropdown (JComboBox) | jbax: AXSelected on the popup child, row-0 only, guarded | yes | ✅ (`jbax select`) |
| dropdown rows other than index 0 | agent-desktop: focus-window + Tab/Space/Down/Return | **no** | ✅ foreground only |
| see popup menus and dropdown lists | jbax (rea refuses windows with layer ≠ 0) | yes, read only | ✅ probes; to be folded into jbax |
| run a popup row (gear menu, ListPopup) | needs Enter or a real click: agent-desktop, foreground | **no** | source-confirmed limit |
| open Settings | agent-desktop: focus-window + menu AXPress + hand the front back | **no** (~1.2–2.7 s) | ✅ `open-settings.sh` |
| real keys (Tab, Return, shortcuts) | agent-desktop press (CGEventPostToPid), app must be active | **no** | ✅ |

Hard limits, by design (JBR/AppKit):
- No Java focus owner while the IDE is inactive, so keys need activation.
- AppKit drops menu AXPress for an inactive app.
- ListPopup runs rows only on Enter or a click.

Everything else runs in the background.

## Zero-token execution

1. **Recipes are data.** For example `recipes/clion/mcp-router-direct.json`:
   `open-settings → goto "Exposed Tools" → select-guarded combo "Enable router-only mode for:"
   row-0 == "ACP agents only" → press OK → verify mcp-tools>1`.
   The executor resolves every target by **role + label (+ breadcrumb page)**, never by a stored path,
   so layout shifts don't break it.
2. **Guards make failures safe.** Each step checks a precondition (row text, page breadcrumb, button
   enabled) and refuses before acting. Each recipe ends with an external verifier.
3. **An exit code and a one-line report**, so a cron job, a hook or a shell alias can run it with no
   agent. An agent is woken only on a non-zero exit, with the failing step plus a fresh rea map of
   that window. That is the only token spend.
4. **Maps are versioned per IDE build** (`maps/<product>-<build>/<window>.json`, generated by rea).
   A diff between builds flags renamed or moved controls before a recipe ever runs against the new
   build.

## Keeping rea working (the local patch must survive reinstalls)

- Saved patch: `../rea-native-ui-clion.patch`. It adds a launch-time fallback, same-size window
  disambiguation, and Swing labels from AXDescription.
- `rea-patch.sh` reapplies it idempotently and fails loudly if the upstream file changed. Run it
  after any `npm i -g rea-agents`.
- Upstream (needs the owner's go-ahead; it's outward-facing): a PR to morluto/rea with those three
  fixes, plus:
  - a `select` step kind (AXSelected=true);
  - popup windows allowed (layer ≠ 0) when the caller names one explicitly.

  Once merged, jbax shrinks to nothing for these cases.

## Next steps (in order)

1. `rea-patch.sh` (done with this plan) and a check in `jbctl` that refuses to run on an unpatched
   rea.
2. **jbax**: one Swift CLI replacing the scattered probes (selpoke, set-direct-bg, popupitems,
   axpressbtn, comboattrs, focusowner). Subcommands: `select --window --label --row-text`,
   `popup list|press`, `focus-owner`, `labels`. JSON in and out, the same contract as rea scenarios.
3. **Recipe runner** in jbctl: JSON recipes, role+label resolution, guards, verifiers, exit codes.
   Port `router-direct` to a recipe first.
4. **Map generator**: `jbctl map <window>` writes the rea map under `maps/<build>/`. `jbctl map-diff`
   compares two builds.
5. More recipes, as needs come up (each one authored once by an agent, then run with zero tokens):
   toggle a plugin, set an option checkbox, change the keymap scheme, MCP server enable/port.
6. Other JetBrains IDEs: the same backends apply (all JBR + Swing). Only product names, bundle ids
   and config dirs differ; make those config.
7. Optional, owner's call: IntelliJ UI Inspector (internal mode, needs a restart) to read Java
   class names when a widget's AX surface is not enough.
