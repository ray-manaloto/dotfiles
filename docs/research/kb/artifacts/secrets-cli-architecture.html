Target architecture · companion to the proposals brief

One entrypoint, four layers, five seams

The ideal setup for keeping mise, fnox, Doppler and the macOS keychain in sync — and the CRUD workflows the CLI owns. Not a description of what runs today.

First, a correction that changes the shape

Doppler cannot sync to the macOS keychain. Its 20+ syncs are cloud targets — AWS Secrets Manager, GCP Secret Manager, Vercel, Netlify, Heroku, Kubernetes, GitHub Actions, Docker, Render, Fly.io, Cloudflare. The keychain is a local resource and is not among them; the CLI's help never mentions it. Control arm: secrets → 3 hits, same grep

That is the more useful answer, because it forces the real question: what is the keychain for? And the answer is that its job should be much smaller than a sync target — it holds the one credential that cannot come from the cloud, because you need it to reach the cloud. Exactly one secret, never synced, never mirrored. Today's setup already does this by accident: the keychain holds DOPPLER_TOKEN and nothing else.

Components

The four layers, and where the CLI sits

Each layer does one thing that no other layer should. The CLI is not a fifth layer — it is the entrypoint that drives the others, which is why it spans them rather than sitting on top.

Root of trust macOS keychain Exactly one secret: the Doppler service token. Never synced, never mirrored, never in a file. On a new Mac this is the only thing a human types, and everything else follows from it.
│ authenticates
Source of truth Doppler cloud All 50 values. The only durable copy — this is what survives the Mac being lost. Free tier. Swappable for Infisical via one fnox provider line, since fnox speaks both.
│ resolves
Resolution fnox Multi-backend read + declaration. 23 providers, so the store underneath is a config choice rather than an architecture. Owns which secrets exist and where each one lives.
│ exports to
Injection mise Per-project environment, scoped by directory. Native sops/age decryption, native redaction. Every consuming project is a mise project, so this layer is free and already installed.
│ consumed by
Consumers shell · devcontainer · agents Get whatever their project scopes. Not 50 by default — a subset, because the scope is the project's mise config rather than the login shell.
└─ driven end-to-end by ─┐
Entrypoint the CLI / SDK Owns origination and reconciliation — the two jobs no layer above provides. Adds and rotates secrets, keeps the layers agreeing, bootstraps a new machine, and is what the Claude Code plugin wraps.
Where things drift

Five seams — and nothing owns them today

"Keeping them in sync" is not one problem. It is five, each with its own failure and its own detection. This table is the actual specification for the CLI's reconcile command.

Seam What drifts How it shows up Owner
Doppler ↔ fnox A secret exists in Doppler but is not declared in fnox, or a declaration points at a value that was deleted. The first is invisible — you never learn the secret exists. The second fails at resolve time, or worse, resolves empty. Nobody
fnox ↔ doctor.toml The reviewed 50-name baseline stops matching the live declaration set. Caught today by the SessionStart doctor — the one seam that already has a tripwire. doctor
Host ↔ devcontainer Two independent resolution paths: fnox on the host, a `doppler download` env file in the container. Silent. Nothing compares the two name sets, so a host-only secret simply is not there in the container. Nobody
Keychain ↔ Doppler The service token is revoked, expired, or was never minted on this machine. Everything below it fails at once. Recovery needs a human and a browser — by design, since it is the root of trust. Manual
Project ↔ what it needs A project's mise scope omits a secret its code reads, or carries ones it does not. The first is a runtime failure. The second is silent over-exposure — the thing scoping was supposed to prevent. Nobody
The finding in that table

Three of five seams have no owner, and the two silent ones — host/devcontainer and project/needs — are exactly the failures you cannot notice by working normally. That is the CLI's real justification, and it is a much better one than the fail-open clause it replaces: reconciliation is work no existing tool does, because no existing tool can see across all four layers at once.

Workflows

CRUD, end to end

Each verb is a sequence between components — the CLI drives, the other four do the work. Order matters in every one of these, and the arrows are where the design decisions actually live.

Create

secrets add STRIPE_API_KEY --project payments
youCLIkeychainDopplerfnoxmiseproject
1
prompt on a TTY — never argv, never stdout
2
read DOPPLER_TOKEN
3
write the value — cloud becomes truth first
4
declare name + provider
5
add to the named project's [env] scope
6
doctor.toml diff — a human reviews the widened set
7
verify by resolving back — presence, not value

Cloud first, declaration second, scope third. If step 4 fails you have an orphaned value you can still find; if the order were reversed you would have a declaration pointing at nothing.

Read

secrets ls · secrets status
youCLIkeychainDopplerfnoxmiseproject
1
list declared names + provenance
2
names only — no verb in this CLI prints a value
3
status answers “is it resolvable”, via exit code
4
values reach a process ONLY here, by injection

Step 4 is the constraint drawn as a diagram: there is no path from a secret to your terminal. The CLI can tell you a secret exists and resolves; only mise or fnox exec can put its value anywhere.

Rotate

secrets rotate STRIPE_API_KEY
youCLIkeychainDopplerfnoxmiseproject
1
prompt for the new value
2
overwrite — the new value is truth immediately
3
invalidate the resolution cache
4
clear the encrypted env cache
5
re-resolve and confirm, by presence
6
report every project that scopes it

Step 4 exists because the mise env cache is encrypted — you cannot grep it to see whether a stale value is still being served, so it must be cleared rather than inspected. Step 6 gives you the blast radius before you revoke the old credential upstream.

Delete

secrets rm STRIPE_API_KEY
youCLIkeychainDopplerfnoxmiseproject
1
which projects still scope this?
2
refuse if any — unless --force
3
remove from every project scope
4
remove the declaration
5
delete from the cloud LAST
6
doctor.toml diff — the narrowed set

Delete runs in the exact reverse of create, and for the same reason. The cloud value goes last so that a failure anywhere in steps 3-4 leaves the secret recoverable rather than orphaned — you can always re-declare something that still exists.

Reconcile — the verb the design hangs on

secrets reconcile [--fix]
youCLIkeychainDopplerfnoxmiseproject
1
list every name in the cloud
2
list every declaration
3
list every project scope
4
scan code for the names it actually references
5
diff all four against doctor.toml — report by name
6
exit nonzero on drift, so it can gate a commit

This is the only verb that touches all four layers, which is exactly why nothing else can do its job. Steps 3 and 4 together close the seam nothing owns today: a project scoping a secret its code never reads is silent over-exposure, and a project reading one it does not scope is a runtime failure nobody predicted.

Bootstrap a replacement Mac

secrets bootstrap
youCLIkeychainDopplerfnoxmiseproject
1
browser login, mint a service token
2
paste it once, on a TTY
3
store it — the only root-of-trust write there is
4
verify the token authenticates
5
fnox resolves all 50
6
mise injects per project
7
run reconcile to prove the machine matches the declared world

Step 1 is the only manual step in the whole system, and it should stay manual — it is the one action that cannot be automated without storing a credential that would itself need protecting. Everything from step 5 down is automatic because the layers below only ever needed the token.

Known costs

What this design owes you

Writes are provider-specific. fnox's Infisical provider is read-through-fnox; writes go via infisical secrets set. So the create/rotate/delete paths need a small per-provider adapter — that is the one place the CLI cannot be a pure driver.

mise's sops and age paths are experimental. mise's own docs say behaviour may change. Depending on them for encryption is a real bet, and worth taking only because the fallback — fnox resolving from the cloud — stays available.

Shell-wide availability goes away. Scoping by project is the point, but it means the current "all 50 in every terminal" behaviour ends. That was a deliberate decision on 2026-08-02, so reversing it here should be deliberate too, not a side effect.
