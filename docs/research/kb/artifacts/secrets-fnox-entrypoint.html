Design variant · fnox as the sole integration point

One entrypoint, and the three places it leaks

The CLI talks only to fnox; fnox talks to everything else. It mostly works — and the exceptions are specific, findable, and decide the backend for you.

The verdict up front

The design is sound and fnox was built for it — there is a real published library crate, fnox-core 1.32.0, described in its own source as the reusable engine and convenience API for downstream consumers. Writes work through 17 of 23 providers.

But the invariant "the CLI only ever talks to fnox" breaks in exactly three places, and one of them is a silent plaintext write. Each is drawn below rather than described, because each one is an arrow that should not exist.

Where the invariant breaks

Three leaks, all specific

Writing to a read-only provider Five providers never implement capabilities() and so default to read-only: 1password, bitwarden personal, doppler, infisical, proton-pass (plus azure-ac, read-only by declaration). fnox set FOO bar --provider infisical does not error — it falls through and writes the cleartext value into fnox.toml.source-read at set.rs:180-183 → :236-243 · not executed Fatal to the design Doppler and Infisical are both in this set.

Declaring a scope on disk --no-defaults is the scoping mechanism and it is CLI/env only — all 11 source lines across the settings are sources.cli/sources.env, zero sources.config.source-verified · control-armed Permanent Scoping lives in your wrapper's flags. Anyone calling fnox directly gets all 50.
What leak 1 does to the backend choice

A fnox-only entrypoint cannot use Doppler or Infisical. Reaching one integration point means moving to a RemoteStorage-class backend — Bitwarden Secrets Manager, Vault, AWS/GCP/Azure Secrets Manager, keepass, or password-store. Bitwarden SM is the only one of those that is both free-tier and cloud-hosted, which makes the single-entrypoint design and the Bitwarden decision the same decision.

Step 4 is mandatory because fnox's daemon cache invalidates on fnox-side inputs only — config, profile, provider refs, FNOX_* vars. A rotation at the remote matches none of them, so a running daemon keeps serving the credential you just rotated away until the idle timeout, which upstream's own example sets to 8h. Step 5 works because fnox check deliberately bypasses the cache, making it the only correct post-rotation probe. Step 6 is filtered because a bare fnox sync re-encrypts every entry — age is non-deterministic.

Measured on 1.32.0 against a fixture that declares a real profile, so the control is armed: -P real returned 52 names including the canary, -P nope returned 51 with only the top-level canary, both rc=0. Neither --if-missing error nor fnox check -P nope catches it — they address a different failure. fnox profiles is the only thing that can, which makes step 1 the single clearest justification for the CLI existing at all.

The build decision this forces

Rust against the crate, or Python against tables

Rust. fnox-core is published, real, and explicitly aimed at downstream consumers — discover(), open(), with_profile(s), with_no_defaults(), get(), list(). Typed results, no parsing, no version-skew in output formatting. The cost is a Rust toolchain in a repo whose tooling is Python, and a language most of the surrounding code is not written in.

Python. Shell out and regex over human-formatted tables that truncate by default, with no --json on any command you need to read. There are no Python bindings — pyo3 → 0 hits, control clap → 45. This works, and it breaks quietly the first time an output format shifts.

Two more things the CLI must own

Serialising writes. All four config-write sites are bare truncating fs::write in a read-modify-write — no temp-and-rename, no locking. Concurrent fnox set loses updates.

Never letting a value reach a terminal. fnox list -V and fnox export both print values, and fnox has no mise-style --redacted — redaction exists only in fnox mcp, the proxy, ci-redact and scan. The wrapper is the only thing standing between those flags and your transcript.
