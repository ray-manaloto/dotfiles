## Respec round 2 (cold review, 13 findings)

Team lead ran two review lanes on `cee3a1e` and relayed 13 confirmed
findings (their own refutation already applied). All 13 addressed in

- **B1** (`eager_reason` could be `""`): normalized `section or None` at

  (heading-with-no-body-before-next-heading, heading-at-EOF).
- **B2** (`UnicodeDecodeError` crashed the build): added a dedicated
  `except UnicodeDecodeError` branch (it's a `ValueError`, not caught by
  the existing `except OSError`), returning a `malformed` record whose
  `body_bytes` is the real on-disk size (bytes WERE read; only decoding
  failed). Test with a real invalid-UTF-8 byte sequence plus a healthy
  sibling file to prove the crash doesn't take down the whole build.
- **C1** (BOM hides a scoped rule): switched `path.read_text(encoding=...)`
  to `"utf-8-sig"`. Documented as a deliberate, more-correct divergence
  from `scoped_rules_on_disk` (which stays BOM-blind) in both the module
  docstring and the C2 agreement test's docstring, so the divergence
  doesn't read as a C1 violation. Test constructs a real BOM'd file.
- **C2** (`paths: []` indistinguishable from a healthy scoped rule): kept
  `load_class == "scoped"` (predicate parity with `scoped_rules_on_disk`
  and C1/C4 — did not introduce a 4th load_class or reclassify to
  malformed, which would have broken that parity). Documented + tested
  that `load_class == "scoped" and not globs` is already the exact,
  unambiguous signal for this footgun. This is my judgment call vs. the
  finding's literal "malformed" suggestion — flagged for team-lead below.
- **C3** (`paths: null` is an undocumented 4th divergent shape): added to

- **C5** (`body_bytes` undercounts CRLF): switched from
  `len(text.encode())` to `path.stat().st_size` (real on-disk bytes,

- **T1** (setext test is a tautology): replaced
  `test_setext_frontmatter_boundary_is_not_a_phantom_heading` with

  the REAL hazard (a `#`-prefixed YAML comment inside frontmatter being
  misread as an ATX heading if scanned unstripped) rather than a setext
  risk that doesn't exist (the parser is ATX-only, confirmed no setext
  detection anywhere in the module). Corrected the module's docstrings
  (`_ATX_HEADING_RE`, `_strip_frontmatter`) to state the real reason.
  **Re-verified the mutation-proof myself**: replacing `_strip_frontmatter`

  mutation run), where the old test would not have.

## Round 2 addendum (A1-A4), commit `3a13c2c`

Team-lead sent four more findings that reached them after their first
round-2 batch, all pre-probed by them with control arms. Addressed all
four, each re-proven independently with my own mutation + control-arm run
before committing:

- **A1** (missing/non-directory `rules_dir` silently returns an empty
  registry): `build_registry` now raises `NotADirectoryError` with a
  message naming the path. Documented as a deliberate divergence from
  `scoped_rules_on_disk`'s silence — a caller passing the wrong path is a
  caller bug, not absent data. Three new tests: missing path, a file
  passed as a directory, and the positive control arm (a real, even

  Added `test_why_this_rule_exists_heading_qualifies_when_it_also_says_eager`
  proving a heading asserting both content-reason AND eagerness correctly
  qualifies (no exclusion added — the operator's C5 ruling against a
  prose/blockquote detector stays intact; this is purely a comment fix
  plus a proof the behavior was already right).
- **A3** (`_ATX_HEADING_RE` anchors `^#`, but CommonMark permits up to 3

  gutted `_find_eager_reason` to always return `(None, None)` → the
  merged test failed on the positive (qualifying-set) assertion, where
  the negative arm alone would have passed trivially.
