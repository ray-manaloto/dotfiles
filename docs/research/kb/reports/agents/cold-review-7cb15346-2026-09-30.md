## Focus-area answers (the brief's five questions)

1. **Every error, empty and timeout branch of the docker query.** All of them are handled and discriminated. `TimeoutExpired` → raise; `OSError` → raise; rc≠0 → raise with stderr, else stdout, else `exit N`; a malformed line → raise; rc=0 with no lines → `[]` (a real absent); blank lines are skipped. Live arms were a bogus `DOCKER_HOST`, a bogus `DOCKER_CONTEXT`, and no docker on PATH, each giving UNVERIFIABLE; the real-docker control gave `[]`. Mutations M1, M2, M3, M16 and M13 all went red.
2. **Can docker down or unanswering read as healthy?** Not through the docker query (above). The silent-healthy routes that remain are: the linked-worktree skip (#3); an empty-string arch entry aliasing to the default (#6); and, as a test gap only, a narrowed state predicate (#7). M4 (UNVERIFIABLE → `[]`) went red, so the main "down reads healthy" regression is pinned.
3. **The default-arch restore command under the three platform resolutions.**
   - *override:* not used by this call. `resolve_platform(None, …)` is called with `None`.
   - *env pin* (the wired SessionStart path): correct in this clone. It depends on the gitignored profile for the non-default arch (#1).
   - *host native:* wrong, because arm64 is named as the bare-`mise run up` arch (#2).
   - Tests cover only the env-pin branch (three pinned strings). M15 proves the env is read (red on this arm64 host), but nothing pins the unpinned behaviour.
4. **The worktree skip.** Detection is correct: the real-git test and live arms return True for 3 real worktrees and False for main; M9 and M17 went red. The skip itself trades coverage for avoiding a false "missing" when a one-line alternative exists (#3).
5. **Tests passing for the wrong reason.**
   - Survivors: M5 (#7), M11 (#8), M14 (#5, a design choice), M19 (the hermetic `env` argument is unpinned, and harmless here because the port and user never reach the label query), M20 (`--path-format=absolute` is unpinned, and harmless), and M21 (`rows[0]` vs `rows[-1]`, cosmetic).
   - The incident test's docstring attributes the name mismatch to the port suffix. Under `names.container` it would actually fail on basename, user AND port, so it discriminates, just for a broader reason than stated.
   - No test spawns real docker. Every `run_checks`/`doctor_main` test replaces `CHECKS`.
