## (a) Item 8 / cold-review F2 — architect is RIGHT; refutation fails

`$.process.run` is unambiguously a "`$` call". The carve-out at `:4173-4175` is the **type-level** doc on `HookBudget`, governing all three members, and names exactly one exception: "a `$.clock` wait excepted". `$.process.run` is `run: (argv, init?) => Promise<…>` on `$.process` (`:2947`) — a `$` call whose wait stops the clock. Corroborating: the same sentence's own example is a "minute-long `$.model.complete`", i.e. an out-of-process wait far exceeding 10 s. So F2 is refuted; do not add a `.catch`, do not shorten `timeoutMs`.

Two supporting facts worth putting in the comment: `$.process.run`'s **default timeout is 30 s, cap ten minutes** (`:2941-2942`) — so `timeoutMs: 90_000` is a deliberate widening within the cap, not a default; and `$.clock.now()` is "Resolves milliseconds since the epoch, now" (`:2864-2870`), **not** a wait, so `register.ts:318-320`'s comment is accurate as written.

## (b) The §1 rule — no total brick, but the escape hatch can be a no-op

Even "uv is broken so every refresh is null" leaves the Bash repair lane open.

## A3 settled — and **item 5 is a harness artifact, not a production defect**

From the types, `$.fs.stat` **without** `resolve` does **not** reject on a dangling symlink, and `isLink` describes the path itself:

- `FsStat.kind` `:4073-4075` — "of what the path leads to: a link is followed, and **one that leads nowhere is `other`**" ⇒ a dangling link has a valid `kind`, so the call succeeds.
- `FsStat.isLink` `:4086-4088` — "True when the path itself is a symbolic link; `kind`, `size` and `mtimeMs` then describe what it points at, **or the link when that is gone**" ⇒ explicitly contemplates a dead target and still returns a stat.
- `FsStat.realPath` `:4091-4094` — with `resolve:true`, "**Absent too when the path leads nowhere**" ⇒ succeeds, `realPath === undefined`.
- `$.fs.stat` docstring `:2749-2750` — "Rejects when missing." The **link** is not missing.

Therefore under the real API a dangling root `doctor.toml` symlink takes `placed()`'s `:162` stat **successfully**, hits `own.realPath === undefined` at `:164-165`, returns `undefined`, and `isDoctorTomlRepair` returns false — **already refused**. The parent-placement arm at `:169-175` is unreachable for it.

It is reachable only under the harness's fake, `tests/fixtures/claude_doctor_hook/harness.ts:83-91`:

```ts
const [linkInfo, targetInfo] = await Promise.all([lstat(absolute), stat(absolute)]);
```

`stat()` on a dangling link rejects ENOENT, `Promise.all` rejects, `placed`'s `.catch` swallows it, and the fake drives execution into the `isLink: false` branch. The fake also returns `kind: "directory"|"file"` where the real type is `'file'|'dir'|'other'` — it has no `other`, which is precisely the value the real API uses for "leads nowhere".

So the respec's "confirmed at register.ts:162-175" names the right lines but the wrong cause: the branch's *reachability* is a property of the fake. **The required work is to make the fake faithful first** (`lstat` + `stat().catch(() => undefined)`, `kind: 'other'`, `realPath: undefined`, never reject on a live link), then re-check whether any production change is still owed. Writing the fix against the current fake, and "proving" it with an arm that runs on the same fake, would certify the fake — the round-2 lesson recurring. Also note `kind` must be `'dir'` not `"directory"` for the fake to model the type at all.
