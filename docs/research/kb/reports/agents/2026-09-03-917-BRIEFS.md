Not a second opinion — omissions. Read every error/None/empty/missing-key/

what signal does anyone get?

correct, but **the difference between "nothing to record" and "silently broken

conditions — that direction matters more than false negatives, because a false
positive sends someone deleting a working rule.

## The collision — recorded because it nearly cost work

`impl-917` sent a premature "standing by" with no report. I probed the tree
(correct), found HEAD unchanged (accurate at that moment), concluded the lane
had failed (wrong — it was still working), and dispatched `impl-917-r3` onto a
checkout that still had a live writer. I stopped it as soon as the first lane's
commit arrived. Nothing was lost: one commit, clean tree, no surviving writers.

Two lessons. A clean probe at time T does not license dispatching a second
writer — the first lane must be *settled*, and I had run that exact check one
message earlier without acting on what it implied. And verification performed
during a collision window is void, so everything was re-run afterward.
