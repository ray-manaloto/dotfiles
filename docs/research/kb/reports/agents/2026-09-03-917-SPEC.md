# Spec — #917: InstructionsLoaded load observer + never-fired report

## 1. Objective

`.claude/rules/*.md` are moving from eager to scoped (#916). Nothing in that plan
observes whether the move worked. A rule scoped with a glob that matches nothing
silently never loads, and on disk that is indistinguishable from a rule loading
fine — the static gate can only see whether a glob matches a FILE, never whether
the rule FIRED in a real session.

Build the observation channel: every instruction-file load in a real session
lands as one JSONL record, and a report command turns those records into three
answers — what loaded eagerly, which scoped rules fired, and **which scoped rules
never fired**. The third is the failure the static gate structurally cannot see.

This must capture a BASELINE before the #916 corpus migration begins. A
measurement that starts after the change cannot show the change.

The failure it prevents: #916 lands, the eager corpus appears to shrink, and one
or more rules are silently dead in every session — with nothing in the repo able
to tell that apart from success.

## 4. Constraints and invariants

**C1 — the hot path must stay cheap, and this is the load-bearing one.**
This hook fires once per instruction file, at session start AND inside every
subagent. Measured on this machine this session: `uv run --project python
python -c "import json,sys,os,pathlib"` = **0.04s**; the same interpreter
importing `dotfiles_setup.main` = **0.23-0.27s**; and bare `import
dotfiles_setup` = **0.04s** (its `__init__.py` imports only `pathlib`), so the
`-m` form genuinely pays no package-init tax. The eligible fanout is **37 files,
not 64**: `InstructionsLoaded` fires only on `CLAUDE.md` and `.claude/rules/*.md`
(hooks.md:56, :1263) — 11 tracked CLAUDE.md/AGENTS.md plus 26 rules — whereas
md-budget's 64 counts SKILL.md files the event never fires on. That is ~1.5s vs
~8.5s of CPU per session start, still a ~6x difference, before subagents
multiply it. So the hook invokes the MODULE directly
(`python -m dotfiles_setup.instructions_observer`), never the `dotfiles-setup`
console script, and `instructions_observer.py` imports stdlib only —
importing anything from `dotfiles_setup` at its module scope silently
reintroduces the 0.27s. Add a test that asserts the module's transitive imports
stay stdlib-only, so this cannot regress unnoticed. The report side has no such
constraint and goes through the normal CLI.

**C1b — derive `project_root` from `$CLAUDE_PROJECT_DIR`, never from cwd.**
This is the #343 defect class and the spec's most serious gap. Hooks run in the
SESSION'S current directory, not the project root
(`python/src/dotfiles_setup/hook_selfcheck.py:105-111`), so a relative
`.agent/instructions-loaded/` resolves against a sibling repo the moment the
session works in one. Records would silently land elsewhere, and the never-fired
report would then call rules dead that fired fine — a false positive in the one
direction that makes the observer worse than nothing. The payload's `cwd` is NOT
the project root either (bundle source: `cwd: Mt()` in the payload builder,
`docs/research/kb/reports/agents/wf-dag-context-gate.md:115-127`). Read
`os.environ.get("CLAUDE_PROJECT_DIR")`; when it is unset or not a directory, fall
back to the module's own repo root resolved from `__file__`, never to `Path.cwd()`.
Test the observer from a foreign cwd and assert the record still lands in this
repo's `.agent/`.

**C1c — the module needs a `__main__` guard, and its absence is a trap.**
`if __name__ == "__main__": raise SystemExit(observe_main())`. Without it the
module runs as `__main__`, does nothing, and exits 0 — which PASSES C2's
malformed-stdin control arm for entirely the wrong reason (no file written, rc=0
— exactly the expected result). Only the section 5 POSITIVE arm discriminates,
which is why that arm is mandatory, not optional
(`.claude/rules/probes-need-a-control-arm.md` rule 2).

**C2 — fail open, always.** Any exception, malformed stdin, unwritable
directory, or missing field returns exit 0 and writes nothing. The vendor
ignores the exit code and the event has no decision control, so a crash cannot
block loading — but it must not produce noise either. Never write to stdout or
stderr on the hot path. Do not swallow the failure silently forever, though:
on an unexpected exception append one line to a sibling
`.agent/instructions-loaded/errors.log` (best-effort, itself wrapped).

**C3 — `session_id` reaches a filename, so sanitize it.** It arrives from the
harness payload and is interpolated into `.agent/instructions-loaded/<id>.jsonl`.
An id containing `/`, `..`, a NUL, or an absolute prefix must not escape that
directory. Reduce to a conservative charset (`[A-Za-z0-9_-]`), cap the length,
and fall back to a fixed name (e.g. `unknown`) when nothing survives. Resolve
the final path and assert it is still inside the target directory before
opening it. Test the traversal attempts directly. Cover the ABSENT cases too,
which C3 originally missed: a missing key, `None`, and a non-string value all
take the same fixed `unknown` fallback, and each gets its own test.

**C4 — concurrent appends must be ONE syscall.** Parallel subagents write the
same session file at once, and O_APPEND atomicity is per-`write(2)`, not per
Python `write()`. A buffered text handle can flush a long record across several
syscalls, letting two writers interleave into a corrupt JSONL line. Measured
here: `io.DEFAULT_BUFFER_SIZE` is **131072** on this machine (not the 8192 often
assumed), and a realistic record is ~1-3KB — the three path fields are bounded by
PATH_MAX and the longest `paths:` frontmatter block in the corpus is 117 bytes
(`md-size-budgets.md`) — so records do not split in practice today. Do not rely
on that margin: encode once and issue a single unbuffered `os.write(fd, blob)`
on a descriptor opened `O_WRONLY|O_CREAT|O_APPEND`, and enforce an explicit max
line length with a test at the boundary. Do not add a lock file — that
reintroduces cost and a failure mode on the hot path.

**C5 — paths and reasons only. No file content, no credentials.** The record
carries the fields listed in section 3 and nothing else. Do not read the
instruction file. Do not capture environment. `cwd` and `transcript_path` from
the payload are NOT recorded (`transcript_path` leaks a user-home path for no
analytical gain). Store `file_path`, `trigger_file_path` and `parent_file_path`
repo-relative when they are under `project_root`, absolute otherwise.

**C6 — the never-fired report must be control-armed** (acceptance criterion 5,
and `.claude/rules/probes-need-a-control-arm.md`). Its test constructs a fixture
with BOTH arms: a scoped rule whose glob is deliberately dead must appear in
`never_fired`, and a scoped rule that did fire must NOT. Build the dead-glob
fixture as a rule that COULD have fired (a plausible glob matching no file) —
rule 8 of that file: a fixture no configuration could ever trigger proves
nothing. Do not mutate the real `.claude/rules/` tree in a test.

**C7 — `hook_selfcheck` must fail if the registration is deleted.** Add an
`InstructionsLoaded` entry to `_SETTINGS_WIRING`
(`python/src/dotfiles_setup/hook_selfcheck.py:85`) with the command substring
that binds the real invocation, and `None` for matchers — a matcher would scope
it to particular load reasons and lose the baseline. Note
`_unanchored_hooks` (same file, L196) already requires every hook command to
contain `CLAUDE_PROJECT_DIR`; the command above satisfies it. Prove the check
fails by deleting the wiring line, not by renaming a symbol — see the token note
in C8.

**C8 — the contract must bind CALL SITES, not definitions.** Model the
`suites.toml` entry on `workflow.bash-logic-enforcement`
(`python/verification/suites.toml`). That file's own `workflow.apt-pins-enforcement`
description records the trap: a contract that asserted only `def` names stayed
GREEN when the whole wiring line was deleted, because the token survived in a
comment. Bind the settings.json command string, the `_SETTINGS_WIRING` entry,
the mise task, and the main.py dispatch entry. Run
`mise run token-check -- <file> "<token>"` while choosing tokens — a token
matching more than once can be satisfied by a stand-in.

**C9 — project conventions.** Zero inline lint suppressions (no `noqa`,
`type: ignore`, `nosec`) — `no_lint_skip` rejects them. Zero bash logic: the
hook is a registration line, all logic is python. `uv run --project python`,
never `--directory`. Do not add a `.sh` file (the `bash_logic_budget` allowlist
would reject it). Do not touch `.claude/rules/*.md` content — this ticket
observes the corpus, it does not migrate it.

**C10 — do not modify** `AGENTS.md` or the root `CLAUDE.md` (byte-locked to
`@AGENTS.md`), and do not add frontmatter keys to any rule file. #916
deliberately deferred that question and THIS observer is the probe that will
settle it later.
