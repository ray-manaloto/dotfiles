### F1 — MEDIUM. The newly-mandated gate runs against a stale render

`pr.py:103-104` adds `home/dot_gitconfig.tmpl` to `SURFACE_PATTERNS` with the
comment *"on-create renders this file and the smoke preflight depends on it."*
Both halves of that comment are **true and verified**:

- `.devcontainer/devcontainer.json:236` → `onCreateCommand` → `bash
  .devcontainer/scripts/on-create.sh`, whose line 41 is
  `chezmoi init --apply --source="${WORKSPACE_FOLDER}" --no-tty --force`.
- `scripts/devcontainer-smoke.sh:20-24` is the preflight that reads the result.

The problem is the **gate chain that entry activates**:

1. `pr.py:367-368` — `touches_surface(paths) and not changes_base_image_inputs(paths)`
   appends `Gate("sync-full", ("mise", "run", "sync", "--", "--full"))`.
2. `python/src/dotfiles_setup/sync.py:791-798` — `--full` runs `mise run verify-local`.
3. `mise.toml:1133-1137` — `verify-local` runs `verify-image` → **`mise run up`** →
   `ps` → `verify-arch` → **`mise run smoke`**.
4. `mise.toml:384-386` — `[tasks.up]`'s `devcontainer up` passes only the two
   `--id-label`s. It does **not** pass `--remove-existing-container`. The only
   task that does is `dev-rebuild` (`mise.toml:424-427`).

`.devcontainer/devcontainer.json:48-51` states the consequence in-file:
*"`mise run up` reuses an existing container **WITHOUT re-running
postCreateCommand**"*. `onCreateCommand` is likewise create-only, and the
rendered `~/.gitconfig` lives on the **persisted named home volume**
(`devcontainer.json:129`, `target=/home/${localEnv:USER},type=volume`).

Net effect: on any pre-existing container — the normal case for a `ship` — the
mandated gate runs the smoke preflight against the **old** `~/.gitconfig` from
the home volume. A regression introduced by the very edit that triggered the
gate (a wrong `.chezmoi.*` expression, a deleted `[safe]` stanza, a typo in the
key) passes. `sync`'s rebuild decision (`sync.py:691-693`, `_decide`) keys on
image/base currency, not on which paths changed, so it will not select
`dev-rebuild` for this path either.

The gate is not worthless — it still proves the *current* container is
trusted — but it does not gate what the comment implies it gates. A correct
classification would route this path to a recreate (`dev-rebuild`) or add a
smoke assertion that `~/.gitconfig`'s `safe.directory` matches the workspace as
rendered from the **branch's** template.

### F2 — LOW. CI cannot compensate

`.github/workflows/ci.yml:291-299` `changes.filters.build` lists
`.devcontainer/**`, `docker-bake.hcl`, `hk-common.pkl`, `hk-image.pkl`,
`python/**`, `.dive-ci`, `.github/workflows/ci.yml`,
`.config/mise/conf.d/shared.toml` — no `home/**`.

That omission is *defensible in isolation*: `home/` is never a COPY input
(every `COPY` line in `.devcontainer/Dockerfile` was enumerated — 127, 133,
139, 392, 393, 543, 622, 666, 669 — none names `home/`), and
`scripts/devcontainer-smoke.sh` has no workflow caller, so CI's no-mount smoke
runs the python-generated tier cores instead. The image genuinely does not
depend on this file.

The finding is the **combination with F1**: because CI structurally cannot
exercise it and the local chain does not re-render it, there is currently **no
automated gate that exercises a `home/dot_gitconfig.tmpl` change end to end**.
The three unit tests in `tests/test_safe_directory.py` are the whole gate.

### F3 — LOW. An assertion that can only pass

```python
source_dir = source / "home"
assert safe_directories == [str(source)]      # line 90
assert str(source_dir) not in safe_directories  # line 91
```

Line 90 pins the list to exactly one element equal to `str(source)`.
`str(source_dir)` is `f"{source}/home"`, which is never equal to `str(source)`,
so line 91 is entailed by line 90 and can never fail independently.

Mutation evidence: under
`.chezmoi.workingTree` → `.chezmoi.sourceDir` the failure is reported at
**line 90**, not 91. Line 91 reads as a guard against the round-1 fixture
collapse but contributes no discrimination; the `.chezmoiroot` file in
`_committed_workspace` is what actually supplies the teeth.

### F4 — LOW. Ambient global gitconfig leaks into the fixture

`_committed_workspace` (`tests/test_safe_directory.py:16-44`) builds the repo
with bare `git` calls that inherit `os.environ`. Only `user.name`/`user.email`
are pinned via `-c`; nothing isolates the global config. Two measured arms in
the scratch tree (both with `GIT_CONFIG_GLOBAL` pointed at a synthetic
developer config):

| Ambient global config | Result |
|---|---|
| `commit.gpgsign=true`, `gpg.format=ssh`, `user.signingkey=/nonexistent/key.pub` | **3 failed** — `CalledProcessError … 'commit' … exit status 128` raised at `tests/test_safe_directory.py:28` |
| `core.hooksPath=<dir with a pre-commit that exits 1>` | **3 failed** |
| `[safe] directory = *` (control arm) | **3 passed** — `_smoke_env`'s `GIT_CONFIG_GLOBAL` override is effective, so the leak is confined to the fixture-building commands |

Direction is loud (a failure, never a silent pass), and it is a **pre-existing
repo-wide pattern**: no test file isolates global config for fixture commits
(`tests/test_branch_guard.py`, `test_session_state.py`, `test_image_smoke.py`,
`test_session_review.py`, `test_process_env.py`, `test_workflow_hooks.py`,
`test_workflows_js.py` all commit the same way). What this diff changed is the
blast radius inside this file: the parent had the commit in **one** test, the
helper now puts it in **all three**, and the repo's local gate is
`pytest tests/ -x -q`, which aborts the suite at the first failure.

One-line fix: add `-c commit.gpgsign=false -c core.hooksPath=` to the commit,
or point fixture git calls at a scratch `GIT_CONFIG_GLOBAL`.

Related: **test 1 does not need the commit at all.** Probed directly —
`chezmoi --source=<init-only repo with .chezmoiroot> execute-template` resolves
`.chezmoi.workingTree` to the repo root with **no commit present** (rc=0). Only
the preflight's `git rev-parse HEAD` needs one.

### F5 — LOW. The non-repo branch lost its only test

The parent's `test_smoke_fails_before_tier_one_when_git_cannot_open_workspace`
used a bare `mkdir`'d, non-git workspace. It was replaced by
`test_smoke_refuses_dubious_ownership_before_tier_one`, which is a **better**

`scripts/devcontainer-smoke.sh:21-24` still collapses three distinct rc=128
causes — not a git repo, a repo with no commits yet, and dubious ownership —
into one message that names only `safe.directory`. Two of those three are now
misdiagnosed *and* untested.

### F6 — LOW. The arming variable is undocumented API

`tests/test_safe_directory.py:63` sets `GIT_TEST_ASSUME_DIFFERENT_OWNER=1`.
This is git's own test-suite hook; it is **UNVERIFIED** that git documents it
outside `t/README` or promises compatibility for it.

The failure direction was measured, and it is safe: removing that key from
`_smoke_env` in the scratch tree makes
`test_smoke_refuses_dubious_ownership_before_tier_one` fail with
`AssertionError: assert 2 == 1` — the preflight passes, the real `uv` runs in
the fixture directory and exits 2. So the test **cannot silently pass
unarmed**. Worth one inline comment naming the dependency so a future reader
does not "clean up" a variable whose absence is the whole point.

Platform check, no finding: the variable short-circuits git's ownership check
before the owner comparison, so it is platform-independent, and the suite runs
non-root everywhere (GitHub runner user, devcontainer uid 1000), so git's
root-ownership special case is unreachable here.

### F7 — LOW. The fixture is a superset of the attributed shape

`docs/rules-evidence/persistence-gate-retry.md:63-70` attributes the real
failure to virtiofs reporting the `/workspaces/dotfiles` **mount root** as
`0:0` while `.git` and the tracked files were `1000:1000`.
`GIT_TEST_ASSUME_DIFFERENT_OWNER=1` forces *every* ownership check to fail,
which is a superset — adequate to prove the stanza clears the check, but it
does not pin the split shape. A future change that made the stanza cover only
the gitdir, or only `.git`, would still pass these tests.
