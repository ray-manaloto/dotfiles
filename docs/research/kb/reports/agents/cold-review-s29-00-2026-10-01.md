## Verdict

**SHIP-WITH-FIXES.**

Both mechanisms are correct and measured. The `image python` rule moves exactly one update: python, and nothing else
(arms A, B and D). The companion image locks still regenerate for it (`refresh.yml:274-277` keys on the `renovate/`
prefix, not the group name). The clang last-rule invariant holds. `branch_name` reads the right Renovate field and
its test discriminates (4/4 mutations red). `--no-deps` is parsed by mise on both 2026.9.18 and CI's 2026.9.8, and it
takes the gate's stderr from 125 B to 0. No other production gate isolates `MISE_STATE_DIR`.

Fix in this unit:
1. **F1**: narrow `renovate.json:103`. Delete "and auto-merges once a standalone build exists", or replace it with
   what actually happens: the PR stays red until a retry or a newer python, and `tests/test_image_smoke.py:802,813`
   must be bumped by hand. Consider **F5** (`minimumReleaseAge` on this rule) in the same edit. It is the native lever
   that avoids opening the doomed PR in the first place.

Ticket (siblings; they do not block this diff):
2. **F2**: `tests/test_image_smoke.py:802,813,814` hardcode `python 3.14.7` and `hk 2.3.0`. Any Renovate PR that
   moves either pin fails CI pytest, so the regrouped `image-build inputs` PR (hk 2.3.0 → 2.4.0) is still blocked.
   S29-00's stated aim, "unblock the ten other tools", is not met until this is fixed.
3. **F6**: test-side `mise exec` calls under the per-test isolated state each run `uv sync --locked`, and a failure
   aborts them.

Optional: **F3**, a structural test for the rule that also asserts no later rule re-groups python. **F7**: keep the
argv pin as the real guard.
