## 3. Interfaces (changes to 22bee5a)

`lane_result.py`
- `parse_parent_thread_id(log_text)` [F11]: find the FIRST line within the first 50 lines that starts with `OpenAI Codex v`; the banner is that line, the following `--------`, the `key: value` lines, and the closing `--------`. Everything else unchanged (unclosed banner → None; a `session id:` after the closing delimiter never counts).
- `collect_spawn_report(report_text)` [F1]: after the LAST anchor, every line whose text starts with a Markdown list marker (`^\s*(?:[-*+]|\d+[.)])\s+`) is a list item until the first NON-list, non-blank line. An item `_AGENT_LINE` matches is parsed as today. An item it does NOT match is still a claim: `name` = its first backticked token if any, else the item text after the marker (stripped); `role` = the remainder of the item text after that token (stripped). Never `break` on an unparseable item. The terminator line (`No other specialists … were spawned.`, bulleted or bare) must NOT become a claim: a list item whose text, lower-cased, matches `^(no\s+other|none\b|nothing\s+else)` is the terminator and ends the list [v7: three real phrasings exist — `No other specialists were spawned.`, `No other specialists or subagents were spawned.`, `No others were spawned.`]. A terminator phrase that follows a claim on the SAME line (`` - `sdlc-config-specialist` (`config_smoke_review`); no others were spawned. ``) is part of that item's role text, not a terminator.
- `collect_session_files(parent_thread_id, sessions_root, *, started_at: str = "")` [F5, F8, F9]: read `payload.source` with type guards at EVERY level (`payload.source` is a str on 2,429 parent records and a dict on children; `source.subagent` is the str `"review"` on 239 children, a dict `{"thread_spawn": …}` or `{"other": "guardian"}` on others). A child whose `source.subagent == "review"` is a codex-internal review thread, NOT a roster spawn: it is returned as an `AgentNode` with `status="review-thread"` and `role=""`, name = `agent_role or agent_path or id`, so the receipt lists it, and the reconciler excludes it from pairing (below). Unreadable/unparseable rollout files: those with `st_mtime >= datetime.fromisoformat(started_at).timestamp()` [v7 — compare EPOCH floats; `_utc_now` emits an AWARE `+00:00` string; never compare a naive local `datetime.fromtimestamp` against it — measured 03:53 local vs 08:53 UTC on this UTC-5 host, which makes a during-run file read as old and the fail arm dead]; when `started_at` is empty or unparsable, treat EVERY skipped file as written during this run (fail closed) and say so in the error text are counted separately and reported in `error` as `skipped N unreadable rollout file(s) written during this run` — the reconciler turns THAT into a failure; older skipped files remain the existing note. Both counts may appear in the one `error` string; keep them distinguishable.

`sdlc_team.py`
- Identity extraction [F2, v7]: a claimed item's identity candidates are exactly two: its `name`, and the FIRST backticked token in its `role` text (if any). Both filtered by the two grammars as in v5. Trailing prose tokens (`spawned after `explorer` finished`) are never identities. A PATH candidate must equal a child's `agent_path`. A ROSTER-GRAMMAR candidate is satisfied by a child when it equals the child's `agent_role` OR the basename of the child's `agent_path` — because real dispatchers write the spawn NAME as the second token: `` - `sdlc-python-specialist` as `round3_python` `` (run b941647c, five items) and `` - `sdlc-config-specialist` (`config_smoke_review`); … `` (run smoke-real) name the role and the spawn name, and the spawn name IS the path basename (`/root/round3_python`). A child is CONSISTENT with a claim when EVERY candidate is satisfied (AND, not OR): a claim whose second candidate is a space-free prose token that names nothing therefore matches no child and fails closed with an error naming that claim — the intended direction; the pinned prompt format never produces such a token. Ambiguity is now ONLY two path candidates.
- Pairing [F4, v7]: walk claims in report order; the candidate children are the UNMATCHED, non-review children CONSISTENT with the claim (definition above). A claim with a path candidate has at most one consistent child (paths are unique among siblings); none → error `claimed path '<path>' matches no observed child` when the path matches no child at all, or `claimed '<roster token>' does not match child at <path> (agent_role '<role>', name '<basename>')` when the path exists but a roster candidate disagrees. A claim without a path candidate pairs with the FIRST consistent unmatched child (this keeps arm 14's two role-only claims pairing two same-role children); none → `claimed item '<name>' matches no observed child`. Review-thread children (status `review-thread`) are excluded from the pairing pool and never produce an unpaired-child error; they are listed in the receipt only.
- `specialists_claimed` [F3]: per claimed item, the item's OWN identity — its roster-name identity when it has one, else its path identity, else its raw `name`. Never the observed child's name. `specialists_observed` unchanged (sorted observed names, review threads INCLUDED with their name — they are observed).
- Receipt canonicalization [F7]: for every matched claim, the canonical SELF_REPORT node is `AgentNode(name=<child node name>, role=<child agent_path>, …)` regardless of claim order, so `merge_sources` reports no role conflict for the pinned `- <role> — <path>` shape.
- Fail-closed inputs [F9]: `reconcile_spawns` adds `spawn reconciliation: <the during-this-run skipped-file text>` when the observed collector reports files skipped during this run; the old-file note stays receipt-only. Pass `payload.started_at` through to the collector.
- Error text for F1 items: an unparseable item that has no identity → the existing `names no roster specialist or agent path` error, quoting the item's `name` (its first backticked token or its text), so the run's errors name the ITEM, not an innocent child.
