are byte-equal" and "the two surfaces have different capabilities" cannot both

  surface-specific, which likely means it cannot mention either surface's tools.

State which you chose and why. F5's gate is written to work either way — it
checks name/effort agreement and corruption, NOT byte-equality.

### F5 — the gate that makes tracking safe

Two facts I measured this session:

- `hk-common.pkl` `excludePaths` contains `.codex/**`, so **every hk builtin is
  blind to the four newly-tracked tomls**.
- The four Codex-app-EXPORTED mirrors share mtime `18:52:09` exactly — one batch
  write — and carry a `claude`→`Codex` substitution (`claude-code-expert.toml`
  scores 5, `adversarial-critic.toml` 2 on `Codex Code|\.Codex/|Codex mcp add`).

Note what I could NOT establish, so you do not overbuild: the cold review claimed
the exporter enumerates `.claude/agents/*.md` 1:1 and will therefore overwrite
the new files. **That mechanism is refuted** — the sibling export surface shows
`.claude/skills/` at 31 directories against `.agents/skills/` at 3, and
`.agents/skills/` contains `codex-task-orchestration`, which has no source in
`.claude/skills/`. The exporter mirrors a SELECTED subset, not a directory. So
the risk is real but unproven, and the response should be a cheap loud gate, not
machinery.

Add ONE hk step (in `hk.pkl`, following the shape of the existing
`session_review_skill_parity` step at `hk.pkl:633`, which is the in-repo
precedent for a two-surface consistency check), plus the minimal `hk-common.pkl`
carve-out that lets it see `.codex/agents/codex-*.toml`. Keep the exclusion for
the rest of `.codex/**`.

The step must fail when:

1. any tracked `.codex/agents/codex-*.toml` contains the corruption signature
   (`Codex Code`, `.Codex/`, `Codex mcp add`); or
2. a `.claude/agents/codex-*.md` has no `.codex/agents/` counterpart of the same
   stem, or vice versa; or
3. a counterpart's `name` disagrees with its filename stem, or its
   `model_reasoning_effort` is not `"xhigh"`.

Per `.claude/rules/zero-bash-logic.md` the logic goes in `python/` with a thin hk
wrapper and a mise task — no new `scripts/*.sh`. Add tests under `tests/`.

**Arm the gate in both directions** (`.claude/rules/probes-need-a-control-arm.md`):
prove it FAILS by introducing a realistic break — not a rename, but the actual
regression shape: paste a corrupted string into one tracked toml, and separately
delete one counterpart file. Then restore and prove it passes. Report both arms'
output. A gate verified only on clean files is decoration.
