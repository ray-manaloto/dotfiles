# SPEC — bump graphify 0.9.42 -> 0.9.53

## 1. Objective

`uv tree --outdated --show-sizes --all-groups --project python` must show **no
first-level outdated packages at all**. `graphifyy[all]` is the last one.

After this change, `mise run graphify-health` must report **`fresh`** at runtime
0.9.53 — NOT `version_drift`. A drifted graph is treated as unavailable by
`.claude/rules/graphify-first.md`, so a bump that leaves the health check
pointing at 0.9.42 would silently DISABLE graphify rather than upgrade it. That
is the failure this spec exists to prevent.

## 2. Files

- `python/pyproject.toml` — the pin, plus a `[tool.uv] override-dependencies`
  entry
- `python/uv.lock` — via `uv lock --project python` only
- `python/src/dotfiles_setup/graphify.py` — the hardcoded expected version
- `tests/test_graphify.py` — the two assertions carrying `0.9.42`
- `graphify-out/**` — regenerated by `mise run graphify-update` (gitignored;
  do not commit it, but DO rebuild it)

Check for any other `0.9.42` occurrence and fix it; the four sites below were
found this session but the sweep is yours.

## 3. Interfaces — the exact end state

**The pin and the override** (both required — the override is what makes it
resolvable at all):

```toml
"graphifyy[all]==0.9.53",

[tool.uv]
override-dependencies = ["graphifyy[all]==0.9.53"]
```

All must move to `0.9.53`. Locate by content, not by line number.

## 4. Constraints and invariants

**C1 — `override-dependencies` is REQUIRED, and here is why.** The SHA-pinned
`kb-setup` dependency (`python/pyproject.toml:40` -> knowledge-base@`c70f0f81`)
itself pins `graphifyy[all]==0.9.42`. Without an override, `uv lock` refuses:
*"your project's requirements are unsatisfiable."* WITH the override it resolves
cleanly — measured this session: `Resolved 143 packages`, `Updated graphifyy
v0.9.42 -> v0.9.53`, rc=0.

**C2 — do NOT touch the knowledge-base repo.** It is out of bounds by operator
ruling. The whole point of the override is that no cross-repo change is needed.
Do not change the `kb-setup` SHA pin either.

**C3 — `kb-setup` must still work.** It declares 0.9.42 and will now get 0.9.53
at runtime. Measured this session: `uv run --project python kb-setup md-budget`
returns rc=0 under the override. **Re-verify it yourself** — that is the real
risk of overriding a consumer's pin, and it is the one thing that would make
this change wrong.

**C4 — rebuild the graph.** After the bump, run `mise run graphify-update`
(AST-only, no API cost) so the graph is built by the new runtime, then confirm
`mise run graphify-health` reports **`fresh`**. Do not commit `graphify-out/` —
it is gitignored.

**C5 — never a bare `graphify` on PATH, and never `graphify install`.**
Use the repo's mise tasks only (`mise run graphify-update`,
`mise run graphify-query`). `.claude/rules/do-not.md` #8: a bare
`graphify install` mutates `~/.claude`. Not needed here; do not run it.

**C6 — the shell PATH on this host is STALE.** A bare `hk` resolves 1.56.1 while
the repo pins 1.57.0, which produces a FALSE failure in
`tests/test_hk_builtins_audit.py`. Run every gate through
`mise exec -- sh -c '...'`.

**C7 — no inline lint suppressions** (`noqa`, `type: ignore`, `nosec`).

**C8 — commit on the current branch `chore/deps-currency-20260831`.** HEAD is
`b75fa3b`, tree clean. Do not create a branch, do not push, do not open a PR.
