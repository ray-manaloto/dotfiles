## Findings

### F1 — HIGH: the only test guarding the template's value cannot fail on the one mutation that breaks it

`tests/test_safe_directory.py:17-53` renders the template with
`chezmoi --source=<tmp>/alternate-clone-name execute-template`, where the
fixture is a bare `mkdir`'d directory with **no `.chezmoiroot` and no git**. In
that shape `.chezmoi.workingTree` and `.chezmoi.sourceDir` are the same string,
so the assertion at `tests/test_safe_directory.py:53` cannot distinguish them.

Measured, on a `git archive 86e0d3e` copy with only
`home/dot_gitconfig.tmpl:25` mutated `workingTree` → `sourceDir`:

```
tests/test_safe_directory.py::test_gitconfig_renders_the_current_chezmoi_working_tree PASSED
1 passed in 0.40s
```

Control arm (same harness, mutation to `.chezmoi.homeDir`): `1 failed`. So the
harness discriminates; the fixture does not.

That mutation is not cosmetic — it is production-breaking. With this repo's real
shape (`.chezmoiroot` = `home`), `sourceDir` is `<workspace>/home`:

```
WT=/…/fakeclone | SRC=/…/fakeclone/home
```

and a `safe.directory` naming `<root>/home` does **not** clear the error, armed
four ways with `GIT_TEST_ASSUME_DIFFERENT_OWNER=1`:

| arm | `safe.directory` | rc |
|---|---|---|
| 1 | none, ownership forced foreign | **128** `detected dubious ownership` |
| 2 | `<root>` (shipped behaviour) | **0** |
| 3 | `<root>/home` (the mutation) | **128** |
| 4 | none, ownership not forced (control) | 0 |

Fix: give the fixture the production shape — a `--source` directory containing a
`.chezmoiroot` of `home` — so `workingTree` and `sourceDir` differ.

### F2 — MEDIUM: the negative test pins a diagnostic that is wrong for two of the three ways it fires

`scripts/devcontainer-smoke.sh:21-25` emits
`git cannot open the workspace at …; verify safe.directory in ${HOME}/.gitconfig`
for **any** non-zero `git rev-parse HEAD`. Measured, three distinct causes:

- not a git repository → `fatal: not a git repository (or any of the parent directories): .git`
- repo with no commits → `fatal: ambiguous argument 'HEAD': unknown revision …`
- forced foreign ownership → `fatal: detected dubious ownership in repository at '…'`

`tests/test_safe_directory.py:56-79` builds the **first** of those
(`tmp_path / "not-a-git-workspace"`, `mkdir` only) and then asserts
`"safe.directory" in diagnostics` at `tests/test_safe_directory.py:77`. The
suite therefore never exercises the condition #1183 exists for, and it pins the
misdiagnosing branch as correct behaviour.

`GIT_TEST_ASSUME_DIFFERENT_OWNER=1` reproduces the real condition with no root
and no container (arm 1 above), so a faithful negative arm is available.

### F3 — MEDIUM: the preflight probes git-core, but the commit's other named victim is libgit2

The commit body claims two failing consumers: "git exits 128 … and hk's libgit2
fails Owner (-36)". The preflight at `scripts/devcontainer-smoke.sh:22` runs
`git`, i.e. git-core only. git-core and libgit2 implement owner validation
separately and read `safe.directory` through different config stacks, so a state
in which `git` succeeds and libgit2 still refuses passes the preflight and fails
inside tier 1 with exactly the obscure message the preflight was added to
pre-empt. UNVERIFIED that such a state is reachable — I could not reproduce
libgit2's path on this host — but the preflight's coverage claim in
`.claude/rules/persistence-gate-retry.md:59-60` ("the smoke harness probes the
workspace before tier 1") is broader than what line 22 actually probes.

### F9 — LOW (security, accepted): the entry disables git's ownership validation for the workspace permanently

`safe.directory` is not scoped to the five-minute window it was added for; once
rendered, git will trust `/workspaces/<clone>` regardless of who owns it, which
is the mechanism by which a foreign-owned repo's `.git/config` and hooks become
executable. In this deployment the container user has passwordless `sudo`
(`.devcontainer/devcontainer.json:237`), so root and the user are one trust
domain and the exposure is negligible. There is no narrower expression of the
fix; recorded so the tradeoff is on the record rather than implied.
