# SPEC — #919: assert the PostToolUse hook registration in the ship/land gate

## 1. Objective

Removing the `PostToolUse` hook registration from `.claude/settings.json`, or
letting its matcher or command drift, must FAIL the `hook-selfcheck` gate that
`mise run ship` and `mise run land` run. Today it does not: `_SETTINGS_WIRING`
asserts `PreToolUse`, `SessionStart`, `SessionEnd` and `InstructionsLoaded`,
but not `PostToolUse`, so the `mise-config-context` write-trigger dispatcher is
covered only by its own unit tests.

The failure this prevents: green unit tests certify that a module COMPUTES
correctly; they never certify that it is still WIRED IN. Deleting the
registration today leaves lint, pytest, verify and hook-selfcheck all green
while the hook silently never fires again. This is the same class as #343
(the guard that failed open off-root for 125 commands while every gate stayed
green) and #917 (which added the `InstructionsLoaded` row for exactly this
reason).
