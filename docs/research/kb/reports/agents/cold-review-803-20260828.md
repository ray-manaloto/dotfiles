## H1 — `all_images.get(image_id, ImageRefs((), ()))` fails OPEN straight into `docker rmi <bare id>`

`python/src/dotfiles_setup/devcontainer_names.py:823-826`

```python
candidates: dict[str, ImageRefs] = {
    image_id: all_images.get(image_id, ImageRefs((), ()))
    for image_id in live_image_ids
}
```

Input that produces the wrong behaviour: any container `.Image` id that
`_docker_image_refs()` did not enumerate. The synthesized `ImageRefs((), ())`
then:

* passes `_has_registry_slash` unconditionally — `any(...)` over two empty
  tuples is `False` (`:836`, `:772`). The one input the destructive-path guard
  exists for — *"we do not know what this image is"* — is the input that
  bypasses it;
* falls through `for ref in refs.tags or (image_id,)` (`:838`) to emit the
  **bare image id** as a `docker rmi` argument.

The two docker calls are separate and racing: `docker images -aq` (`:700`) runs
in `teardown-images`, the container inspect (`:681`) runs just before it. An
image that arrives or is retagged between them lands in `live_image_ids` with
no refs, and the code's response is to *delete it*, not to skip it.

Control arm on this host: all 28 containers resolved (`in_all_images=True`
× 28), so this is latent, not observed.

No test pins it either direction — mutating the fallback to `all_images[image_id]`
(raising `KeyError`) leaves **54/54 green**.

Fix: skip an id absent from `all_images`, or treat unknown as refuse. "Unknown"
must not be the permissive branch in a function whose output is `docker rmi`.

## H2 — the slash guard's narrowing does not hold for the *legacy* container arm

`devcontainer_names.py:758-772` (guard), `:816-819` (what it guards),
`:623-627` (the legacy arm it inherits)

`teardown_image_refs`'s container set is `teardown_container_ids(..., all_arches=True)`,
which is the union of *our* labelled containers **and** the legacy arm: every
container carrying `devcontainer.local_folder=<workspace>` and none of our
labels. That arm is by construction containers whose provenance this repo does
not control.

`_has_registry_slash` refuses a candidate only if a tag or digest contains `/`.
Its docstring concedes the general claim is false ("`busybox:stable` … one of
many single-segment Docker Hub images") and narrows to *"the narrower, true
statement about THIS repo's images"* — but the legacy arm is definitionally
**not** this repo's images. A legacy container whose `.Image` is a single-segment
or locally-tagged image passes the guard and is handed to `docker rmi`.

Slash-free, shared, non-clone-owned images are present on this very host right
now (`symphony-opensymphony:local`, `symphony-gcc-runtime:local-arm64`), so the
shape is not hypothetical — only the pairing with the folder label is.

Status: reachable path, **UNVERIFIED** that such a container exists today (none
of the 28 pairs the folder label with a slash-free image).

Fix: apply the orphan-tag/ownership test to images reached through the *legacy*
arm too, rather than trusting the slash heuristic to carry it.

## M5 — `_is_orphan_tag`'s two shapes are each individually deletable with the suite green

`devcontainer_names.py:732-756`; `tests/test_devcontainer_names.py::test_teardown_images_finds_the_clis_own_orphan_tag`

Measured, both directions:

| mutation | result |
|---|---|
| drop shape 2 (`vsc-<basename>-<full_digest>`) | 54 passed |
| drop shape 1 (`vsc-dotfiles-<hash>`) | 54 passed |
| `_is_orphan_tag` → `return False` | 1 failed |

Cause: the fixture workspace is `WORKSPACE = "/workspaces/dotfiles"`, basename
`dotfiles`, so `full_digest.startswith(names.hash)` is **True** (probed:
`hash=be636185`, digest `be63618543ef9a76…`). The CLI-tag test's input is
therefore matched by shape 1 alone — it passes for a reason unrelated to its
name. And no test ever feeds a `vsc-dotfiles-<hash>-<arch>` tag through the
orphan path (both tests using that shape pass `from_containers`, which bypasses
`_is_orphan_tag` entirely).

The one case shape 2 exists for — a clone whose directory basename is **not**
`dotfiles`, where the CLI's tag is `vsc-<basename>-<fullsha>` and shape 1's
hardcoded `vsc-dotfiles` prefix cannot match it — is never exercised. The
orphan-tag half of the design (what makes `prune` still find overlays after
`stop` already removed the containers) is effectively unpinned.

Fix: one test with `_names(workspace="/x/myrepo")` asserting the CLI tag is
found, and one asserting `vsc-dotfiles-<hash>-<arch>:latest` is found through
the orphan path (`from_containers=[]`).

## M7 — the documented MUST is unenforceable and rests on line ordering alone
