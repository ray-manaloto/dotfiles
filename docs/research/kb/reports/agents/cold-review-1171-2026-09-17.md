### H1 (HIGH) — the headline doc claim is false for every unbounded shape

The diff replaced the docstring line "…wrapper is OTHER and is left to #1171" with:

> `session_orphans.py:7-8` — "a ``zsh -c source ...snapshot...`` wrapper whose argv contains the loop is classified as that WAIT-LOOP."

and `.claude/skills/verify/SKILL.md:30-32` with "The snapshot … wrapper **is itself a `WAIT-LOOP`**".

Measured against the real wrapper argv (captured live from this session's own `ps`, pid 15666 — prefix `/bin/zsh -c source …/snapshot-zsh-….sh 2>/dev/null || true && … && eval '<cmd>' < /dev/null && pwd -P >| /tmp/claude-…-cwd`), driving `session_orphans._SHELL_COMMAND` + `hook_guard.is_audit_wait_loop(mask_shell_syntax(...))` directly:

| loop inside `eval '…'` | wrapped verdict | bare `sh -c '…'` verdict (control) |
|---|---|---|
| `deadline=$((SECONDS+540))` NL `while [ $SECONDS -lt $deadline ]; do …; done` | **OTHER** | OTHER |
| `deadline=$((SECONDS+540)); while [ $SECONDS -lt $deadline ]; do sleep 15; done` | WAIT-LOOP bounded | WAIT-LOOP bounded |
| `while true; do sleep 5; done` | **OTHER** | WAIT-LOOP unbounded |
| `while ! curl -sf http://x; do sleep 5; done` | **OTHER** | WAIT-LOOP unbounded |
| `until [ -f /tmp/flag ]; do sleep 5; done` | **OTHER** | WAIT-LOOP unbounded |
| `cd /tmp; while true; do sleep 5; done` | WAIT-LOOP **bounded** (mislabelled — see M4) | WAIT-LOOP bounded |
| `while [ $SECONDS -lt $DEADLINE ]; do sleep 5; done` | **OTHER** | WAIT-LOOP bounded |

The bare column is the control arm: the same eight strings, same code path, and five of them do produce `WAIT-LOOP`, so the probe discriminates.

**Mechanism.** `_AUDIT_WAIT_LOOP_CANDIDATE` requires `while`/`until` at a command boundary: `(?:^|[;&|\n\x00]\s*)` + `_WRAPPER`, or immediately after a literal `bash|zsh|dash|sh -c ['"]?` (`hook_guard.py:163-175`). In the real wrapper the character before `while` is the `'` opening `eval '…'`; `eval '` is not in `_WRAPPER` and is not `sh -c`. The wrapper is therefore classified **only when the loop is not the first statement inside the eval** — which inverts the risk ordering: the bounded, deliberately-terminating poll is caught, and the three unbounded shapes (the ones the tool exists to find) are not.

**This is a documentation defect, not a code regression.** The diff changes no classification code; a base replay (`git archive ff2fbaf` + `PYTHONPATH`) returns byte-identical verdicts on all five probe shapes. What is new is the sentence asserting the coverage.

**Not asserted anywhere.** `tests/test_session_orphans.py:35-38` models a wait loop as `zsh -c 'deadline=…; while …; done'` — the synthetic `zsh -c '<loop>'` form, which takes the `sh -c ['"]?` branch. No fixture contains the real `source …snapshot….sh … && eval '…'` prefix, so the claim the docstring makes is guarded by nothing.

### H2 (HIGH, pre-existing) — the repo's own prescribed poll shape is invisible

`.claude/rules/long-running-command-hangs.md` rule 2 prescribes, verbatim:

```bash
deadline=$((SECONDS+540))
while [ $SECONDS -lt $deadline ]; do grep -q RC "$LOG" && break; sleep 15; done
```

`ps` renders that embedded newline as the literal four characters `\012`. Measured on three **real** processes spawned for this review (all self-terminating at 45 s; confirmed exited afterwards, 0 survivors):

```
25459 bash -c deadline=$((SECONDS+45))\012while [ $SECONDS -lt $deadline ]; do sleep 5; done   -> OTHER
25460 bash -c deadline=$((SECONDS+45)); while [ $SECONDS -lt $deadline ]; do sleep 5; done     -> WAIT-LOOP bounded
25461 bash -c n=0; while ! test -f /nonexistent-…; do sleep 5; …; done                          -> WAIT-LOOP unbounded
```

Rows 2 and 3 are the control: identical logic, one line, correctly classified. The candidate boundary class is `[;&|\n\x00]` — a real newline, not the two-character escape `ps` emits — so the multi-line form has no boundary before `while`.

Consequence for the commit's own title ("a healthy session exits 0"): an agent that followed the repo's prescribed in-turn poll leaves a process that lands in `OTHER`, blocks with rc=1, and that `--kill` will never reap. Verified pre-existing at `ff2fbaf`; reported because the diff's title and doc rewrite now rest on it.

### M1 (MEDIUM) — `--kill` widened to a class where `command` is not an identity

`session_orphans.py:288-297` adds `wait_loop_children` to the reap targets and hands them to `reap.Selection` directly. `reap.reap` re-snapshots and calls `confirm_targets`, whose entire PID-reuse defence is "same pid **and** same command string" (`reap.py:366-387`, and `reap.py:40-44` describes it as the guarantee). Demonstrated:

```python
sel      = Process(pid=331, ppid=330, age_s=4, command="/bin/sleep 5")
imposter = Process(pid=331, ppid=999, age_s=1, command="/bin/sleep 5")
confirm_targets([sel], [imposter], protected=frozenset())
# -> CONFIRMED (would be signalled), 0 dropped
```

`/bin/sleep 5` is the least distinguishing command string on a host, and a poll loop respawns its sleep every iteration, so the selected pid is very often already gone by the time `reap` re-snapshots. The guard cannot distinguish "the sleep I selected" from "a different `sleep 5` that landed on that pid". Nothing in the new tests exercises a changed table between snapshot and signal — `test_kill_targets_the_wait_loop_and_its_sleep_but_not_harness` feeds a stable table for the first two reads.

### M3 (MEDIUM) — the shapes and the tests share one observation

`HARNESS_CHILD_SHAPES` pins `caffeinate -i -t 300` (exact duration), one MCP package name, and the `~/.npm/_npx/<hash>/node_modules/.bin/` layout. The comment at `:76` states "The harness renews this exact five-minute macOS sleep inhibitor" — true today; I confirmed live on this session's root (84642): `16504 caffeinate -i -t 300`, `84703 npm exec @modelcontextprotocol/server-pdf --stdio␣␣␣␣`, `85403 node /Users/rmanaloto/.npm/_npx/6583fba12287d067/node_modules/.bin/mcp-pdf-server --stdio`.

The problem is the failure mode when the harness moves. Mutation M12 (`-t 300` → `-t 600`) and M11 (`/Users/` → `/home/`) both turn the suite red — but red **because the fixture carries the same literals transcribed from the same single observation**. A harness upgrade that changes the duration or the npx layout leaves the suite green and every handoff blocked. This is the `probes-need-a-control-arm.md` rule-9 shape: the check binds something we do not own, with no arm that fails when the upstream fact changes.

Related coverage gap: only the PDF MCP pair is typed. A session whose MCP roster differs (this host runs `npm exec xcodebuildmcp@latest mcp` under another claude root) gets `OTHER` rows for every other server, so "a healthy session exits 0" is a property of one roster, not of a healthy session.

### M4 (MEDIUM, pre-existing) — the bounded/unbounded label can be wrong

`format_plan` labels via `hook_guard.is_unbounded_wait_loop`, which uses `_WAIT_LOOP_CANDIDATE` — boundary `[;&|\n]`, **without** `\x00` — while classification uses `_AUDIT_WAIT_LOOP_CANDIDATE`, boundary `[;&|\n\x00]`. `mask_shell_syntax` turns an in-quote `;` into `\x00`. So a loop preceded by a statement inside quotes is admitted by the audit predicate and then always reports "bounded". Rendered live:

```
WAIT-LOOP bounded     330 (6m00s, S) sh -c 'x=1; while ! curl -sf http://h; do sleep 5; done'
```

That is an unbounded `curl` poll labelled `bounded`. Pre-existing (`hook_guard.py` is untouched by this diff), but the rewritten `session-handoff/SKILL.md:96-97` is what directs an operator to read this label.

### M5 (MEDIUM) — macOS-only home path

`session_orphans.py:70-73` hard-codes `/Users/[^/\s]+/`. The devcontainer is Linux (`/home/<user>`), and the surrounding `node` binary prefix is deliberately generic (`(?:/[^\s]+/)?node`) — so the pattern is generic where it does not need to be and platform-locked where it does. Mutation M11 confirms the literal is load-bearing.

The three HARNESS rows are exactly what the diff set out to stop blocking, and that half works. But the residual `OTHER` rows are another lane's *legitimate, in-flight* tool call — including that lane's own `zsh -c source …` wrapper, which only the **calling** lane's chain is protected from (`session_orphans.py:141-143`). ## Areas checked with no findings

Stating these explicitly, with what was run:

1. **Partition exactly-once.** Every descendant reaches exactly one of the four buckets; the `continue`-based exits make double-counting unreachable. Mutation M9 (letting wait loops also fall into `other`) turns 8 tests red. The tests themselves assert it (`test_wait_loop_only_admits_a_direct_typed_sleep_child:168-169`, union == descendants and sum-of-lengths == union size).
2. **Iteration-order dependence of the chained HARNESS parent.** `reap.descendant_pids` is breadth-first (`reap.py:239-255`), so a parent is always enumerated before its child and `harness_ids` is always populated in time. The only ways the chained child loses its parent — parent protected, or parent classified WAIT-LOOP — both fail **closed** to `OTHER`.
3. **argv forgery into `HARNESS`.** Not reachable. Both `SESSION_ROOT` shapes require `ppid == root_pid`, and a process cannot choose its parent; only the session root's own direct spawns qualify, and the repo's `zsh -c source …snapshot…` wrapper never reduces to a bare `caffeinate`/`npm` argv (it keeps the wrapper argv through `eval`). The one operator-controlled lever is `--root <pid>`, which is an explicit flag.
4. **Test teeth.** 12 mutations run in a `cp -R` scratch copy under `PYTHONPATH` shadowing (never the checkout); baseline 14 passed. All 12 turn the suite red: drop the parent requirement (1 failed), drop the direct-parent rule for sleeps (1), revert the `--kill` widening (1), drop `.rstrip()` (4), make HARNESS block again (4), loosen `ppid == root_pid` (1), widen the sleep pattern to `sleep .*` (1), add HARNESS to the kill set (1), double-count wait loops (8), empty the shape tuple (4), `/Users/`→`/home/` (4), `-t 300`→`-t 600` (4). Note per `tests/AGENTS.md`: five of these break exactly one test, which marks a narrow axis enumeration, not quality — the unenumerated cells are H1 (the real wrapper argv) and M1 (a table that changes between snapshot and signal).
5. **Contract tokens.** Strict `per_path_tokens` replay over the whole of `suites.toml`: **1273 tokens scanned, 0 failures**. The scan is its own control arm.
6. **`.agents/` mirror staleness.** Both mirrors are real tracked files (not symlinks) and both are current: `verify/SKILL.md` is byte-identical to the `.claude/` copy, and `session-handoff/SKILL.md` differs only in the three known `PER_FILE` reversions (CLAUDE.md→AGENTS.md routing, the self-referential skill path). No semantic drift in the rewritten hunks.
7. **The prior round's `ps` self-count defect stays fixed.** `own_subtree` (`session_orphans.py:142`) excludes the tool's own `ps` child; the fixture models it (pid 202) and the live run's protected set carried the whole caller subtree. Three consecutive live runs produce no `ps -eo` row.
8. **The diff's core value is delivered, and verified live** — not by fixture: the three real harness descendants of this session were classified `HARNESS`, where at base all three were blocking `OTHER` rows.
