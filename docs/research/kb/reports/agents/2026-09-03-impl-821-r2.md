## Work log

### Premise and native-capability check

Current source agrees with the respec: `lock_top_level_config_tools` derives
normalized top-level names, refuses the empty set, runs scoped `mise lock`, and
returns the subprocess result without reconciling stale lock entries.

The real tool reports `mise 2026.9.1 macos-arm64 (2026-09-02)`. Its `mise lock
--help` says TOOL arguments target specific tools and that the bare form updates
all configured and task-specific tools. Available flags include `--global`,
`--jobs`, `--dry-run`, `--platform`, `--bump`, `--json`, `--local`,
`--minimum-release-age`, and `--upgrade`; there is no prune flag. A narrow
producer-side prune is therefore necessary.

The generated root lock uses one `[[tools.X]]` array-table per tool, followed by
that tool's child tables until the next `[[tools.Y]]`. The implementation will
remove only stale whole-tool blocks, validate the resulting TOML, and skip the
write entirely when the tool set already matches.

### Implementation

- Added post-success lock reconciliation inside
  `lock_top_level_config_tools`; a failed `mise lock` still returns its original
  rc without pruning.
- Stale `[[tools.X]]` blocks and their child tables are removed as one unit.
  TOML itself decodes quoted/bare tool keys; the regex only finds generated
  block boundaries.
- Both config and lock names use the single production `_EXTRAS_RE` definition.
  `tests/test_lock_coverage.py` now imports that definition instead of defining
  a byte-identical second copy. Its production coverage assertions are
  unchanged.
- The candidate lock is parsed and required to equal the normalized top-level
  config set before it is written. An already exact lock returns before
  `write_text`.
