## Respec round 1 (rev 2) — F1 fix + F2/F3/F4 cleanup

Cold review found `check_settings_wiring` matches per-EVENT, not per-ENTRY:
`.claude/settings.json`'s three `PreToolUse` entries were flattened into one
blob before checking, so a required matcher token could be satisfied by a
DIFFERENT entry than the one carrying the required command. Live today:
narrowing the deny-guard entry's matcher to drop `Bash` still reported fully
wired, because the unrelated `graphify-hook-guard.sh search` entry's
`Bash|Grep` supplied the missing token.

### Fix (C1/C2)

`check_settings_wiring` now selects the OWNING entries per row — those whose
command contains at least one required substring — and scopes both the
substring check and the matcher-token union to those entries only, falling
back to all entries (today's old behavior) when none owns the row. Kept exact
alternation-token membership (no regression to substring containment).

### F2/F3/F4 (C4/C5/C6)

- Corrected the false #919 row comment: it claimed no prior test certified the
  PostToolUse wiring, but `tests/test_mise_config_context.py`'s
  `test_settings_wires_this_hook_without_depending_on_a_mise_task` has done so
  since PR #902 (`git merge-base --is-ancestor 2ceb351 HEAD` → 0). Rewrote the
  comment to state the row's real delta: alternation-token matching sees a
  matcher narrowed to `Write|NotebookEdit` that the older test's
  substring-containment check (`"Edit" in m`) cannot, since `"Edit" in
  "NotebookEdit"` is True.
- Refreshed the module docstring (was: 3 events, PreToolUse "scoped to
  `Bash`"; now: 5 events, full tool list).
- Scoped `test_partial_matcher_fails` and
  `test_a_substring_matcher_does_not_satisfy_a_required_token`'s negative
  assertions to `PreToolUse`'s own failures, so the new PostToolUse row's
  requirements can't make them pass for the wrong reason.

### New tests (C3)

Added `_full_settings_with_graphify_pretooluse()` (the real 2-entry PreToolUse
shape: guard + graphify sibling) plus:
