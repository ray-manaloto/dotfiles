## Respec round 1 (rev 2) — F1 fix + F2/F3/F4 cleanup

Cold review found `check_settings_wiring` matches per-EVENT, not per-ENTRY:
`.claude/settings.json`'s three `PreToolUse` entries were flattened into one
blob before checking, so a required matcher token could be satisfied by a
DIFFERENT entry than the one carrying the required command. Live today:
narrowing the deny-guard entry's matcher to drop `Bash` still reported fully
wired, because the unrelated `graphify-hook-guard.sh search` entry's
`Bash|Grep` supplied the missing token.

### Fix (C1/C2)

`check_settings_wiring` now selects the OWNING entries per row — those whose
command contains at least one required substring — and scopes both the
substring check and the matcher-token union to those entries only, falling
back to all entries (today's old behavior) when none owns the row. Kept exact
alternation-token membership (no regression to substring containment).

## Respec round 2 (rev 3) — close the class, not the instance

Round 2's cold review proved rev 2's fix (`3ac54a5`) was half a no-op and the
same defect class was still live on two other axes:

1. The command-side `owners`/`joined` scoping was a provable no-op: `owners`
   is defined as "entries whose command contains a required substring", so
   any entry that could contribute a token IS an owner by construction —
   `joined` over owners equals `joined` over all entries. Only the matcher
   half ever carried the fix.
2. **Command-axis hole:** splitting `SessionStart`'s one entry into a
   `startup`-only `web-setup.sh` entry and a `resume`-only
   doctor/tool-currency-check entry returned GREEN — the #418 doctor and the
   tool-currency check (wired ONLY in `.claude/settings.json`) would never
   run on a real `startup` session.
3. **Matcher-axis hole across owners:** narrowing the real guard entry's
   matcher to `Bash` and adding a decoy entry (matcher
   `AskUserQuestion|Edit|Write|NotebookEdit`, command merely mentioning
   `pretooluse-guard.sh` in an `echo`) returned GREEN — `ask_quality` and
   `branch_guard` (#400) silently absent while ship/land/hook-selfcheck all
   stayed green.

### Fix (C1)

Removed all pooling (`owners`/`scoped`/fallback machinery). New rule: for
each `_SETTINGS_WIRING` row, at least ONE single entry must carry every
required command substring AND every required matcher token
(alternation-token membership, not substring containment — unchanged from
round 1). No entry qualifying → report against the CLOSEST candidate (the
entry with the most matched required substrings), so the failure message
still names what to fix (C3). This deliberately rejects a legitimate-but-
unused shape — one logical hook split across two entries with the same
command and complementary matchers — documented as a trade-off in the code
comment (C2), per A3.

### Comment corrections (C4/C5/C6)

- Deleted the invented fallback rationale ("so a missing command still
  reports missing rather than silently passing or crashing") — disproven by
  a live probe (L16): an empty `joined` already reports every required token
  missing regardless of any fallback.
- Removed the "scope BOTH checks" framing since the new rule IS the
  single-entry invariant, not a scoping trick.
- Fixed two backwards test comments: `test_partial_matcher_fails`'s negative
  assertion comment was a non-sequitur (nothing else requires `'Bash'`, so
  the unscoped form would have been equivalent) — rewritten to state what the
  scoping actually buys (precision of what the assertion means, not
  laundering prevention). `test_a_substring_matcher_does_not_satisfy_a_
  required_token`'s laundering argument was attached to the negative
  assertion when it belongs on the positive one (`PostToolUse` independently
  requires `'Edit'`, so an unscoped POSITIVE assertion could be satisfied by
  a different row's failure) — moved to the correct assertion.

### New tests (C7) + mutation ledger (C8)

Added `_full_settings_with_pretooluse_matcher_split_across_two_owners()` and
`test_matcher_tokens_split_across_two_owning_entries_fails` — two PreToolUse
entries BOTH carrying the guard's real command, matcher tokens split across
them (multi-owner laundering; round 2's per-owner union would have pooled

Added `test_session_start_split_across_two_entries_fails` — SessionStart's
