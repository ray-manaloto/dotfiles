## Answers to the six caller questions

1. **Can the regen commit anything outside the intended set?** No. `git add` (`:522`) uses exactly the four pathspecs that confine excludes (`:467`). Every arm outside them was BLOCKED, including a rename, a space in a path, a `schemas-extra/` sibling and a `.orig` sibling. Inside `schemas/`, the set is wider than the writers (F3). The one writer outside the set, `.claude/types/claude-code.d.ts`, turns the job red instead of committing (F2/F3).
2. **artifact-drift rc classification.** rc 0 → in sync. rc ≥2 → fail (arm: rc=127). rc 1 → drift, and it also absorbs every uncaught Python exception and an `hk builtins` failure (arms C and E). A real CLI error is never committed AS drift. Two of the backstops are real: the regen runs the same code, and the re-check is mandatory. But a transient error unlocks a full refresh on a drift-free PR (F4) and, through F1, can commit codex churn. Missed drift: none found. The job, `hk_audit` (`hk.pkl:373-375`) and `config.schema-vendor-drift` call the same predicates. The job's hk comes from the same `shared.toml` and lock as lint's full install.
3. **Loop safety.** The App-token push fires `synchronize` (`:304-306`), so the job re-runs. The second run is a no-op. `drift-check` passes, and `artifact-drift` is offline and deterministic, so it reports `drift=false`. That false skips regen, confine, commit and push (`if:` at `:432/:444/:459/:510/:520/:544`). The committed tree equals the re-checked tree, because confine proves nothing else moved. Upstream churn cannot make the CHECK flip, so it cannot loop. It can only ride along in a commit that some other drift triggered (F1/F4).
4. **PR-pinned hk.** Yes. jdx/mise-action at the pinned SHA auto-adds `--locked` when a lock exists, and adds shims to PATH by default. #1449's `.config/mise/mise.lock` carries hk 2.4.0 for `linux-x64`. The `hk util` dependency holds in hk 2.4.0: all four fixers exist with the flags `_HK_HYGIENE_FIXERS` assumes (control `bogus-fixer` → rc=2). A refresh under 2.4.0 hygiene leaves every vendored file unchanged.
5. **renovate.json `jdx/mise` rule.** BASE vs HEAD dry-runs both returned rc=0 with 48 updates. The delta is exactly the two action.yml `jdx/mise` updates, which move `github-actions-non-major` → `image-build-inputs`. `jdx/mise-action` stays in `github-actions-non-major`. No other dep is named `jdx/mise`. clang is rule 10 of 11, last (`tests/test_p2996_single_literal.py:163`). All three `jdx/mise` deps are `semver-coerced` patch updates, so a calendar "major" splits them consistently. Their datasources differ (`github-release-attachments` vs `github-releases`), so one Renovate run may see the release before the other (UNVERIFIED as a real-world skew; pin_parity would hold the PR either way).
