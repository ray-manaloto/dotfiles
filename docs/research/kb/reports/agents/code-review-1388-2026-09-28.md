I found two real issues in `HEAD~1..HEAD`. I couldn't submit them through ReportFindings because that tool isn't available in this session, so they're listed here. I tested every example with `hook_guard.match()` and checked how zsh itself behaves with `zsh -c`.

1. **`python/src/dotfiles_setup/hook_guard.py:338` (medium): the rule misses `echo ====` inside compound commands.**
   - The pattern requires `echo`, `printf` or `print` to come straight after `_CMD`. `_CMD` only matches the start of the line or `;`, `&`, `|` or a newline, plus env/exec-style wrappers. Shell keywords and grouping characters aren't in that set.
   - So `for f in a; do echo ====; done`, `if true; then echo ====; fi`, `{ echo ====; }` and `(echo ====)` all come back `None`.
   - zsh fails on each of these: `zsh -c 'for f in a; do echo ====; done'` and `zsh -c '(echo ====)'` both print `zsh:1: === not found` with rc=1.
   - Separators inside loops and `if` blocks are a common way agents write multi-step commands, so the abort described in #1388 still gets through. A fix would let the rule's anchor also match after `do`, `then`, `else`, `{` and `(`. No test covers these shapes.

2. **`python/src/dotfiles_setup/hook_guard.py:338` (low): the rule blocks two command shapes zsh runs fine.**
   - `[^;&|\n]*?(?<=\s)={2,}` fires on any `==` that follows whitespace anywhere later in the same echo command, including where zsh never does `=`-expansion.
   - Arithmetic: `echo $(( 1 == 1 ))` is denied, but zsh prints `1` with rc=0.
   - Trailing comments: `echo ok  # a == b` is denied, but zsh prints `ok` with rc=0.
   - Both shapes are legitimate and now get blocked. The rule file warns that a redirect that misfires on legitimate commands "erodes trust in the guard". No test covers either case.

Nothing else in the diff looked wrong:
- Quoted and escaped separators are handled correctly, because the masking replaces quoted text with NUL rather than whitespace. `echo "a"==b` and `echo \====` are both allowed, which matches zsh.
- Real positives are denied as intended: `echo x ==y`, `print -- 'a' ==` and `echo a == b`, which zsh also rejects.
