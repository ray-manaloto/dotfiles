Because `$OUT` is created at claim time, a lane that dies before codex writes leaves a

### CONTROL: the same retry against the PRE-FIX guard (`test ! -e "$OUT"`)
after the pre-fix failed run, files: [prompt-lane-42.md]      <- no $OUT left

The control arm is the point: the shape this commit replaced **recovered** from a failed
lane; the shape it installed does not. Corroborated independently by R3's first probe,
where the real `codex` failed and left the pre-claimed file at 0 bytes.

Severity is MED rather than HIGH because the default id, `$$-$(date +%s)` (line 87),

shape that cannot retry, and nothing in the snippet or the surrounding prose tells anyone
to remove a stale claim. A claim taken before the work should be released when the work
fails, or the refusal message should name the recovery (`rm "$OUT"`).

**R11, the exact ASCII surface.** Enumerated all 125 printable ASCII bytes (not a spot
check); both shells accept **exactly** the advertised set and reject the other 66:

```text
zsh  accepts ASCII: [-.0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz]
bash accepts ASCII: [-.0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz]
```

`/`, `$`, backtick, `;`, `*`, `|`, `&`, `>`, quotes, space and tab are all rejected in both.
So **no injection or traversal route survives the validator**, and the leading `(` in the
case pattern and the `[!…]` negation are portable across zsh, bash and `sh` (dash-style) —
all three parse and discriminate identically on ASCII.

Non-ASCII is where the stated contract and the behaviour part company:

```text
zsh   LC_ALL=en_US.UTF-8  é  -> reject      bash  LC_ALL=en_US.UTF-8  é  -> ACCEPT
zsh   LC_ALL=C            é  -> reject      bash  LC_ALL=C            é  -> reject
                                             bash  LC_ALL=en_US.UTF-8  İ ǅ Ａ -> ACCEPT
                                             both shells, both locales: ，  -> reject
```

That is the classic collation-range trap: bash's `A-Za-z` under a UTF-8 locale is a
collation range, not a code-point range, so letter-like non-ASCII falls inside it. The
deviation admits **letters only** — the fullwidth comma is rejected, and no separator or
metacharacter gets in — so it is cosmetic, not exploitable. Worth knowing because the
refusal message promises `[A-Za-z0-9._-]+` and bash does not deliver literally that.

**R18** `..` / `.` / `-n` are accepted and harmless *only* because of the suffix position
(`…-prompt-..md` is a legal filename, and R5 re-armed the traversal as unreachable). If a
later edit ever puts `$LANE_ID` in a leading component, these become live in the same
commit, silently.

the commit's central claim — which is the opposite of round 1's outcome.
