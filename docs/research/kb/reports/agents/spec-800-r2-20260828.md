## 4. Constraints and invariants — one item per confirmed finding

**F1 (HIGH, CONFIRMED) — a stopped container on a superseded base is `up`'d and recorded current.**
Trace: registry moves → amd64 sync refreshes (new local image id) → fresh record drops arm64's entry → arm64's container is STOPPED → `decide_action` (sync.py:540-548) returns "up" before ever consulting `container_current` → `mise run up` REUSES the stale container → `write_sync_record` records its overlay id → forever "verify-only".
Required outcome: a non-running container whose overlay id is not the one recorded for this arch on the CURRENT record is rebuilt (`dev-rebuild` removes + recreates it), not reused.
Mechanism (pinned):
- `container_image_id`: query `docker ps -q` (running) FIRST and fall back to `docker ps -aq` only when that is empty. NOT a bare `ps -aq`: `docker ps -a` lists newest-first, so a newer exited leftover would shadow the running container and the reordered `decide_action` would then REBUILD the live one (premise report M1). Update its docstring (no longer "RUNNING" only), `container_current`'s docstring (the dropped shortcut), and the module action-matrix docstring (:26-31) to describe the new behaviour.
- `container_current`: DROP the `container_state != "running" → True` shortcut. Order becomes:
  `registry_digest is None → True` (see F4) ; `container_image_id is None → True` (absent container, or probe failed — non-destructive) ; `record is None → True` ; `recorded = record.containers.get(self.arch)`; if `recorded is None`: fall back to `record.legacy_container_image_id` (F10); still `None → False` ; else `==`.
- `decide_action`: `if not status.container_current: return "rebuild"` moves ABOVE `if status.container_state != "running": return "up"`.
- `_converge`'s rebuild WARN ("in-container sessions will be killed") stays conditional on running.
Consumers re-checked: `sync_main` prints `[CONTAINER OUTDATED]` when not current (sync.py:~568) — now also fires for a stopped stale container; correct. Existing `test_current_but_not_running_brings_up` keeps passing (its `container_image_id` is None → current → up).
Tests: (a) stopped + record for this arch holds a DIFFERENT id → "rebuild"; (b) stopped + record holds the SAME id → "up"; (c) absent (container_image_id None) → "up".

**F2 (HIGH, CONFIRMED) — refresh downloads the other architecture for single-arch hosts.**
Required outcome: a refresh never clobbers a platform already present under the local tag, and never adds one the host has not asked for. Platforms requested = `{resolve_platform()} ∪ local_platforms(image_ref)`, joined in `published_targets()` order (deterministic). Import `resolve_platform` back.
Probe basis (premise-verifier, docker 29.7.2, format `{{.Id}}` — do NOT use `{{.Variant}}`, it is a template error on the variant-less arm64 manifest and reads as a false miss): `docker image inspect --platform linux/amd64/v2 <ref>` rc 0; `--platform linux/arm64/v8` rc 0 (containerd normalises `/v8` onto the variant-less manifest); controls `linux/riscv64` rc 1, `linux/arm64/v7` rc 1, and bare `linux/amd64` rc 1 (so probe the EXACT `published_targets()` triples — never `os_arch()`).
Replace the `# ponytail:` comment with one line saying the union is why a single-arch host pays for one platform.
Tests: monkeypatch `local_platforms` + env `DOTFILES_PLATFORM`: (a) local has both → both requested; (b) local has none (absent tag) → only the pinned one; (c) local has only arm64, pin amd64 → both. Keep the `","`-presence assertion where two are expected (F13).

**F4 (HIGH, CONFIRMED) — registry unreachable + record lacking this arch → `dev-rebuild` on every sync, forever** (no record is written when `registry_digest` is None, sync.py:~681/687).
Required outcome: with the registry unreachable, sync must never take a destructive action on container-currency grounds (same principle as `stale`'s "network blip must not tear down"). Mechanism: `container_current` returns True when `self.registry_digest is None` (first clause). Test: registry None + running container + record lacking arch → "verify-only".
