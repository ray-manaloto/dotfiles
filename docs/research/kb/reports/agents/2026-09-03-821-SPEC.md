# SPEC — #820/#821: stop the lock-refresh composite writing task-scoped tools into the root `mise.lock`

Repo: `/Users/rmanaloto/dev/github/ray-manaloto/dotfiles`. Issue: **#820** (class),
manifesting as **#821** (the daily refresh PR, permanently red).

## 1. Objective

`.github/actions/lock-refresh/action.yml:31` runs a **bare `mise lock`**. Bare
`mise lock` locks *all configured **and task-specific** tools* — so the repo's one
task-scoped pin, `mise.toml:876` `tools.node = "24"` inside `[tasks.renovate-dryrun]`,
lands in the repo-root `mise.lock`. `tests/test_lock_coverage.py::test_root_lock_covers_host_config`
compares the lock against **top-level `[tools]` only**, so it fails with
`stale mise.lock entries for removed tools: ['node']` and every daily refresh PR is
born red.

Make the composite lock **only the top-level tools**, so the root lock matches the
contract the test encodes.

## 3. The change

**Do NOT hardcode a tool list into the YAML** — it would silently drift from
`mise.toml` and the drift would only surface as a red daily PR, i.e. exactly the
failure mode we are closing.

Follow the three-layer rule (`.claude/rules/agent-artifact-conventions.md` rule 6,
`.claude/rules/zero-bash-logic.md`): **python library → `dotfiles-setup` subcommand →
mise task**, and have the composite call the task.

1. **Library**: a function that reads a mise config file and returns its **top-level
   `[tools]`** keys, and a runner that invokes `mise lock` with exactly those names.
   Put it beside the existing lock code (`python/src/dotfiles_setup/lock_refresh.py`
   already owns refresh mechanics and has `merged_system_config_tools` /
   `runtime_config_tools` as precedent for this exact shape — reuse the module, do not
   create a parallel one).
2. **CLI**: wire it into `python/src/dotfiles_setup/main.py` alongside the existing
   `lock-stage` / `lock-collect` subcommands.
3. **Task**: a `mise.toml` task wrapping the CLI.
4. **Composite**: replace `run: mise lock` at `.github/actions/lock-refresh/action.yml:31`
   with the task invocation, preserving the existing `GITHUB_TOKEN`/`MISE_GITHUB_TOKEN`
   env block (the convergence loop depends on it).

### Explicitly OUT of scope
- **Do not add `--bump`.** The architect noticed that `refresh.yml:15` claims this job
  "owns re-RESOLUTION of `latest` pins" while bare `mise lock` only *"refreshes metadata
  for the currently locked versions"* — re-resolution needs `--bump`, which the composite
  does not pass. That is a **separate, behaviour-changing finding**; report it in your
  final message, do not fix it here.
- Do not touch `tests/test_lock_coverage.py`'s production assertions. The test encodes
  the contract we want; it is correct.
- Do not touch `.devcontainer/**`, `refresh.yml`'s `image-lock-pr` job, or anything
  related to #947 — a separate lane owns that.
