### Failure scenarios (one per finding)

- **F1:** A handoff says `knowledge-base PR #640 MERGED` while KB#640 is still open. If dotfiles #640 is any merged PR, handoff-check passes, so the next session trusts a false merge. If it is a dotfiles issue, the claim is silently dropped.
- **F2:** The session merges three PRs, writes `session-…c.md`, and handoff-check then flags a drifted claim. The skill says restart at step 1, so `session-state` re-runs with since = the mtime of the handoff just written, renders `merged since <now>: none`, and the operator pastes it verbatim as instructed. The State now omits all three merges, and handoff-check passes.
- **F3:** An author writes `#1460 merged` in "what shipped" (the historical house style: 57 unchecked instances). #1460 was actually closed unmerged. No claim is extracted, and rc=0.
- **F4:** An author writes `#1435 MERGED` meaning its fix PR, but #1435 is the issue. The claim is dropped and not counted; rc=0.
- **F5:** A refactor of `_build_command_handlers` drops `--since`. `mise run session-state -- --since X` silently uses the handoff mtime instead, and CI stays green.
- **F6:** On a degraded network where `gh api` answers and `gh pr view` hangs, a lookup started at 299 s ends at about 539 s. This is bounded, but not by the stated 300 s.
- **F7:** Someone re-runs #1450's failed check, and it passes. `task_plan.md:1105` stays historically true, but handoff-check fails on it at every resume until the prose is rewritten or hidden.
- **F8:** Handoff generated seconds after `land`: the just-merged PR is missing from `merged since`, rendered as a confident `none`.
- **F10:** A Renovate rebase lands during step 5.3. The round-trip reports a DISAGREEMENT, and the doctrine demands a new machine check for a non-defect.

## Q-FRESH / Q-SCOPE / Q-CLAIM

**Q-FRESH** (decision→action pairs):

- **Facts vs. judging.** `handoff_check._claim_findings` fetches each number once per run (`:538`) and judges every claim against that answer within the same run. That is fresh.
- **`session-state` → paste → `handoff-check`.** This is a deliberate two-phase design: facts are generated at T and re-judged at T+Δ. The drift it catches is the intent.
- **The staleness it introduces** is F10: volatile bot-PR states inside the snapshot, plus a doctrine that attributes every drift to a missing check. F2 is also temporal: the "previous handoff" decision is made from a filesystem mtime that the current session itself moves.

**Q-SCOPE:**

- **In S29-H scope:** F1, F2, F5, F6. The S29-H spec owns the reference regex, the default window, the tests and the deadline.
