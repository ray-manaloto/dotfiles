**Findings**

1. **`python/src/dotfiles_setup/doctor.py:1514` — medium.** Sessions inside the devcontainer will show an UNVERIFIABLE finding every time.
   - The new check is in `CHECKS`, which the SessionStart hook runs through `mise run doctor` whenever `CLAUDE_CODE_REMOTE` is not `true` (`.claude/settings.json:129`).
   - The image installs Claude Code (`.devcontainer/mise-system.toml:412-413`) but has no docker CLI or socket. So in a session started inside the container, `docker_container_rows` gets an `OSError`, which becomes `devcontainers: UNVERIFIABLE — docker ps failed ([Errno 2] …); is Docker Desktop running?`.
   - That line appears at the start of every in-container session. It breaks the doctor's "silent when healthy" contract and points at a problem that doesn't exist.
   - The check only makes sense on the host. Inside the container the workspace is `/workspaces/<clone>`, so the label hash would never match anyway. The check should skip there, the same way it already skips a linked worktree.

2. **`python/src/dotfiles_setup/doctor.py:1478` — low.** The git call in `is_linked_worktree` has no timeout.
   - The `docker ps` call right next to it is deliberately limited to 10s so a hung daemon can't hold the session. The `git rev-parse` call has no limit.
   - A stuck git (lock, network filesystem, a broken mise git shim) would freeze the SessionStart doctor with no end. The spec requires every call in this check to be time-limited.
