## HIGH

1. **A stopped container built on a superseded base is brought up by `up` and
   then RECORDED as current — so it is never rebuilt.**
   `sync.py:551-556` (`decide_action`) tests `container_state != "running"`
   → `"up"` *before* it tests `container_current`; `sync.py:686-689`
   (`_converge`'s `up` tail) then calls `write_sync_record`, which at
   `sync.py:266-268` writes `containers[names.arch] = container_image_id(names)`
   unconditionally. Trace the exact two-arch sequence this PR exists to serve:
   registry moves → amd64 sync is stale → `refresh_local_tag` mints a new
   `local_image_id` → `write_sync_record` takes the *fresh-start* branch
   (`sync.py:263-265`, local image id changed) and **drops arm64's entry** →
   arm64's container, built on the superseded base, is *stopped* → arm64 sync
   sees `stale=False`, `container_state="stopped"` → action `up` → `mise run up`
   **reuses the existing container** (`mise.toml:262`: "To force-refresh, use
   `mise run dev-rebuild`") → the record is written with the stale overlay id →
   every subsequent arm64 sync is `verify-only`. The one case #800's
   per-arch record was added to detect is laundered into "current" by the `up`
   branch. Smoke tier-1 identity only catches a *config*-level change, so a
   promote-only retag passes.
   Fix shape: `decide_action` should check `container_current` before the
   `container_state != "running"` branch, or `_converge`'s `up` path should not
   record when `status.container_image_id` was already known-stale.

2. **`refresh_local_tag` now downloads the other architecture's ~20GB for every
   user, including single-arch ones.** `sync.py:511-527`: `platforms` is the
   comma-join of `published_targets()` (`platform_target.py:280-282`,
   `PUBLISHED_ARCHES = ("amd64", "arm64")` at `:152`) — unconditional, not
   intersected with what the host has. Measured on this host,
   `docker image ls --tree ghcr.io/ray-manaloto/dotfiles-devcontainer:dev`
   shows `linux/amd64/v2` 21.5GB + `linux/arm64` 19.9GB. The repo's own
   `verify-before-advancing.md` states a cold base pull "can take hours" on a
   slow link; this doubles it for every stale sync on a host that will never run
   the second arch. The `# ponytail:` comment at `sync.py:512-517` names the
   upgrade path but shipping the cost is still the defect — the intersect it
   describes is ~2 lines (`docker image ls --tree`, or simply
   `{resolve_platform()} | {platforms already in local_digests}`).

3. **Two sibling call sites of the same dead label were left broken.** The diff's
   own premise — `--id-label` REPLACES `devcontainer.local_folder`, so that
   label "no longer identifies anything post-#677" (`sync.py:9-13`) — applies
   verbatim to:
   - `mise.toml:1002` (`[tasks.prune]`):
     `container_ids="$(docker ps -aq --filter "label=devcontainer.local_folder=$PWD")"`
     → always empty → prints the false reassurance `(no container labeled for
     $PWD — already stopped)` at `mise.toml:1008`, leaves both containers
     running, and the following `docker volume rm` (`mise.toml:1013`) then fails
     on in-use volumes.
   - `python/src/dotfiles_setup/docker.py:269` (`DockerManager.down`, reachable
     via `main.py:1643`): same filter → logs `No active or exited devcontainers
     found for this project.` and returns 0 having torn nothing down.
   Both should route through `devcontainer_names.teardown_container_ids`
   (`devcontainer_names.py:571`), which already handles exactly this (its
   `legacy` arm is the folder-label fallback).

4. **Offline + a record lacking this arch = rebuild on EVERY sync, forever — the
   docstring's "rebuilds once" is unconditional in prose, conditional in code.**
   `read_sync_record`'s docstring (`sync.py:210-213`) promises a legacy record
   means "every architecture rebuilds once". But the record is only written when
   `status.registry_digest` is truthy (`sync.py:681` and `:687`), and
   `registry_digest is None` also forces `stale=False` (`sync.py:141-142`). So
   with the registry unreachable: `container_current` is False
   (`sync.py:180-182`, `containers.get(arch)` → None), `decide_action` → `rebuild`,
   `_converge` skips `refresh_local_tag` (not stale) and runs `mise run
   dev-rebuild` — which is `--remove-existing-container --build-no-cache`
   (`mise.toml:352`) — and then records nothing. Next sync: identical. Pre-#800
   a populated flat `container_image_id` broke this loop; the empty `containers`
   map cannot.

## MED

5. **Multi-platform `--output type=docker` requires the containerd image store,
   and nothing in the code, tests or docs states that.** `sync.py:518-536`.
   Verified enabled on this host (`docker info` → `driver-type
   io.containerd.snapshotter.v1`, Docker 29.7.2), which is why it works here. On
   a daemon with the classic store buildx refuses a manifest list from the
   `docker` exporter, `refresh_local_tag` returns False, and sync dies with the
   opaque `buildkit tag refresh failed for <ref>` (`sync.py:679`) that names
   neither the cause nor the fix. Grep for `containerd`+`store|snapshotter`
   across `.devcontainer/`, `docs/`, `.claude/` returns no requirement statement.

6. **The load-bearing claim of change #2 is mock-only evidence.**
   `tests/test_sync.py:344-364` monkeypatches `sync.subprocess.run` and asserts
   only the *string* passed after `--platform`. Nothing exercises a real
   multi-platform `type=docker` export, so the assertion that this fixes the
   measured `rc=125, "does not provide the specified platform"` is untested end
   to end (`.claude/rules/real-integration-evidence.md`).

7. **`write_sync_record` silently drops this arch's entry when the container
   probe returns None.** `sync.py:266-268`: `cid = container_image_id(names); if
   cid is not None: containers[names.arch] = cid`. A transient `docker ps`
   failure right after a successful `dev-rebuild` writes a record *without* this
   architecture — which `container_current` reads as "never converged" and the
   next sync answers with another full `--build-no-cache` rebuild. No log line
   marks it. One `logger.warning` in the `else` would make it diagnosable.

8. **`read_sync_record`'s new docstring overclaims corruption tolerance.**
   `sync.py:213-216` says "a malformed state file must not crash the whole
   invocation", but the `except` at `sync.py:227` catches only
   `OSError, json.JSONDecodeError, KeyError`. A state file holding a JSON *list*
   or *string* now raises `AttributeError` on the new first access,
   `data.get("containers")` (`sync.py:221`) — uncaught. The guard added
   (`isinstance(containers, dict)`, `sync.py:222-223`) covers exactly one
   corruption shape, not the class the docstring names.

9. **`observe()` can now raise where it previously could not.** `sync.py:553`
   calls `resolve_names(workspace=workspace)`, which raises `ValueError` on a
   malformed `DEVCONTAINER_SSH_PORT` (`devcontainer_names.py:186-196`) — a pin
   that has nothing to do with syncing. `mise run sync` now aborts with a
   traceback on a typo'd port. `write_sync_record`'s docstring
   (`sync.py:236-242`) reasons about this risk for its *own* call and concludes
   it is safe, without noticing the new one it added upstream.

10. **The legacy record's information is discarded rather than migrated.**
    `sync.py:221-226` drops the old flat `container_image_id` key entirely. On a
    single-arch host the arch is knowable (`names.arch`), so a one-line
    migration would avoid the forced rebuild the docstring accepts. Judgment
    call, but the accepted cost is a `--build-no-cache` overlay rebuild that
    kills live in-container sessions (`sync.py:672-676`) — worth avoiding for
    the majority single-arch case.

## LOW

11. **`SyncStatus.arch: str = ""` default is a silent-wrong-answer footgun.**
    `sync.py:123`. Any construction that forgets `arch` gets `""`,
    `containers.get("")` → None → `container_current` False → a spurious
    rebuild. `observe()` is the only production site today, but the field has no
    invariant forcing it. A `KeyError`-raising lookup or no default would fail
    loud instead.

12. **`SyncRecord` is `frozen=True` with a `dict` field** (`sync.py:200`), so the
    generated `__hash__` raises `TypeError` if anything ever hashes a record or
    puts one in a set. Nothing does today.

13. **`test_refresh_local_tag_targets_every_published_platform` degenerates to a
    tautology if `PUBLISHED_ARCHES` narrows to one entry**
    (`tests/test_sync.py:361-364`): `expected` and the reverted
    `resolve_platform()` would then coincide, and the test would pass against
    the old code. Cheap fix: also assert `"," in cmd[idx]`.

14. **`test_container_state_filters_on_both_id_labels_not_local_folder` asserts
    over `captured` without asserting `captured` is non-empty**
    (`tests/test_sync.py:264-268`). If `_run` were ever stubbed away the `for`
    loop is a no-op and the test passes vacuously. (It is populated today —
    `container_state` + `container_image_id` each append one command.)
