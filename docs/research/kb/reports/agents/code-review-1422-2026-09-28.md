**1. Medium: `already_current` only checks `:dev`, but it passes the whole promote job** (`python/src/dotfiles_setup/image_promote.py:217`, `python/src/dotfiles_setup/image.py:2312`)

`_current_holds_markers` compares `:dev`'s per-arch digests with the markers. But the retag step in `.github/workflows/ci.yml` (from about line 525) moves three things: `:dev`, `:latest` and every `:dev-<arch>`. The new verdict exits 0 with `eligible=false`, so that whole step is skipped.

- **Scenario:** an earlier promote retags `:dev`, then fails partway through the `:dev-<arch>` loop (for example, a registry error on `imagetools create --prefer-index=false`), or before `:latest` is updated.
- **Result:** the next main merge built behind that commit is STALE. It sees `:dev` holding the markers, returns `already_current`, and exits 0. The step skips and main goes green, while `:latest` and/or `:dev-<arch>` still point at the old image.
- Before this change, that run failed red (rc=1). Now the partial state is blessed silently.
- **Fix:** check `:latest` and every `:dev-<arch>` against the same marker digests before downgrading to `already_current`.

**2. Low: markers checked only on this new path skip the platform check** (`python/src/dotfiles_setup/image_promote.py:215`)

`check_promote_eligibility` raises `ValueError` when a marker resolves to a platform other than `linux/<arch>`. `_current_holds_markers` has no such check. On a STALE verdict, the eligibility loop stops at the first stale arch, so markers for later arches are resolved for the first time here, without that check. A mis-shaped later-arch marker therefore feeds the digest comparison and never raises. It only matters if `:dev` carries the same wrong digest, which is unlikely.

Summary lines:
- `python/src/dotfiles_setup/image_promote.py:217` — `already_current` checks only `:dev`, and exit 0 skips the retag step, so a stale `:latest` or `:dev-<arch>` left by a partially failed earlier promote now leaves main green.
- `python/src/dotfiles_setup/image_promote.py:215` — markers resolved only on the new `:dev` path skip the `linux/<arch>` platform check the main eligibility loop enforces (low).
