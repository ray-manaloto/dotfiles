## Findings

### F1 — HIGH · `never_fired` reports rules that demonstrably loaded; a file can appear in `eager` and `never_fired` in the same run

`python/src/dotfiles_setup/instructions_report.py:132-136`

`fired` is populated only when `reason == "path_glob_match"`. `never_fired` is
`scoped_set - fired`. The harness emits five `load_reason` values
(`hooks.md:1275`): `session_start`, `nested_traversal`, `path_glob_match`,
`include`, `compact`. Four of the five put a scoped rule into `never_fired`
even though a record proving it loaded is sitting in the corpus.

`compact` is not hypothetical here: `memory.md:462` says path-scoped rules
reload after compaction, and `.claude/CLAUDE.md` records that
`DISABLE_AUTO_COMPACT` is deliberately **not** set, so compaction is routine in
this repo. The two records this repo has actually captured are `include` and
`nested_traversal` — neither is `path_glob_match`.

Failure scenario: session compacts, `md-size-budgets.md` reloads with
`load_reason: "compact"`. `mise run instructions-report` prints it under
"never fired (scoped, on disk, never observed loading)". The #916 migration
then deletes or rewrites a rule that is firing correctly.

Worse, the two buckets are not disjoint. Measured:

```
records: [{session_start, md-size-budgets.md}, {compact, ci-local-parity.md}]
eager      : ('.claude/rules/md-size-budgets.md',)
never_fired: ('.claude/rules/ci-local-parity.md', '.claude/rules/md-size-budgets.md')
```

The same run asserts `md-size-budgets.md` both loaded and never loaded.

### F2 — HIGH · The C4 concurrency test cannot fail: `communicate()` serializes the writers

`tests/test_instructions_observer.py:360-401`, specifically the loop at
`:391-393`:

```python
for proc, payload in procs:
    proc.communicate(input=payload, timeout=30)
    assert proc.returncode == 0
```

`Popen.communicate()` writes stdin, closes it, **and waits for the process to
terminate**. Each child blocks in `sys.stdin.read()`
(`instructions_observer.py:216`) until it is fed, so child *i* has fully exited
before child *i+1* receives a byte. No two `os.write` calls ever overlap. The
12 processes are concurrent only in the interval where all of them are blocked
reading stdin — never at the write.

Control arm (run): I copied the observer to a scratch tree and replaced the
single `os.write(fd, blob)` with `for i in range(0, len(blob), 8): os.write(...);
time.sleep(0.001)` — the exact defect C4 exists to prevent, maximally
interleaving. Replaying this test's orchestration verbatim against it:
**12 lines, 0 corrupt, test passes.** Re-run with genuinely concurrent writers
(stdin pre-filled from files so every child writes immediately): the mutated
writer produces **12/12 corrupt lines** and the unmutated writer 0.

So the production code is correct — but the only evidence offered for it is a
probe with one face, and the commit message cites it as "proven non-interleaving
via a 12-process real subprocess arm". Per
`.claude/rules/probes-need-a-control-arm.md` rule 2, that claim is currently
unearned; the fixture needs the stdin pre-fill (or a barrier) to discriminate.

### F3 — MEDIUM-HIGH · A symlinked rule that fires is reported `never_fired`

`python/src/dotfiles_setup/instructions_observer.py:124-135` +
`python/src/dotfiles_setup/instructions_report.py:76-88`

`_normalize_path` does `candidate.resolve().relative_to(project_root.resolve())`.
`resolve()` follows symlinks, so a rule symlinked in from a shared tree resolves
**outside** the repo, `relative_to` raises `ValueError`, and the fallback at
`:135` returns the original **absolute** path. `scoped_rules_on_disk` meanwhile
records the repo-**relative** path. The two never compare equal.

`memory.md:250` documents `.claude/rules/` symlinks as a supported way to share
rules across projects, and `memory.md:229` notes glob matching was extended to
symlinked paths in v2.1.198 — so this is a configuration the harness explicitly
supports.

Measured: a symlinked `.claude/rules/shared-rule.md` with a `path_glob_match`
record → `fired=()`, `never_fired=('.claude/rules/shared-rule.md',)`. Control
arm: the identical rule as a regular file → `fired=('.claude/rules/plain.md',)`,
`never_fired=()`.

Fix shape: normalize without following symlinks (`os.path.abspath` /
`PurePath.relative_to` against an unresolved root), or resolve *both* sides
identically on the report side.

### F4 — MEDIUM · Three silent drop paths, none counted, each a `never_fired` false positive

- `instructions_observer.py:198-199` — a record over `_MAX_RECORD_BYTES` (8192)
  is `return`ed away. **No `errors.log` line, no counter, no file created.**
  Measured: a payload with a 9000-char `file_path` through the real subprocess
  → rc=0 and `find $CLAUDE_PROJECT_DIR -type f` returns nothing at all. Control
  arm: the malformed-stdin path *does* write `errors.log`, so the logging route
  works — this path just doesn't use it.
- `instructions_observer.py:193-196` — the containment miss returns silently.
- `instructions_report.py:110-114` — a malformed JSONL line is `continue`d with
  no count surfaced in `RuleLoadReport`.

The report renders `never_fired` as fact. It has no field distinguishing "no
record exists" from "the record was dropped", so any of these turns into
"this rule never fired". `RuleLoadReport` should carry `dropped`/`malformed`
counts, and the size drop should append to `errors.log` like every other
failure.

### F5 — MEDIUM · `${CLAUDE_PROJECT_DIR:-.}` satisfies the anchoring gate while re-opening the hole it guards

`.claude/settings.json:124` vs `python/src/dotfiles_setup/hook_selfcheck.py:216-227`

`_unanchored_hooks` tests `if _PROJECT_DIR_ANCHOR in command: continue` — a bare
substring check for `CLAUDE_PROJECT_DIR`. The wired command is
`uv run --project "${CLAUDE_PROJECT_DIR:-.}/python" …`. The `:-.` default means
that when the variable is unset the hook resolves `./python` **against the
session's cwd** — precisely the #343 defect the check's own docstring
(`:202-214`) describes. The gate passes because the token is present; the
behaviour it certifies is absent.

Failure scenario: `CLAUDE_PROJECT_DIR` unset (a non-standard host, an SDK
embedding, a `env -u` wrapper) while cwd is a sibling repo that happens to have
a `python/` uv project → `uv run` executes in the wrong project, or errors to
stderr on every one of ~37 loads per session start. Note the observer's *own*
`_project_root()` (`:98-110`) correctly refuses a cwd fallback — the shell
command in front of it does not.

Either drop the `:-.` (let the hook fail loudly) or make the gate reject a
`:-`/`:=` default on the anchor variable.

### F6 — MEDIUM · Only the top-level `.claude/rules/*.md` is enumerated

`python/src/dotfiles_setup/instructions_report.py:76` — `rules_dir.glob("*.md")`,
non-recursive, and `_RULES_SUBDIR` (`:43`) is a single fixed `.claude/rules`
under the project root.

`memory.md:201` documents "rules in nested `.claude/rules/` directories" as a
supported shape. Any scoped rule in `python/.claude/rules/` or
`.devcontainer/.claude/rules/` is invisible to `scoped_rules_on_disk`, so it can
**never** appear in `never_fired` — the report silently under-reports exactly
the failure it exists to detect. Latent today (this repo has no nested rules
dirs: `find .claude/rules -mindepth 1 -type d` → empty), but the report's own
label claims "scoped rules present on disk".

### F7 — LOW-MEDIUM · Nothing executes the production command

Production (`.claude/settings.json:124`):
`uv run --project "${CLAUDE_PROJECT_DIR:-.}/python" python -m dotfiles_setup.instructions_observer`.
Every test (`tests/test_instructions_observer.py:39-49, 373-383`):
`[sys.executable, "-m", "dotfiles_setup.instructions_observer"]` with
`PYTHONPATH` injected. The `uv run` layer, the `--project` path expression, and
the shell expansion of `${CLAUDE_PROJECT_DIR:-.}` are exercised by nothing.
`hook_selfcheck`'s new entry (`:103-111`) only substring-matches the command
text; `check_pretooluse_endtoend` (`:230+`) drives the PreToolUse wrapper for
real, but there is no equivalent end-to-end arm for this hook.

I measured the wired command myself (0.06-0.07s, vs 0.05s for a bare stdlib
import under the same `uv run`), so the **perf** premise in the module docstring
is sound — this is a coverage finding, not a speed one.

### F8 — LOW · User-scope instruction files are recorded as absolute home paths, defeating the stated privacy rationale

`instructions_observer.py:75-77` excludes `transcript_path` because "the latter
leaks a user-home path for no analytical gain". But `memory_type` is one of
`User`/`Project`/`Local`/`Managed` (`hooks.md:1274`), and a `User`-scope load is
`~/.claude/CLAUDE.md` — outside the project root, so `_normalize_path` falls
through to `:135` and stores `/Users/<name>/.claude/CLAUDE.md` verbatim. The
test at `:145-148` asserts this behaviour intentionally. `.agent/` is
git-ignored, so nothing escapes the machine — but the stated reason for
excluding `transcript_path` does not survive the path fields that were kept.

### F9 — LOW · `_FRONTMATTER_RE` requires a newline after the closing fence

`instructions_report.py:45` — `\A---\n(.*?)\n---\n`. A rule file whose
frontmatter block ends at EOF with no trailing newline does not match, and the
rule is silently classified as unscoped (so it is never a `never_fired`
candidate). Measured: `'---\npaths:\n  - "*.py"\n---'` → not detected;
the same content plus `\nbody\n` → detected. CRLF files happen to survive
(`\r` lands inside the capture and YAML tolerates it).

### F10 — LOW · `os.write` return value is discarded

`instructions_observer.py:200-203`. `os.write` may return a short count; the
code assumes the whole `blob` landed. PEP 475 handles `EINTR`, and an ≤8 KiB
write to a local regular file will not realistically be short — but on a
network filesystem or against a full disk this truncates a JSONL line, which is
the exact corruption `_write_record`'s docstring says it prevents. A
`written != len(blob)` check that logs to `errors.log` costs nothing on the hot
path.

### F11 — LOW · Unbounded growth, no rotation

`.agent/instructions-loaded/` accumulates one JSONL per session forever
(~37+ records per session start, plus one per subagent per lazy load), and
`errors.log` grows without bound. `_iter_records`
(`instructions_report.py:105-108`) does `read_text().splitlines()` per file —
whole-file reads across an unbounded number of files. Nothing prunes, and
`.agent/` only clears on `git clean -xdf`.

## Premise check

The brief's stated environment facts held: Python is 3.14.0
(`uv run --project python python -V`), `requires-python = ">=3.14"`
(`python/pyproject.toml:5`), so `except OSError, ValueError:`
(`instructions_observer.py:134`) is valid PEP 758 and catches both — **not** a
finding, and I confirmed it rather than assuming it.

One brief premise I'd qualify: "a process that runs untrusted-ish input from
stdin, constructs filesystem paths". The path-construction attack surface is
genuinely closed — `session_filename` (`:112-126`) reduces to a 64-character
charset before any join, and the `is_relative_to` assertion at `:193` backs it
up. I could not build an escape. The real damage in this commit is not
traversal; it is **measurement correctness** (F1, F3, F4, F6) and **an
evidence claim resting on a probe that can only pass** (F2).
