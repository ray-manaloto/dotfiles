## Implementation evidence

- Current `lock_refresh.py` already owns TOML parsing and exposes sibling
  name-set helpers (`merged_system_config_tools`, `runtime_config_tools`), so
  adding the root-config helper and runner there follows the existing module
  boundary rather than creating a parallel abstraction.
- Current `main.py` imports the two lock-refresh entrypoints, registers
  `lock-stage` / `lock-collect`, and dispatches them from the central command
  table. The requested adjacent CLI command fits that established seam.
- No source-level contradiction with the inline spec was found in the first
  pass.
- The composite's root-lock step is exactly the stated bare `mise lock`, with
  `GITHUB_TOKEN` and `MISE_GITHUB_TOKEN` scoped on that same step. The change
  can replace only its `run:` value and leave both credentials untouched.
- `mise.toml` has a top-level `[tools]` table and the documented
  `[tasks.renovate-dryrun] tools.node = "24"` override. The existing
  `test_root_lock_covers_host_config` normalizes top-level keys by stripping
  bracketed extras, confirming that the new library helper must own the same
  normalization for argv parity.
- `tests/test_lock_refresh.py` is the established isolated-fixture suite for
  this module. Its fixtures use only `tmp_path`, so the new tests can avoid the
  production config and lockfile entirely.
- `lock_integrity.declared_tools` is related but intentionally returns raw
  config keys across one or more repository-relative files for interactive
  scoped locking. Reusing it would not meet this change's single-config-path
  API or extras normalization contract, so the new helper remains in
  `lock_refresh.py` as specified.
- Existing subprocess-backed modules treat `subprocess.run` as the system
  boundary. The new refresh runner will expose that boundary as an injectable
  callable so the argv test can inspect behavior without invoking live mise or
  mocking an internal collaborator.
