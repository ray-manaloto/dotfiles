## 1. Objective

**F1 — the real defect.** `check_settings_wiring` matches per-EVENT, never
per-ENTRY. It flattens every entry of a hook event into one blob — `joined`
keeps only commands, `tokens` keeps only matchers — so a required matcher token
can be satisfied by a DIFFERENT hook than the one carrying the required command.

`.claude/settings.json` has THREE `PreToolUse` entries, so this is live today.
Measured by me this session, mutating the real settings in memory:

- Narrow the pretooluse-guard entry's matcher to `AskUserQuestion|Edit|Write|NotebookEdit`
  (i.e. someone tidies `Bash` out of it) -> `check_settings_wiring` returns `[]`.
  The `Bash` requirement is satisfied by the unrelated `graphify-hook-guard.sh
  search` entry, whose matcher is `Bash|Grep`.
- Control arm: drop `Bash` from BOTH entries -> it correctly reports
  `"settings.json PreToolUse hook must be scoped with matcher 'Bash' ..."`.
  So the check discriminates; it is the pairing that is lost.

Consequence: every mise-tasks-only Bash redirect silently stops firing while
lint, pytest, verify, ship, land and hook-selfcheck all stay green. That is
#343 with a green gate — precisely the class this module's own comment at
`hook_selfcheck.py:60-71` claims to close.

The outcome required: **a required matcher token must be satisfied by the entry
that actually carries the required command, not by a sibling entry under the
same event.**

## 4. Constraints and invariants

C1. **The pinned rule for the fix.** For each `_SETTINGS_WIRING` row, first
    select the OWNING entries: those whose command contains at least one of the
    row's required substrings. Then:
    - required substrings are checked against the joined commands of the OWNING
      entries only;
    - required matcher tokens are checked against the union of the OWNING
      entries' matcher tokens only.
    If NO entry owns the row, keep today's behaviour: report the missing
    required tokens (do not silently pass, and do not crash).
    I verified this is safe for every current event: only `PreToolUse` has more
    than one entry (see premise L7), and each other event's single entry
    carries all of its row's required substrings.

    substring containment. `Edit` is a substring of `NotebookEdit`; that
