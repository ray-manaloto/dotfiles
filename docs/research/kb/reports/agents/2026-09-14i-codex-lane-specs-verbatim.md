# SPEC — #1111: a typed gate result at a known path

## 1. OBJECTIVE

Agents in this repo cannot learn a gate's outcome without parsing prose. The
established workaround is:

    mise run lint > /tmp/lint.log 2>&1; echo "rc=$?" >> /tmp/lint.log
    grep -E "FAILED|passed" /tmp/lint.log | tail -3

which is fragile (a pipe returns the pager's status, masking failure), lossy
(rc=1 covers "a test failed", "the tool is missing" and "the log was never
written" alike), and recurrent — the operator has asked for it to stop
repeatedly and it keeps coming back.

Make this true: **running a gate produces a TYPED RESULT at a KNOWN PATH**, so
an agent reads one structured value and never parses output. The goal is not to
forbid scraping but to make it pointless.

Concretely:

- **O1** `dotfiles-setup gate run <name>` runs a named gate, captures its output,
  and writes a typed result to a deterministic path.
- **O2** A `GateStatus` enum distinguishes outcomes that `rc=1` currently blurs:
  at minimum PASSED, FAILED, TOOL_MISSING, TIMED_OUT, NOT_A_GATE.
- **O3** `dotfiles-setup gate read <name>` returns that result as JSON on stdout,
  exiting with a code derived from the enum — so an agent can consume EITHER the
  file or the exit code, and both agree.
- **O4** The result model is CODE-GENERATED into a JSON Schema, committed under
  `schemas/`, so the shape cannot drift silently.
