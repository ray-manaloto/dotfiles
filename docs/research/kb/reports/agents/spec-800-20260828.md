# SPEC — #800: sync.py must see this workspace's container, and one `:dev` refresh must serve both architectures

Repo: /Users/rmanaloto/dev/github/ray-manaloto/dotfiles — branch `fix/800-sync-id-labels` (already checked out, clean, off main f6fc3f9).
Issue: https://github.com/ray-manaloto/dotfiles/issues/800

## 1. Objective

Two defects in `python/src/dotfiles_setup/sync.py`, fixed together because the first exposes the second.

**Part 1.** `container_image_id()` and `container_state()` find the devcontainer with
`docker ps --filter label=devcontainer.local_folder=<workspace>`. Since #677, `mise run up` passes
`--id-label dotfiles.workspace=<hash> --id-label dotfiles.arch=<arch>`, and `--id-label` REPLACES the
CLI's inferred label set, so this repo's containers carry NO `devcontainer.local_folder` label
(measured 2026-08-28: 0 hits for `$PWD`; control: 3 other-folder containers still carry it). Result:
`container_state()` is always "absent", every sync decision keyed on the running container is dead code.
Outcome required: both functions find exactly THIS workspace's container for THIS architecture (both id
labels, ANDed), and never the other architecture's container in the same folder.

**Part 2.** `refresh_local_tag()` re-exports ONE platform (`resolve_platform()`) under the local `:dev`
tag via buildkit `--output type=docker`. On a host running both architectures from one clone, each
arch's refresh clobbers the other platform under the tag, so the other arch's `mise run verify-image`
(`docker run --pull=never`, first step of `verify-local`) fails with "does not provide the specified
platform" (measured rc=125). Outcome required: after a refresh, the local tag serves EVERY published
platform, so neither architecture's verify path is broken by the other's sync.

**Consequence that must NOT ship (traced this session).** Once Part 1 makes the container visible per
architecture, the sync record's single flat `container_image_id` is written by whichever arch synced
last. The other arch then reads a running container whose overlay id ≠ the recorded one →
`container_current` False → `decide_action` = "rebuild" → an unneeded `dev-rebuild` on EVERY
architecture flip, forever. The record must hold the container id PER ARCHITECTURE. Additionally, after
a real tag refresh (registry moved) each architecture's container is on the old base and must rebuild
exactly once; after an ordinary `up` (tag unchanged) the other architecture's entry must survive.

Required shapes after the change:

```python
def container_image_id(names: DevcontainerNames) -> str | None
def container_state(names: DevcontainerNames) -> ContainerState
# both filter: ["docker", "ps", (-a), "-q"/"--format", "--filter", f"label={names.workspace_label}", "--filter", f"label={names.arch_label}"]

@dataclasses.dataclass(frozen=True)

    registry_digest: str
    local_image_id: str
    containers: dict[str, str] = dataclasses.field(default_factory=dict)  # arch -> overlay image id

@dataclasses.dataclass(frozen=True)
class SyncStatus:
    ...existing fields...
    arch: str = ""   # the architecture this sync is for (names.arch)

def write_sync_record(workspace: Path, image_ref: str, registry: str) -> None  # signature unchanged
def refresh_local_tag(image_ref: str) -> bool                                # signature unchanged
```

`observe()` resolves `names = resolve_names(workspace=workspace)` ONCE and passes it to both container
probes; `write_sync_record` resolves the same way (it is called from `_converge`, not from `observe`).
`resolve_names` can raise `ValueError` on a malformed `DOTFILES_PLATFORM` / `DEVCONTAINER_SSH_PORT`; that
raise is WANTED in `observe()` (fail before converging) and cannot newly occur in `write_sync_record`
because `observe()` already resolved against the same, unmutated `os.environ` (`_mise_env` copies for the
child only, sync.py:468). Say so in `write_sync_record`'s docstring so nobody threads it as a parameter.

On-disk JSON: `{"registry_digest": ..., "local_image_id": ..., "containers": {"amd64": "sha256:..."}}`.
A legacy record with a flat `container_image_id` key reads as `containers={}` (one rebuild per
architecture after upgrade — accepted, state it in the docstring). Keep the `except OSError,
json.JSONDecodeError, KeyError` shape (PEP 758 comma-except is deliberate in this repo). Guard the
`containers` value with `isinstance(..., dict)` in the reader (a corrupt non-dict value would otherwise raise
`AttributeError` inside `container_current`, which is evaluated in an f-string at sync.py:568) — treat a non-dict as `{}`.

## 4. Constraints and invariants

- **Part 1 filter semantics:** both labels ANDed (two `--filter` flags — docker ANDs distinct label
  filters). Mirror `devcontainer_names.teardown_container_ids` (l.571-606), whose docstring states why a
  bare folder filter is wrong. Delete `_LOCAL_FOLDER_LABEL` from sync.py if nothing else uses it, and fix
  the module docstring line 8-9 ("detected via the `devcontainer.local_folder` label") to name the two id labels.
- **Part 2 mechanism (PINNED by measurement, this session, `mp-export-probe.log`):** keep buildkit —
  `docker pull` of this image is a documented invariant NOT to use (`mise.toml` `[tasks.verify-image]`
  comment "Review finding [29] … never classic-pull ~38GB"; `.claude/rules/mise-tasks-only.md` table).
  Change `--platform` from `resolve_platform()` to ALL published platforms:
  `",".join(t.platform for t in published_targets())` from `dotfiles_setup.platform_target` — this evaluates to
  `linux/amd64/v2,linux/arm64/v8` (`_MICROARCH_LEVEL["arm64"]="v8"`, platform_target.py:111). Verified by the
  premise-verifier with THAT exact string: buildkit normalises `/v8` onto the registry's variant-less arm64
  manifest; tree shows `linux/amd64/v2` + `linux/arm64`; `--platform linux/arm64/v8 --pull=never` → aarch64.
  Measured on this host (docker 29.7.2, containerd snapshotter): `docker buildx build --pull --platform
  linux/amd64/v2,linux/arm64 --output type=docker -t <tag> -` with `FROM …:dev` → rc=0 in 17s (layers
  local); `docker image ls --tree` shows both `linux/amd64/v2` and `linux/arm64` under the one tag;
  `docker run --platform <each> --pull=never <tag> uname -m` → `x86_64` / `aarch64`, both rc=0.
  Cost ceiling (state it in a `# ponytail:` comment): a cold refresh now pulls both architectures'
  layers (~2×20GB) even for a single-arch user; upgrade path = intersect with the platforms already
  present under the local tag.
- **Buildkit re-export mints a NEW image id every run** (measured: three consecutive exports →
  three different `{{.Id}}`), so `SyncStatus.stale`'s record witness (`local_image_id` equality) stays
  exactly as it is and the record stays ONE file per image_ref (shared across architectures). Do NOT
  key the state file per architecture — a per-arch record + the image-id equality ping-pongs forever.
  Do not "fix" `registry_digest()`'s docstring or `stale` — both are ratified (#674).
- **Record write rule (derive inside `write_sync_record`, no new parameter):** read the existing
  record; if it exists AND its `registry_digest` == the new one AND its `local_image_id` == the current
  `local_image_id(image_ref)` → MERGE (keep other architectures' entries, set/overwrite this arch's);
  otherwise write a FRESH record with only this architecture's entry. Effect: a real tag refresh drops
  the other arch's entry (it must rebuild once); an ordinary `up` preserves it.
- **`container_current` rule:** not running → True. `self.container_image_id is None` → True
  (docker inspect failed; non-destructive). record None → True (first-ever sync). record present but
  `containers.get(self.arch)` is None → **False** (this arch has not converged onto this tag → rebuild).
  Otherwise `==`. Keep the existing docstring's "Review finding [1]" rationale; extend it.
- `container_current` clause ORDER is load-bearing: the `container_image_id is None → True` clause MUST precede
  the `containers.get(arch) is None → False` clause (`test_unknown_container_id_is_non_destructive` relies on it).
- `_run` stays the only subprocess path for probes (tests monkeypatch it). `resolve_names` reads
  `DOTFILES_PLATFORM` from the environment — that is correct (sync runs under the mise task env; the
  arm64 profile sets it).
- Repo conventions: zero inline suppressions (`noqa`/`type: ignore` are rejected by hk); ruff + ty
  clean; tests must fail if the change is reverted; no wall-clock or real docker in tests. Do not run
  `hk` directly — the gate is `mise run lint`.
- Do not touch the running containers or the local `:dev` tag; do not run `mise run sync/up/down`.
