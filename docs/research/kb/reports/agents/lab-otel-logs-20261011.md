## Reliability and privacy findings

1. **UNSET and CLI success overstate what was checked if presented as workflow success.** `telemetry_handler.py:95–97` skips malformed records/read errors; its table colors non-ERROR traces green (`:126–136`), and its CLI returns SUCCESS/rc 0 even for an empty result (`:212–226`). This review independently counted every raw JSONL line before accepting the parsed count. The live file has no malformed lines, but the loader behavior remains a source-level risk. `doctor.py:889–919` emits its own probe and declares PASS based on initialization/file line count; it does not establish end-to-end ingestion or session coverage.

2. **Handled model failures can still be marked OK.** `telemetry.py:547–553` sets OK and finish reason stop after a normal context exit, including an empty reply. `llm_client.py:294–296` catches failures and returns None; council `_post_completion_json` catches HTTP/parsing failures and returns None (`council.py:369–381`). These paths can explain empty OK completions without propagated exceptions. The live 138 empty completions are observed; the specific cause of each was not proven.

3. **Collector JSON ingestion loses status; acknowledgments do not prove storage.** The protobuf parser preserves UNSET/OK/ERROR (`telemetry_handler.py:321–344`), but the JSON OTLP parser hardcodes OK/INTERNAL and drops events/status description (`:382–408`). POST can acknowledge HTTP 200 with empty partialSuccess when parsing yields nothing or append fails; OSError is discarded (`:438–472`). HTTP access logging is suppressed (`:475`). Therefore zero retained ERROR/log-error matches cannot establish absence of ingestion failure. No malformed event or failure injection was sent during this audit.

4. **Buffering is optional and not a durable bounded queue.** `telemetry.py:393–411` defaults file buffering off, masking on, and attaches a SimpleSpanProcessor. Buffered mode uses an unbounded in-memory queue (`:153–155`), batch limit 50, 0.5-second flush interval and two-second shutdown join (`:63–65`); export returns SUCCESS after enqueue (`:238–253`). `_flush_batch` clears the batch without honoring write failure, and `force_flush` discards its timeout argument (`:191`, `:266–279`). These are inspected source risks; this review did not observe a queue overflow, write loss or live process buffering flag. The trace file has no rotation/retention policy in the reviewed exporter.

5. **Masking does not mean payload omission.** The exporter recursively masks strings in attributes/event attributes by regex (`telemetry.py:67–109`, `:347`), while GenAI tracing stores prompt/completion text (`:539–552`). Span name/status description do not receive the same exporter masking (`:367`). Full retained safe scans found 177 prompt fields, 177 completion fields, zero redaction-marker strings, zero nonempty status descriptions and zero narrow email/SSN/credential-pattern matches. These counts do not prove semantic privacy: personal names, clinical values, arbitrary secrets or identifiers outside the regex set were not certified absent. No raw sensitive value was output.

6. **The hook bypasses exporter masking and has no observed records here.** `.agents/hooks.json:2–21` declares grouped PostToolUse/PostInvocation commands with five-second timeouts, using `mise run telemetry:hook`. `telemetry_handler.py:249–300` hashes a conversation ID into a trace ID, stores conversation/step, truncates tool args/result to 4,096 characters and appends JSONL directly without the exporter mask. Error description is also copied directly. The live file contains no such conversation/tool fields, so bypass exposure is a source-level risk, not an observed sensitive hook payload. Host app acceptance/registration of this grouped hook format was not verified. The hook command itself omits `--no-deps`; normal execution can reach mise's uv/codegen dependencies (`mise.toml:25–35`). This audit bypassed those dependencies for every lab CLI inspection.

7. **Propagation is partial attribution, not session coverage.** `telemetry.py:443–470` injects W3C current trace context and `llm_client.py:278` uses it. Council injects before opening its GenAI child span (`council.py:406–415`), so that header reflects the preexisting parent context rather than that newly opened child. Direct hook records have no parent span. No project trace records contain session/workspace identifiers or serialized resources. There is no demonstrated mapping of the 338 traces onto the 19 source Antigravity conversations established in the prior runtime report.
