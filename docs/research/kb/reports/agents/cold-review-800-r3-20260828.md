## (b) New silent-failure branches

1. **LOW-MEDIUM — `docker.py:279-286`: the new catch downgrades a failed
   container lookup to rc 0.** `down()` returns after `logger.error(...)`, and
   `main.py:1643` calls it with no `sys.exit`, so
   `dotfiles-setup docker down` now exits **0** having torn down nothing;
   before the diff the `CalledProcessError` propagated and the process exited
   non-zero. Blast radius is small and that is the only reason this is not
   MEDIUM: `mise run down` is an alias for `[tasks.stop]` (mise.toml:1053-1055),
   which shells `dotfiles-setup devcontainer teardown`, not this verb — this
   Python `down()` has one caller and no mise task. If any script ever chains
   `dotfiles-setup docker down && …`, it will proceed on a failed teardown.
   Fix is one line: `raise SystemExit(1)` instead of `return`, or have
   `main.py` exit on a False return. (Cited: docker.py:264-296, main.py:1643,
   mise.toml:1053-1076.)
2. **NOT a silent failure — the `ValueError` catch in `_converge`**
   (sync.py:722-725). It returns `(False, str(exc))`, which `sync_main`

   correct. Reachability is real but narrow: `resolve_platform()` only escapes
   `published_targets()` when `DOTFILES_PLATFORM` is pinned to an unpublished

   published `linux/amd64/v2` (platform_target.py:111, 273, 333-336). Pre-diff
   that same input produced `docker buildx --platform ''`; the guard is a
   strict improvement.

Two caveats, both LOW and both pre-existing rather than introduced:

3. **LOW — rc 0 from `--check` still does not mean "sync would change
   nothing".** With an absent or stopped container that is otherwise current,
   check prints `check: current` and returns 0, while `decide_action` returns

   new prose is defensible, but a caller reading rc 0 as "no-op" is wrong. If
   the intent is "sync would rebuild", the honest predicate is
   `decide_action(status, force=opts.force) != "verify-only"`.
4. **LOW — `check: current` also covers "the container probe failed".**
   `container_current` returns True when `container_image_id is None`

   returned nothing because the daemon is unhappy". The registry-unreachable
   case is separated into rc 2, but a reachable-registry / unusable-daemon host
   reports `current` rc 0. Non-destructive by design and documented in the
   docstring; noting it only because the new prose promotes `--check` from a
   "staleness report" to a "currency report".
