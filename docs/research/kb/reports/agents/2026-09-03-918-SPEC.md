# SPEC — #918 Rule registry: parse rule frontmatter and bodies into records

Parent: #916 (rule scoping + enforcement). Repo:

## 1. Objective

Build the single source of truth **for #916's consumers** — the #927 gate,
the #928 write-trigger dispatcher, and the #929-#932 corpus lanes — of what
every instruction rule in `.claude/rules/` IS: its id, its repo-relative path, its load class, its
`paths:` globs when scoped, the stated reason it is eager when it is not, and
whether the write-hook should inject it. Those tickets read this instead of re-parsing markdown.

**Scope limit, stated because it is NOT obvious.** This registry does NOT
become the source of truth for the md-size-budget gate. That gate runs a
THIRD, independent load-class classifier in another repo
(`kb_setup.md_budget.has_paths_frontmatter`) which already disagrees with both
this registry and `scoped_rules_on_disk`; reconciling the three is a separate
ticket, not this one. C2b makes the disagreement visible instead of silent.

**The failure this prevents, and it has already happened once in this repo.**
`instructions_report.scoped_rules_on_disk` is a SECOND parser of the same
frontmatter, and during #917 three independent bugs coexisted precisely
because nothing asserted two sides agreed on path spelling. A registry that
silently disagrees with that function is worse than no registry: both look
correct in isolation and the disagreement is invisible. Part 4 pins the
assertion that closes this.

**The second failure it prevents.** That existing function reacts to
unparseable frontmatter with a bare `continue` — a malformed rule becomes
indistinguishable from a rule with no frontmatter at all, so a typo silently
reclassifies a scoped rule as eager and NOTHING reports it. The registry must
record malformed frontmatter as its own outcome.

## 3. Interfaces

Two frozen dataclasses and one builder. Field names are pinned (later tickets
read them); ordering and helper decomposition are yours.

```
@dataclass(frozen=True)
class RuleRecord:
    rule_id: str            # filename stem, e.g. "zero-skip-policy"
    path: str               # repo-relative POSIX, e.g. ".claude/rules/zero-skip-policy.md"
    load_class: str         # "scoped" | "eager" | "malformed"
    globs: tuple[str, ...]  # the paths: list; () unless load_class == "scoped"
    eager_reason: str | None          # section BODY text; None when unstated
    eager_reason_heading: str | None  # the heading line that anchored it
    malformed_detail: str | None      # parser error; None unless "malformed"
    inject: bool            # should the write-trigger dispatcher inject it
    body_bytes: int         # len(raw.encode()) — WHOLE file, frontmatter included

@dataclass(frozen=True)
class RuleRegistry:
    records: tuple[RuleRecord, ...]   # sorted by path
    # plus whatever accessors the tests need; keep it small.

def build_registry(rules_dir: Path) -> RuleRegistry: ...
```

`load_class` is a three-way partition, exhaustive and mutually exclusive: every
`.md` file under `rules_dir` lands in exactly one.

## 4. Constraints and invariants

**C1 — Traversal must match `scoped_rules_on_disk` exactly.** That function
uses `rules_dir.rglob("*.md", recurse_symlinks=True)` and computes
`path.relative_to(rules_dir.parent.parent)`. Both details are load-bearing and
both were bugs once: `Path.rglob` defaults `recurse_symlinks=False` on Python
3.13+, and a symlinked rules subdirectory is a documented sharing mechanism.
Use the same traversal and the same path spelling. Do NOT resolve symlinks.

**C2 — The agreement is ASSERTED, not assumed.** This is the invariant that
closes the class described in part 1. Two tests, both required:

- Against the REAL repo (`.claude/rules/`): the set of `record.path` where
  `load_class == "scoped"` MUST equal `set(instructions_report.scoped_rules_on_disk(...))`.
  Import that function; do not reimplement it in the test.
- Against a tmp_path fixture containing a file with UNPARSEABLE frontmatter:
  the two MUST diverge, in the documented direction — `scoped_rules_on_disk`
  omits it entirely, the registry records it as `load_class == "malformed"`.
  This is the control arm proving the registry actually fixes the swallow
  rather than inheriting it. A test that only ever shows agreement cannot
  distinguish a working registry from a copy of the old function.
- The SAME divergence test, second arm: a fixture file that cannot be READ
  (`OSError`, e.g. mode `0o000` — skip the test if running as root, where the
  mode has no effect). `scoped_rules_on_disk` omits it via its own
  `except OSError: continue`; the registry records it as `malformed`. C3
  legislates both swallows, so both need an arm. Restore the mode to `0o644`
  in a `finally` — a `0o000` file left behind breaks `tmp_path` cleanup under
  some pytest configurations. Verified to fire: euid 501, `0o000` ->
  `PermissionError [Errno 13]`, readable sibling still returned (control POS).

Do NOT collapse the real-repo assertion into a hardcoded list of filenames.
`tests/test_instructions_report.py:131-143` already does that; set-equality
against the live function is strictly stronger and survives a rule being added
or scoped without a test edit.

**C2b — the THIRD classifier is a tripwire, and its divergence must NOT be
pinned as a contract.** `kb_setup.md_budget.has_paths_frontmatter`
(`knowledge-base/python/src/kb_setup/md_budget.py:240-248`) decides the
eager-vs-scoped line-budget class and GATES `mise run lint` via `hk.pkl:617`
(`kb-setup md-budget`). It does NOT parse YAML — it runs
`re.search(r"^paths:", front, re.MULTILINE)` over the raw frontmatter text, so
it answers TRUE for `paths:` holding a string, `paths:` holding a dict, and
unparseable YAML containing a `paths:` line. Those are exactly the shapes C4
rules EAGER and C3 rules MALFORMED. It is importable from this repo's venv
(`from kb_setup.md_budget import has_paths_frontmatter`) — verified this
session, all four arms.

Write ONE test asserting that on the REAL `.claude/rules/` corpus all three
classifiers agree — registry-scoped == `scoped_rules_on_disk` ==
`{f for f in corpus if has_paths_frontmatter(read(f))}`.

**MEASURED this session, so the test is known-writable and known-green:** 26
files; all three return exactly
`{".claude/rules/ci-local-parity.md", ".claude/rules/md-size-budgets.md"}`;
both symmetric differences empty; zero malformed. If your run disagrees with

**W1 — the tripwire's failing arm is DELIBERATELY un-exercised, and the test
must say so.** Every fixture that would arm it IS the bug-as-contract this
spec rejects, so the honest resolution is a stated non-arm, not a fragile one.
The test's docstring MUST name (a) the three divergent shapes — `paths:` a
string, `paths:` a dict, unparseable YAML containing `paths:` — (b) that the
failing arm is deliberately not exercised because exercising it would pin a
bug as a contract, and (c) **issue #951**, which tracks the reconciliation.
Without (c) the "forces the reconciliation" claim is empty — a deferral with
no ticket is a deferral that does not happen.

**W2 — assert the ENUMERATION axis too.** C2b as stated compares the
predicate, not the gate: it applies `has_paths_frontmatter` to the filesystem
corpus, while the real gate reaches its corpus through
`kb_setup.md_budget.tracked_files()` (`git ls-files`) -> `classify()` ->
`DEFAULT_EXCLUDED_PREFIXES`. An untracked rule, or one under a symlinked
subdirectory, is in the rglob corpus and NOT in the gate corpus. Also assert
`rglob-corpus == {f for f in tracked_files(root) if classify(f) in
("rule_unscoped", "rule_scoped")}`. Verified True today. It shells out to git;
that cost is accepted.

**W3 — this couples the dotfiles suite to the knowledge-base SHA pin.** A
`kb-setup` bump can turn `tests/test_rule_registry.py` red with no dotfiles
change. That is the intended tripwire behaviour, but keep the `kb_setup`
import at MODULE level so a KB API change surfaces as a loud `ImportError`
rather than a silently-skipped test, and note in a comment that a red here may
be KB-side.

Do NOT write a test that asserts the synthetic divergence as expected
behaviour. Encoding a bug as a contract means the correct upstream fix breaks
this suite — the exact trap #917 hit, where a test asserted the bug and any
correct fix failed. The real-corpus agreement test is a live tripwire: the day
someone adds a rule with `paths: "a-string"` or a typo'd block, it fires and
forces the reconciliation, instead of the budget gate and the registry
silently disagreeing about the same file.

**C3 — Malformed is never silently absent.** Do not copy
`instructions_report.py`'s `except yaml.YAMLError: continue`. An unparseable
frontmatter block yields a `malformed` record carrying the parser's message in
`malformed_detail`. An UNREADABLE file (`OSError`) is also `malformed`, not
skipped. A file with NO frontmatter at all is not malformed — it is a
well-formed eager rule.

**C4 — Frontmatter shape.** Scoped means a leading frontmatter block whose
parsed mapping has a `paths` key holding a list. Frontmatter that parses but
lacks `paths`, or whose `paths` is not a list, is EAGER — not malformed. The
block is matched by the same shape `instructions_report.py:59` uses, which
tolerates an EOF-terminated block with no trailing newline; that case has a
real fixture in `tests/test_instructions_report.py` and must keep working.

**C5 — DECIDED by the operator, 2026-09-03: the eager reason is
HEADING-ANCHORED only.** A rule states its eager reason iff it has a markdown
heading whose text asserts the LOAD CLASS. The test is mechanical: take the
heading text, lowercase it, strip backticks; it qualifies iff it contains
`eager` or `paths:-scoped`.

This deliberately EXCLUDES `## Why this rule exists`, which **12** rules carry
and which justifies the rule's CONTENT, not its load class. Matching on "why"
would report 12 false positives. A test must pin that exclusion explicitly —
but assert it by NAMING the files, or as `len(qualifying) == 3` plus a named
exclusion. Do not assert a bare count of the "why" rules: that number is a
property of the prose corpus and will move under #929-#932 without anything
being wrong.

Known corpus truth at spec time — treat as a round-trip fixture, and if your
reading disagrees, say so rather than adjusting the code to fit:

- qualifies: `.claude/rules/clean-git-state.md`, `.claude/rules/zero-skip-policy.md`
  (both "Why this rule is eager (never `paths:`-scoped)"),
  `.claude/rules/agent-artifact-conventions.md` ("Why this rule cannot be
  `paths:`-scoped")
- does NOT qualify, KNOWN AND ACCEPTED: `.claude/rules/ai-cli-invocation.md`
  (states it in a leading blockquote) and `.claude/rules/clarify-before-acting.md`
  (states it inline in prose). Both are recorded as eager-with-no-reason. This
  is the operator's decision; the prose fix belongs to #929-#932. Do not add a
  blockquote or prose detector to "rescue" them.

`eager_reason` is the section BODY — the text from after the qualifying
heading up to the next heading of the same or higher level.

Two parser hazards, both real in this corpus:

- **Fenced code blocks contain lines that look like headings.** 12 lines
  matching `^#{1,6} ` in the corpus are BASH COMMENTS inside ``` fences (8 in
  `ai-cli-invocation.md`, 4 in `gh-cli-watch.md`). None sits in a qualifying
  section today, so the corpus round-trips either way — but a fence in a
  future qualifying section would truncate the body silently. Track fence
  state; `doc_refs._doc_lines` (`python/src/dotfiles_setup/doc_refs.py:386-396`)
  already does exactly this and is the shape to mirror.
- **ATX headings only, and strip the frontmatter first.** A setext-aware
  reader treats the CLOSING frontmatter `---` as an H2 underline, inventing a
  phantom heading at `ci-local-parity.md:6` and `md-size-budgets.md:7`.

**Pinned interface behaviour:** `eager_reason` and `eager_reason_heading` are
both `None` for a scoped rule AND for an eager rule with no qualifying
heading. They are never `""`.

**C6 — The inject set lives in this module, not in frontmatter.** Expose it as
an explicit module-level constant (a frozenset of rule ids or repo-relative
paths, your call — document which). Seed it with the two currently-scoped
rules as the pilot. `RuleRecord.inject` reads from that constant. Do NOT add
any new frontmatter key: #916 decision 1 pins the format at `paths:` only,
present ⇒ scoped, absent ⇒ eager, and whether the harness tolerates unknown
keys is deliberately unverified and deferred to #917.

**C6a — a TRACKED artifact in this repo specifies the OPPOSITE shape, and it
is SUPERSEDED.** `docs/research/kb/reports/agents/2026-09-02-ticket-cut-advisor.md:125`
describes this same registry as parsing `eager: <reason>` and `inject: true`
**as frontmatter keys**. That predates #916 decision 1 and is superseded: the
operator settled the format at `paths:` only, and C6 forbids adding any new
frontmatter key. If you read that artifact while orienting, treat this spec as
authoritative and that row as history. Do not add `eager:` or `inject:` to any
rule file's frontmatter.

That artifact also lists a `body_bytes` field, which revision 3 of this spec
dropped by oversight rather than by decision. **Reinstated:** add
`body_bytes: int` to `RuleRecord` — the byte length of the file, `len(raw.encode())`.
It costs one call, it is part of "what the rule IS", and the corpus lanes and
the #927 gate will want it to rank the eager corpus. No consumer exists today,
which is why its exact semantics are pinned here rather than inferred later:
WHOLE-file bytes, frontmatter included, not body-only.

**C6b — `rule_id` is not a new concept.** `doc_refs._declared_rules`
(`python/src/dotfiles_setup/doc_refs.py:382-383`) already derives the same id
set as `{p.stem for p in (repo_root/".claude"/"rules").glob("*.md")}`, and it
gates too (`hk.pkl:515`). It is a non-recursive glob, so it is NOT a
frontmatter parser and C2 is unaffected — but use the same `.stem` spelling,
and do not invent a different id scheme.

**C8 — ZERO inline lint suppressions.** No `# noqa`, no `# type: ignore`, no
