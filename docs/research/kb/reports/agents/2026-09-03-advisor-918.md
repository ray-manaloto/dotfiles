# Advisor Verdict: Rule Registry #918

**VERDICT: SHIP**

**Deciding Risk:** The dual-parser agreement test is structurally blind to bugs both parsers share — but this limitation is explicitly documented, mitigated by independent divergence tests, and tracked for unification in #951.

---

## On the Three Concerns

**Concern 1 — Shared parser seam with no unified definition:**

The architect correctly identifies that `test_scoped_agreement_against_real_repo` can only certify parity, not correctness. The test cannot catch bugs where both parsers fail identically — the code's own docstring states: "An agreement oracle like this one structurally cannot catch that class of bug at all... Parity is not correctness — it is a floor, not a ceiling."

However, this is mitigated and defensible:
- The registry diverges from `scoped_rules_on_disk` on *correctness* — it handles UTF-8 BOMs correctly (line 290, `utf-8-sig`), while the old function doesn't. Divergence tests prove the registry catches what the old function misses.
- The control arm proved this: a real BOM case was misclassified by the old function and is now fixed.
- Issue #951 exists to unify both parsers and a third classifier. This ticket correctly stays out of that scope.

**This seam is acceptable for a root ticket.** The test is not blind to regressions on the real corpus — it *will* fail if the two parsers diverge.

**Concern 2 — Tripwire test with its failing arm "deliberately never exercised":**

The architect misread the test's design. The failing arm is **not unreachable in principle** — it will fire if the corpus gains one of the four bad shapes (line 425–441 documents all four: `paths:` as a string, dict, null, or unparsable YAML). Those four shapes ARE tested individually in other tests (lines 129–173).

The comment "deliberately never exercised HERE, in this real-corpus tripwire test" means the real corpus doesn't currently have those bugs — which is correct. But the test is a "live tripwire" (line 416: explicit phrasing), not a frozen contract. If someone adds `paths: "a-string"` to a real rule, this test will fail and report a finding. That is the whole point.

**The architect is wrong here.** The test is valid under `.claude/rules/probes-need-a-control-arm.md` — the failing arm is reachable; it's just not exercised by the current corpus.

**Concern 3 — Unused fields (body_bytes, inject):**

Both fields are used:
- `body_bytes` is measured (line 298, `stat().st_size`) and tested (lines 812–862, including CRLF regression coverage).
- `inject` is tested and seeded with two rules from the pilot (lines 789–805).
- Both are documented in `RuleRecord` (lines 148–155) for their consumers (#927 gate, #928 dispatcher).

**This is correct groundwork for a root ticket,** not speculative generality.
