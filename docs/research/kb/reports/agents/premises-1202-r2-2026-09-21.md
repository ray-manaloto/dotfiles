## The four refutation targets

**(1) `realPath` equality — sound, but not for the reason the spec implies, and the ROOT is the trap.** Partially lands.

- *Relative `e.file_path`*: `$.fs` paths are "relative to **the working directory**" (`:2717`, `:2731`, `:2739`) — i.e. `$.session.cwd()` (`:2361`), which is a **different** thing from `$.session.root()` (`:2369`). So a relative target resolves against cwd, not root. Outcome is fail-safe (ENOENT or a non-equal realPath → refuse), so the guard stays sound. Do **not** "fix" it by joining against root.
- *Identity completeness*: the `.d.ts` states the opposite of a clean identity test — `:4094-4096`: "a hard link, a volume or file-id spelling (macOS `/.vol/`) or **a case alias keeps its own spelling**". So realPath equality is an **allow-list that fails safe on aliases**, not a complete identity test. That is exactly what `:4098-4099` says and the spec quotes, so the rule is right; only the framing "by RESOLVED identity" overstates it.
- *Measured disagreement (cross-check)*: POSIX `realpath()` on this APFS volume **does** case-normalise — `…/DOCTOR.TOML` → `…/doctor.toml` (bun `fs.realpathSync`, this session; `./` and `python/../` also fold). So if `$.fs.stat` is `realpath(3)`, `DOCTOR.TOML` is **permitted** — a spelling the spec's refuse-list never enumerates. Harmless (it is the same file), but the spec should say so rather than have a reviewer discover it.
- **M1 (highest implementation risk)**: `:4099` requires "an allow-list on `realPath` under a root **resolved the same way**." `$.session.root()` is documented absolute, **not** documented as realpath-resolved. Comparing a resolved target against a *string-joined* `root + "/doctor.toml"` breaks under a symlinked root (`/tmp`→`/private/tmp`, a symlinked home) — the permit then **never fires** and #1202 returns. The spec's wording ("equals the `realPath` of `<root>/doctor.toml`") is correct; it is the one line to make unmissable.

**(2) `$.session.root` from a `classic.PreToolUse` handler — REFUTATION FAILS, it is reachable.** `Events` at `:3908-3909`: every event's `$` is `EngineInterface`, with a single exception for `engine.create` (`NoEngineInterface`). No per-event narrowing, so `classic.PreToolUse` gets the full `$` including `$.session` and `$.fs`. `register.ts`'s narrow structural param on `readVerdict($)` still accepts it.

**(3) "`$` calls do not consume HookBudget" — REFUTATION FAILS; the spec is right and better-sourced than its citation.** The load-bearing sentence is the **type-level** doc at `:4169-4175`, above the `@example`, and it governs all three members: "Each bounds the hook's OWN time: the clock stops while a `next(e)` call **or any `$` call of the hook's** is in flight (**a `$.clock` wait excepted**)…". Not `.catch`-only — `:4192`'s "its `$` calls are free" is a restatement for the grace window. **Two corrections**: cite `:4169-4175` (not `:4176-4189`), and carry the **`$.clock` exception** — §4 asks for "an injectable clock source", and if the implementer reaches for a `$.clock` *wait* it **does** burn the 10 s budget. Reading a timestamp is fine; sleeping is not.
