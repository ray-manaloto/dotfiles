LLVM Debian/Ubuntu nightly packages

Download

The goal is to provide [Debian](https://www.debian.org/releases/) and [Ubuntu](https://www.releases.ubuntu.com/) nightly packages ready to be installed with minimal impact on the distribution.

Packages are available for amd64, i386 (Debian only), s390x and arm64 (aka aarch64). This for both the stable, qualification and development branches (currently 21, 22 and 23).

Packages are built using stage2 and extremely similar to the one shipping in Debian & Ubuntu.

**Version & distribution support policy:** on a best-effort basis, we provide:

- main (the development branch)
- the last 2 LLVM releases
- all currently supported Debian & Ubuntu versions (with the exception that we may stop maintaining old LTS releases if this becomes too hard or complex to maintain)

The packages provide [LLVM](https://llvm.org/) \+ [Clang](https://clang.llvm.org/) \+ [compiler-rt](https://compiler-rt.llvm.org/) \+ [polly](https://polly.llvm.org/) \+ [LLDB](https://lldb.llvm.org/) \+ [LLD](https://lld.llvm.org/) \+ [libFuzzer](https://llvm.org/docs/LibFuzzer.html) \+ [libc++](https://libcxx.llvm.org/) \+ [libc++abi](https://libcxxabi.llvm.org/) \+ [openmp](https://openmp.llvm.org/) \+ [libclc](https://libclc.llvm.org/) \+ [libunwind](https://github.com/llvm/llvm-project/tree/main/libunwind) \+ [MLIR](https://mlir.llvm.org/) \+ [BOLT](https://github.com/llvm/llvm-project/tree/main/bolt) \+ [flang](https://flang.llvm.org/docs/) \+ [libc](https://libc.llvm.org/) \+ wasm support

News

The work on apt.llvm.org has been partially supported by the OpenSSF, Google, & The Linux Foundation.

This platform serves more than 124tb of packages every month and is used by various actors like the Linux Kernel, TensorFlow, etc and referenced more than 24k times on Github.

The main goal of this support is to improve the security and sustainability of this platform. Previously we were running on an old rack that was no longer supported, and sooner or later would have failed. Now we're running on a [cloud-based build platform](https://blog.llvm.org/posts/2021-11-02-apt.llvm.org-moving-from-physical-server-to-the-cloud/) where the cloud provider is keeping the hardware up-to-date.

We deployed sigstore support, which makes it easier for users to verify that the packages came from us and to detect potential malicious signatures. We even contributed upstream to sigstore, helping future users of sigstore.

In parallel, we continued to ship new releases, enable new features (bolt, etc) etc.

Automatic installation script

For convenience there is an automatic installation script available that installs LLVM for you.

To install the latest stable version:

```
bash -c "$(wget -O - https://apt.llvm.org/llvm.sh)"
```

Copy

To install a specific version of LLVM:

```
wget https://apt.llvm.org/llvm.sh
chmod +x llvm.sh
sudo ./llvm.sh <version number>
```

Copy

To install all apt.llvm.org packages at once:

```
wget https://apt.llvm.org/llvm.sh
chmod +x llvm.sh
sudo ./llvm.sh <version number> all
# or
sudo ./llvm.sh all
```

Verification using sigstore

Source, Debian tarballs and dsc files can be verified using [sigstore/rekor](https://sigstore.github.io/).

This can be done with "rekor verify":

file="llvm-toolchain-10\_10.0.1~%2b%2b20210327072807%2bef32c611aa21-1~exp1~20210327183412.212.dsc"

url="https://apt.llvm.org/unstable/pool/main/l/llvm-toolchain-10/$file"

sig\_file="$url.asc"

wget --quiet https://apt.llvm.org/sigstore.public.key

./rekor verify --rekor\_server https://rekor.sigstore.dev --signature $sig\_file --public-key sigstore.public.key --artifact $url

echo $?

Copy

Or with "rekor search":

file="llvm-toolchain-10\_10.0.1~++20210327072807+ef32c611aa21.orig.tar.xz"

url="https://apt.llvm.org/unstable/pool/main/l/llvm-toolchain-10/$file"

wget --quiet $url

sha=$(sha256sum $file\|awk '{print $1}')

./rekor search --sha sha256:$sha --rekor\_server https://rekor.sigstore.dev

Technical aspects

Packages are rebuilt against the trunk of the various LLVM projects.

They are rebuilt through a Jenkins instance:

[https://llvm-jenkins.debian.net](https://llvm-jenkins.debian.net/)

## Bugs

Bugs should be reported on the [LLVM bug tracker](https://github.com/llvm/llvm-project/labels/packaging) (label: packaging).

## Workflow

Twice a day, each jenkins job will checkout the debian/ directory necessary to build the packages. The repository is available on the Debian hosting infrastructure:
[https://salsa.debian.org/pkg-llvm-team/llvm-toolchain/](https://salsa.debian.org/pkg-llvm-team/llvm-toolchain/).

Sources of this page, llvm.sh and others scripts are available on github:

[https://github.com/opencollab/llvm-jenkins.debian.net/](https://github.com/opencollab/llvm-jenkins.debian.net/)

In the _llvm-toolchain-\*-source_, the following tasks will be performed:

- upstream sources will be checkout
- The tarball will be created. It is named: llvm-toolchain-X\_X.Y.Z~++DATE+UPSTREAM\_COMMIT\_HASH.orig.tar.xz
- Debian .dsc package description is created
- Start the jenkins job _llvm-toolchain-X-binary_

Then, the job _llvm-toolchain-X-binary_ will:

- Create a chroot using cowbuilder or update it if it already exists
- Build all the packages
- Launch lintian, the Debian static analyzer
- Publish the result on the LLVM repository

Note that a [few patches](https://salsa.debian.org/pkg-llvm-team/llvm-toolchain/tree/snapshot/debian/patches/) are applied over the
LLVM tarballs (and should be merged upstream at some point).
