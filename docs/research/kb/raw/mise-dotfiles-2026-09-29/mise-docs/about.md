# About [​](https://mise.jdx.dev/about.html\#about)

mise (pronounced “meez”), short for _mise-en-place_, helps you set up and work in development environments. The name comes from the French culinary practice of preparing ingredients and utensils before cooking. In a project, `mise.toml` serves a similar purpose: it records the tools, environment, and commands needed to get to work.

## What mise manages [​](https://mise.jdx.dev/about.html\#what-mise-manages)

- **[Development tools](https://mise.jdx.dev/dev-tools/):** install runtimes and command-line tools, select versions per project, and share those choices with your team and CI.
- **[Environment variables](https://mise.jdx.dev/environments/):** define project configuration, load dotenv files or secrets, and activate environments such as Python virtualenvs.
- **[Tasks](https://mise.jdx.dev/tasks/):** give build, test, lint, and other commands names, dependencies, and arguments.
- **[Machine setup](https://mise.jdx.dev/bootstrap.html):** declare packages, files, services, and other host setup separately from a project's tool installations.

You can adopt these features independently. Start by managing one tool or one task; you do not need to move all your existing scripts and configuration at once.

## Where to start [​](https://mise.jdx.dev/about.html\#where-to-start)

Follow [Getting Started](https://mise.jdx.dev/getting-started.html) for the first setup, then the [walkthrough](https://mise.jdx.dev/walkthrough.html) to work through a project. The [glossary](https://mise.jdx.dev/glossary.html) explains terms such as backend, shim, and task. Use [Troubleshooting](https://mise.jdx.dev/troubleshooting.html) when a command or shell environment does not behave as expected.
