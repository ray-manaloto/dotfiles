# Evidence — five-stage workflow

The eager [rule](../../.claude/rules/five-stage-workflow.md) points to the
[authored skill](../../.claude/skills/five-stage-workflow/SKILL.md) and
[durable protocol](../agent-workflows/five-stage-workflow.md). The approved
prevention program is [#1843](https://github.com/ray-manaloto/dotfiles/issues/1843),
with protocol work in [#1852](https://github.com/ray-manaloto/dotfiles/issues/1852).
These are routing and acceptance authorities, not evidence that a future task
has completed their stages.

## Why the pointer is eager

The workflow is selected before substantial implementation, recovery or ticket
dispatch. The destination files may not exist yet, so path scoping cannot select
it reliably. The eager rule carries the route and operative limits; the durable
protocol carries stage outputs, ownership, proof budgets and retrospective
requirements. The existing `docs/agent-workflows/` directory is a durable artifact
location; it is not a new generated skill loader path.

## Evidence boundaries

- Record the selected installed instructions, version, source hash and actual
  invocation mode. Direct file-guided application under recorded authorization
  does not establish native Skill invocation or fresh-session pointer loading.
- Keep path ownership and serial integration explicit. The
  [active-hook interval observation](active-hook-writer-boundary.md) supports
  cooperating holds and one observed native hook interval. It does not establish
  universal writer exclusion, shared hk stash state or a replayed race.
- The public [saved-verifier controls](../../tests/test_verification_admission.py)
  exercise compile-only admission, exact byte binding, single-use START and
  terminal evidence. Capture/cleanup failure remains incomplete even when the
  recorded leader exit is zero. Storage failure can prevent publication.
- The public [reader controls](../../tests/test_proof_reader.py) check independent
  authority, command/root enumeration, representation and required references.
  ALLOW means those bounded reader checks matched. A fresh observation can match
  an explicitly planned failure; empty reference/issue domains prove only their
  independently declared empty scope. Historical attempts remain historical.
- The [tracker convention](../issue-tracker.md) distinguishes hosted OPEN blockers
  from prerequisites accepted into the integration tip. Draft publication,
  scoped controls and historical native evidence do not establish final-candidate
  review, native qualification or delivery.

P10's canonical skill/protocol bytes and historical attempts remain unchanged by
P11's review corrections. Changed product bytes require ROOT-owned qualification
and whole-spec review before delivery; this evidence pointer grants no additional
attempts and does not reset an old clock.
