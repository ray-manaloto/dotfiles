# dotfiles2

A mise monorepo for TypeScript (Claude Code mods), Python and C++.

- Root `mise.toml` declares the monorepo roots and no tools: every tool is in the global config
  (`unix/home/.config/mise/config.toml`, DL-757), at its latest release; `mise.lock` covers
  macos-arm64, linux-x64 and linux-arm64.
- Versions are exact pins, never `latest`: `pin = true` makes `mise use` and `mise upgrade --bump`
  write the resolved version. Code reads a tool's version from one variable: the pinned version
  (`mise current`, `mise.lock`) for mise tools, the tool's own version command for native installers.
- Before building a new mechanism from scratch, even a small one, find real projects already doing
  it and quote their working configuration (repo, file, line); docs alone are not enough.
- Never guess how a tool behaves. Read its source offline at the installed version and explain the
  behaviour from `file:line`; docs are a lead, not proof. Map a setting's blast radius from the AST
  (tree-sitter, ast-grep, `graphify update`) and LSP (clangd with a compile database,
  `codebase-memory-mcp`), then confirm it with a real run. Say what stays unexplained and keep digging.
- `mise run test` runs every root's `test` task; the root task lists them in `depends`
  (`//...:test` would include the root task itself and recurse).
- Start Codex under hc with `hc run --bg --name <name> codex-hc "<task>"`: `hc run codex` has no keys
  and no `--no-daemon`. Herdr.app's own launcher reads `~/.config/herdr-app/programs.json`.
- Roots: `typescript/` (bun), `python/` (uv project), `cpp/` (CMake presets, C++26).
- Python (DL-758): uv only through mise tasks; ruff, ruff format and ty clean; 100% line and branch
  coverage from real tests (real git, cmake, compilers; no mocking library); every model, type and
  enum generated by datamodel-codegen from a JSON Schema. `python/toolchains/p2996/` is the first
  package that follows this; its `check` task runs all of it.
- Before committing a Python unit, stage it and run `mise run review:python`, which must end
  `VERDICT: PASS`: a read-only Codex reviewer checks the changes against `CODING_STANDARDS.md`. The
  pre-commit hook refuses a commit under `python/` whose staged files differ from what passed. Run it
  in its own terminal pane, never inside a read-only Codex session: that sandbox denies mise's temp
  file, the git-dir report and the network, and the session gets no extra access. A read-only session
  reviews by reading the report and the changes under `python/`: staged, unstaged and untracked.
- The hook also needs the reviewer pane's own approval: start the reviewer Codex in the checkout being
  committed and name its session once with `mise run //repo:pane-pin <session id>`. Stage everything,
  run `mise run //repo:pane-fingerprint`, and the reviewer's last final answer must end with the line
  `PANE-APPROVE <fingerprint>`. Any later final answer withdraws it, so ask for nothing after it. A
  new commit or a changed index voids it. This is a local record: the pin and Codex's session log are
  plain files that anyone running as this user can edit, so it catches mistakes, not a forger.
- Run anything against a scratch home through `bash tasks/scratch/env.sh <empty folder> <command>`, from
  this checkout's path. A scratch `HOME` alone keeps the inherited XDG paths, and from a checkout mise
  climbs to the real `~/.config/mise/config.toml` as a project config and installs every tool in it.
- `mise run shell:apply` links the six zsh files; run it before a bare `mise dot apply` and after each
  `shell:rollback`. A bare apply stops on `~/.zprofile` and `~/.zshrc`, and with `--force` replaces them
  with no backup.
- `.gitignore` is an allowlist. A new top-level path must be added there on purpose; never
  add keys, `age.txt` or any secret file.
