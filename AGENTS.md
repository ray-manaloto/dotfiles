# dotfiles2

A mise monorepo for TypeScript (Claude Code mods), Python and C++.

- Root `mise.toml` declares the monorepo roots and no tools: every tool is in the global config
  (`unix/home/.config/mise/config.toml`, DL-757), at its latest release; `mise.lock` covers
  macos-arm64, linux-x64 and linux-arm64.
- Versions are exact pins, never `latest`: `pin = true` makes `mise use` and `mise upgrade --bump`
  write the resolved version. Code reads a tool's version from one variable: the pinned version
  (`mise current`, `mise.lock`) for mise tools, the tool's own version command for native installers.
- Before building a new mechanism from scratch, even a small one, find real projects already doing
  it and quote their working configuration (repo, file, line); docs alone are not enough.
- Never guess how a tool behaves. Read its source offline at the installed version and explain the
  behaviour from `file:line`; docs are a lead, not proof. Map a setting's blast radius from the AST
  (tree-sitter, ast-grep, `graphify update`) and LSP (clangd with a compile database,
  `codebase-memory-mcp`), then confirm it with a real run. Say what stays unexplained and keep digging.
- codebase-memory-mcp: install, reinstall and upgrade its agent setup only with `mise run //cbm:install`, never with
  its own `install`, `update` or `install.sh` (`docs/research/codebase-memory-mcp/install.md`).
  Run the task only from the primary checkout on `main`; `CBM_INSTALL_ALLOW_NON_MAIN=1` is only for
  qualifying a candidate from another checkout on purpose and still changes the live setup.
- `mise run test` runs every root's `test` task; the root task lists them in `depends`
  (`//...:test` would include the root task itself and recurse).
- Roots: `typescript/` (bun), `python/` (uv project), `cpp/` (CMake presets, C++26).
- Python (DL-758): uv only through mise tasks; ruff, ruff format and ty clean; 100% line and branch
  coverage from real tests (real git, cmake, compilers; no mocking library); every model, type and
  enum generated by datamodel-codegen from a JSON Schema. `python/toolchains/p2996/` is the first
  package that follows this; its `check` task runs all of it.
- Zero bash: no tracked `*.sh`, no shell shebangs and no multi-line mise `run`, in this repo and the
  tracked global config. Write Python as a package under `python/` and call it from a one-line `run`.
  Only the zsh startup files under `unix/home` stay shell. `mise run //repo:zero-bash` lists leftovers.
- Before committing a Python unit, stage it and run `mise run review:python`, which must end
  `VERDICT: PASS`: a read-only Codex reviewer checks the changes against `CODING_STANDARDS.md`. The
  pre-commit hook refuses a commit under `python/` whose staged files differ from what passed. Run it
  in its own terminal pane, never inside a read-only Codex session: that sandbox denies mise's temp
  file, the git-dir report and the network, and the session gets no extra access. A read-only session
  reviews by reading the report and the changes under `python/`: staged, unstaged and untracked.
- Large Codex reviews fan out: a read-only lead splits the change into slices of about 1,000 lines,
  one subagent per slice works every (file, rule) row, and the lead verifies and merges, as
  `tasks/review/python.md` does.
- Every commit, not only one under `python/`, needs the reviewer pane's own approval: start the
  reviewer Codex in the checkout being committed and name its session once with
  `mise run //repo:pane-pin <session id>`. Stage the changed files by name (jouet denies `git add -A`), write the message to a file, run
  `mise run //repo:pane-fingerprint <message file>` and commit with `git commit -F <message file>`.
  The reviewer's last final answer must end with the line `PANE-APPROVE <fingerprint>`. Any later
  final answer withdraws it, so ask for nothing after it. A new commit, a changed index or a changed
  message voids it. Resume the reviewer with `codex resume <id> -a never -s read-only`: a plain
  resume runs under the global config, full access here, and only a last turn under policy `never`
  and read-only approves. This is a local record: the pin and Codex's session log are plain files
  that anyone running as this user can edit, so it catches mistakes, not a forger.
- While Codex is out of quota, the fallback reviewer approves instead
  (`~/.config/agents/workflow/cross-review.md`): write the staged diff to a file, run a fresh
  `fallback-reviewer` subagent (Read, Grep and Glob only; `.claude/agents/fallback-reviewer.md`) and pin
  its transcript with `mise run //repo:pane-pin --subagent <agent-*.jsonl>`. The commit message or PR
  body carries, from before the fingerprint, the line
  `Reviewed by the fallback reviewer (Codex quota depleted).` Go back to the Codex pane when quota returns.
- Open a pull request only with `mise run //repo:pr-create <title> <body file>`, after the reviewer
  approved `mise run //repo:pr-fingerprint <title> <body file>` the same way. The task sends the
  bytes it checked. Edit a PR's title or body, or comment, only after the same approval of the new
  text. This is a rule, not a lock: `.claude/settings.json` makes Claude ask the owner before
  `pr-create` and `gh pr` and `gh issue` writes, but the web UI and other clients can still
  publish anything. `gh pr merge` is not on that list: the owner's sentence "merge #N" is the OK.
  Merge once with `gh pr merge N --merge --match-head-commit <sha>`, only when the head is the
  reviewer-approved commit and the checks pass; otherwise stop and tell the owner.
- This repo is public and the approval is its leak check. Before approving, the reviewer reads the
  whole staged diff and the commit message, or the PR title and body, for content from a private
  project: challenge names, C++ solution code, benchmark numbers, harness paths or challenge
  research. If any is there it does not approve. Never commit with `--no-verify` or `HK=0`.
- No public text carries a claude.ai session link: commit messages, PR titles and bodies, issues and
  comments have no `https://claude.ai/code/session_…` URL and no `Claude-Session:` trailer, even when
  the harness asks for them. A commit's only trailer is
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The reviewer's leak check refuses either.
- Local `main` moves only to `origin/main`: merge on GitHub, fetch, then `git merge --ff-only origin/main`.
  A `reference-transaction` hook in the shared `.git/config` refuses any other commit, reset, `branch -f`
  or deletion of main, `HK=0` and `--no-verify` included. hk's post-merge step installs it, a uv tool copy
  of repotools, on the fast-forward that brings it or a newer one to main; `mise run //repo:main-guard-install`
  does the same by hand, and `//repo:main-guard-remove` switches it off until the next install. If the
  copy can't start (its Python pruned), every move of main fails with a hint to re-run the install. It is
  a local check that anyone running as this user can remove, so it catches mistakes, not a forger.
- Run anything against a scratch home through `mise run scratch:env <empty folder> <command>`, from
  this checkout. A scratch `HOME` alone keeps the inherited XDG paths, and from a checkout mise
  climbs to the real `~/.config/mise/config.toml` as a project config and installs every tool in it.
- zsh reads its startup files from `$ZDOTDIR=~/.config/zsh` (set in `~/.zshenv`, the one file zsh reads from `$HOME`),
  so `~/.zprofile` and `~/.zshrc` are unused and untracked: an installer that appends to them (Codex's does)
  edits nothing in the repo. The tracked files are `unix/home/.zshenv` and `unix/home/.config/zsh/`.
- `mise run shell:apply` links the seven zsh files and removes the old links into this checkout at `~/.zprofile`,
  `~/.zshrc` and `~/.zshrc.d` (never a real file); run it before a bare `mise dot apply` and after each
  `shell:rollback`. A bare apply stops on `~/.zshenv` and the files under `~/.config/zsh`, and with `--force`
  replaces them with no backup. The live files link into the main checkout, so a change to them goes live at the
  fast-forward of `main`: run `git merge --ff-only origin/main && mise run shell:apply` as one command.
- `.gitignore` is an allowlist. A new top-level path must be added there on purpose; never
  add keys, `age.txt` or any secret file.

## Workflow facts

- Check: `hk check --all && mise run test` runs the hk checks and every root's tests; it passes before each
  commit. A change under `python/<package>/` or `swift/` also runs that root's `check` task (lint, types,
  codegen), e.g. `mise run //visualplan:check`.
- Shipping: a branch and a pull request into `main`, opened with `mise run //repo:pr-create`
  (it wraps `repotools pr-create`); the owner merges on GitHub, and local `main` only fast-forwards
  to `origin/main`.
- Research: notes go in `docs/research/`.
- Review approval: the pinned reviewer pane approves each commit (`repotools pane-pin`,
  `repotools pane-fingerprint`, through `mise run //repo:pane-pin` and `//repo:pane-fingerprint`;
  see `~/.config/agents/workflow/cross-review.md`). The hk `commit-msg` step `pane-approval` runs
  `mise run //repo:pane-approved` and refuses a commit the pane has not approved.
- Content guard: the reviewer's leak check on the exact bytes, bound to the approval fingerprint. The
  reviewer approves only bytes it has read and found free of private content. Any change to those bytes
  changes the fingerprint and voids the approval. The home-path scan is not the content guard.
